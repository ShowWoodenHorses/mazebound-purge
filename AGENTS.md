# Инструкции для Codex

Перед работой прочитай [CLAUDE.md](CLAUDE.md) и соблюдай его действующие правила, архитектурные ограничения и рабочие договорённости.

Следуй указанному там порядку чтения Docs/Progress.md, Docs/TZ.md и справочников. CLAUDE.md остаётся источником общих правил проекта; не дублируй их здесь. Дополнительные договорённости пользователя с Codex приведены ниже.

## Экономный режим — обязательная договорённость пользователя (2026-11-14)

- Не перечитывай неизменённые документы, файлы и схемы инструментов, уже доступные в текущем контексте. После потери контекста читай только необходимое для восстановления задачи.
- Сначала точечный поиск имён/символов/заголовков, затем нужные диапазоны. Обычно возвращай 1500–2500 токенов на чтение; больший объём — только по необходимости. При поиске кода ограничивай типы файлов, исключай `.meta` и сгенерированные файлы.
- Фильтруй результаты до передачи модели. Для MCP выводи одно представление (`structuredContent` или `content`), только нужные поля; не дублируй JSON. Полную схему запрашивай только у нужного инструмента, один раз в доступном контексте.
- Если вывод обрезался, сужай запрос. Не повторяй большие выгрузки и не компенсируй слишком широкий поиск простым увеличением лимита вывода.
- Самостоятельно выбирай способ экономии контекста. Для короткого чтения используй точечный поиск. Для больших логов, отчётов Unity и пакетных проверок данных или локализации используй Code Mode или короткий локальный скрипт: обработай вход целиком и верни итог, количество проверок и расхождения с адресами. Если результат ограничен, укажи общее число находок. Постоянную команду добавляй, когда одна и та же проверка регулярно повторяется. При замерах различай объём вывода инструментов и входные токены всего прогона.
- Перед реализацией проверяй пути и сигнатуры. Вспомогательные скрипты выполняй с явной UTF-8; делай изменения небольшими и безопасными для повторного запуска после частичного сбоя.
- Долгие операции проверяй с разумными интервалами (обычно 20–30 секунд), без серий пустых односекундных опросов. Возвращай краткий статус, а не полный повторяющийся ответ. Независимые чтения объединяй, когда это уменьшает число обращений.
- Сначала заверши изменения и целевые тесты, затем запускай необходимую итоговую регрессию. Повторяй её только после значимых изменений, ошибок или появления нового риска. Обязательные проверки качества ради экономии не сокращай.
- Не расширяй согласованный объём задачи. Отчёты делай краткими и содержательными, без повторения уже известных деталей. Подагентов не запускай только ради предполагаемой экономии.
- На границе согласованного подэтапа обновляй документацию для продолжения в новом чате. Не дроби текущую задачу на новые чаты без необходимости и не меняй заданные подэтапы.
- Не выдавай оценки расхода за измеренные токены и не обещай процент экономии без данных. Настройки модели, глубины рассуждений и подключений не меняй без указания пользователя.
