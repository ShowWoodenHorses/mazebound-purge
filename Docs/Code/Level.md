# Уровень, визуал, свет, видимость, тулза, сборки

Справочник по текущему коду (перенесён из CLAUDE.md 2026-10-17). Читать, когда задача касается этих систем; **обновлять при их изменении.** Общие правила — [CLAUDE.md](../../CLAUDE.md).

## Уровень, тулза, сборки, ассеты
- Клетка `(x, y)` ↔ мир `(x, 0, y)`; North = +Y сетки = +Z мира. За пределами сетки = Wall.
- Мутация `LevelData` (и `LevelCatalog`) только `internal` (InternalsVisibleTo `Purge.Editor`, `Purge.Tests.EditMode`); команды тулзы — `LevelAuthoring` (GenerateNew, RegenerateVisuals). **Generate New** до генератора биомов (этап 8) — `OpenFieldGenerator` (Core/Generation): площадка W×H (мин. 5×5), стена по периметру, старт в центре; `ObstacleDensity` — одиночные столбы на клетках с чётными координатами (не рядом со стартом; связность гарантирована), по `LayoutSeed` (бывший `MazeSeed`, `FormerlySerializedAs`).
- ID объектов: `{prefix}_{N}` через `LevelData.CreateUniqueId`. Межобъектные ссылки — по ID; на Definitions — прямые SO-ссылки.
- Случайность только `DeterministicRandom` / `StableHash` (не `System.Random`, не `string.GetHashCode`).
- Визуал клетки — слои (`CellLayer`): **Floor у каждой клетки** (сплошной пол под тонкими стенами), **Wall** только у клеток-стен поверх; `CellLayers.All` = эти два (обязательные). **Decor** — необязательный, только у клеток пола (`VisualResolver.ResolveDecor`: override, пустой override = «здесь нет декора», > assignment, без default). Авторасстановка `VisualAssigner.ChooseDecor`: `DecorDensity` и `MaxAutoDecorHeight` (`LevelGenerationSettings`), по `VisualSeed`, General-варианты не выше лимита (`VisualVariant.Height` меряет редактор — `DecorHeights` перед каждой авторасстановкой), поворот — четверть; **в клетке ключа авто-декора нет** (ключ теряется в куче предметов) — только ручной; добавление/перенос/удаление ключа пересчитывает авто-декор клетки (`VisualAssigner.AssignDecor`). Ручному декору можно задать `DecorPlacement` (`VisualData.DecorPlacements`: сдвиг ≤0.5 клетки, высота, yaw в градусах; `LevelEditing.SetDecorPlacement` делает авто-декор ручным; снятие override / пустой override / стена убирают placement) → `VisualResolver.ResolveDecorPose`; в сцене — `DecorSceneHandles` (вместе со светом — `LevelSceneHandles`, двигают и превью). Подбираемым предметам (ключ, аптечка, оружие — `VisualKinds.IsPlaceable`) — `ObjectPlacement` по id (`VisualData.ObjectPlacements`, `LevelEditing.SetObjectPlacement`, «Put on decor» в инспекторе связывает предмет с декором — `ObjectPlacement.OnDecor`: сдвиг/поворот одного двигает другой, `LevelEditing.PutOnDecor/DetachFromDecor`; кнопки ±0.25 по X/Z; `ObjectSceneHandles`) → `VisualResolver.ResolveObjectPose` → `EntityViewFactory.Create(level, entity)`; только визуал (подбор по клетке), перенос в другую клетку / Clear Overrides сбрасывают, выпавшие в игре — без него. Префабы стен — без пола. Overrides — по (клетка, слой).
- Визуал: выбор = хеш(VisualSeed, kind, cellIndex | entityId) → взвешенно; хранится `VisualChoice` (VariantId + Rotation). Rotation — четверти по часовой сверху. Префабы стен в канонической ориентации: End→N, Straight→N+S, Corner→N+E, TJunction→N+E+S; дверь rot 0 перекрывает проход С–Ю. Special-варианты только вручную. Нет варианта → явный DefaultVariantId → иначе пусто (не случайный другой).
- Префабы визуала — `AssetReferenceGameObject` (Addressables).
- **Строгое правило ключей: 1 ключ = 1 дверь.** Ключ того же цвета, что дверь; после использования удаляется из инвентаря. Ключ только отпирает дверь — она остаётся закрытой; открыть/закрыть её игрок может отдельным действием сколько угодно раз. Связь — `Door.KeyId`, цвет — `VisualVariant.ColorTag` (8 пар: red, blue, green, yellow, orange, cyan, purple, pink; RGB имени — `VisualColors`, новому имени нужна строка `hud.locked.<имя>`; запертая дверь — цветной вариант, разные пары по возможности разных цветов; ключ берёт цвет итогового визуала своей двери; дверь без ключа — без цвета).
- Зомби не открывают двери (закрытая дверь — blocker для их маршрутов). A* — 4 направления, `GridPathfinder` без аллокаций.
- **Test / Play** из тулзы — `LevelPlayLauncher` (Editor): валидация → Build / Sync → `playModeStartScene` = Bootstrap → Play → при `MainMenu` вызывает `GameFlow.StartLevel` с `LevelLaunchOptions(startIndex)`. Запрос хранится в `SessionState` (переживает reload домена), стартовая сцена сбрасывается после выхода из Play. Ищет `ProjectLifetimeScope` через `FindFirstObjectByType` — допустимо только в Editor-коде.
- Сборки: **Purge → Build** (`Editor/Build/PurgeBuilder`) — Addressables-контент + плеер в `Builds/`; платформа должна быть активной (иначе меню только переключает). Перед контентом ассеты, попавшие в несколько бандлов, переносятся в группу **Purge Shared Dependencies** (`LevelSync.IsolateDuplicates`, правило Addressables «Check Duplicate Bundle Dependencies»); остались дубли — сборка не идёт.
- **Ловушка сборки:** не-Addressable ассет, на который ссылаются несколько групп, копируется в каждый бандл — в сборке это **разные объекты** (в редакторе — один). Не сравнивать определения из разных Addressable-корней по ссылке без запасного сравнения по id; PlayMode-тесты (режим AssetDatabase) такое не ловят. Ориентация — только альбомная. В атласах шрифтов только символы из ASCII и таблицы переводов: новый символ (например «★») появляется лишь после того, как попал в `Strings.tsv` и прошёл Build Localization; звёзды и т.п. рисуются иконками.
- Список префабов, нужных игре, и требования к ним — [Docs/Prefabs.md](Docs/Prefabs.md).
- Команды меню **Purge** (что делают, когда запускать, рецепты «добавить оружие/звук/декор…») — [Docs/PurgeMenu.md](Docs/PurgeMenu.md). **Обновлять при добавлении/изменении команд меню.**
- **Размер веб-загрузки (этап 60+):** до первого `gameplayStart` ≤ 20 МБ (мобильная главная CrazyGames; сейчас ~16). **Purge Visuals** — PackSeparately + имена-хеши (`LevelSync.PackSeparately`, держат Build/Sync и `PurgeBuilder`): уровень качает только свои бандлы; **Purge Shared Dependencies** — PackTogether (`LevelSync.PackTogether`): по бандлу на ассет старт на сети был на ~3 с дольше — кэш Unity в браузере перепроверяет каждый файл (замер 80 мс / 20 Мбит/с). Текстуры паков на WebGL/Android: цвет ≤ 1024, нормали ≤ 512, свечение ≤ 256, персонажи ≤ 512 (`ThirdPartyAssetCollector`). LZMA на WebGL нельзя (Addressables молча оставляет LZ4). Замер — CDP-скриптом (байты до `gameplay start`).
- **Сторонние паки** качаются в `Assets/_Project/Import` — папка в `.gitignore`. Используемое переносит в `Art/ThirdParty/<пак>/…` меню **Purge → Dev → Collect Used Third-Party Assets** (GUID сохраняются; заодно снимает коллайдеры/Rigidbody и LOD с префабов — остаётся `LOD0`). Запускать после того, как взяли из пака что-то новое, **до коммита**; ссылок на `Import` из проекта быть не должно. Он же ограничивает текстуры паков для Android/WebGL (≤1024, нормали 512, свечение 256, персонажи 512, ключи 256; отдельно — **Cap Third-Party Texture Sizes**). Меши/аватар персонажей — копии в `Art/Characters` (**Purge → Dev → Extract Character Meshes**), чтобы общий `Characters.fbx` Synty не попадал в сборку целиком; запускать после смены модели персонажа.
- Тулза: окно **Purge → Level Designer** (`Scripts/Editor/LevelDesigner`), правки уровня — через `LevelEditing` (Core, покрыт тестами). Руководство для людей: [Docs/LevelDesigner.md](Docs/LevelDesigner.md) — **обновлять при изменении тулзы/визуальной системы**.
- Валидатор: `LevelValidator.Validate(level)` → `ValidationReport`; проверки идентифицируются `ValidationCodes`, сообщения на английском.

## Визуал уровня в игре
- `LevelVisualSystem` (Presentation, шаг `BuildVisuals`): `VisualPrefabLibrary` грузит через `IAssetOwner` уровня **только используемые** варианты (`LevelVisualUsage`) → `GeometryBuilder` → `EntityViewFactory`. Варианты берутся только через `VisualResolver` (сохранённые id), никакого выбора в runtime.
- Геометрия (пол, стены) — без GameObject на клетку: меши префабов склеиваются вручную (`MeshAccumulator`) в `VisibilityChunk` 8×8, сабмеш на материал, затем `StaticBatchingUtility.Combine`. В **UV3** каждой вершины — её клетка.
- Поклеточное скрытие (§54) — шейдер **`Purge/Geometry`** (`Art/Shaders/PurgeGeometry.shader`): при глобальном keyword `PURGE_VISIBILITY` вершины клеток, скрытых в `_PurgeVisibility` (R8-текстура W×H, `CellVisibilityMask`), схлопываются; тени тоже. API: `LevelGeometryView.SetCellVisible/SetAllVisible` + `ApplyVisibility()` (заливает маску, выключает чанки без видимых клеток). Без keyword всё видно (редактор; `GeometryShaderEditorGuard` сбрасывает keyword после Play).
- Требования к префабам пола/стен/декора: материалы на `Purge/Geometry`, меши Read/Write, только MeshRenderer — проверяет `EditorLevelValidator`. Декор склеивается в чанки так же (после слоёв клетки). Модели декора из `Art/Decor` готовит **Purge → Dev → Build Decor** (`DecorBuilder`: копии материалов на `Purge/Geometry`, Read/Write, масштаб под клетку кроме тел, подъём плоских на 4 мм, набор `PlaceholderDecorSet` в теме).
- Объекты (двери, пикапы) — `EntityView` в `EntityViewRegistry` по id; зомби и игрока создают их системы. Runtime-меши/текстуры — уничтожать явно (`UnityObjects.Destroy`), после выгрузки уровня `Resources.UnloadUnusedAssets`.
- Камера уровня — `TopDownCamera` (сцена Game): наклон 88° (почти сверху), `Frame(bounds)` при загрузке, затем `Follow` за игроком на расстоянии, при котором ±`FollowHalfExtent` клеток помещаются при любом aspect (по умолчанию ±7; решение 2026-10-14 — настройка игрока ±4…±10, в настройках ещё нет). Камера **не вращается по Y** — вверх экрана всегда North; ввод на это опирается.
- Частота кадров: Android — `targetFrameRate` = 60 (`ApplicationEntryPoint`; умолчание Unity 30), веб — по экрану.

## Свет
- **Без realtime-теней и ламп Unity.** Настроение — `VisualTheme.Lighting` (`ThemeLighting`): ambient, слабая «луна» без теней, фонарь игрока, пятно-тень, пресеты источников. Применяет `LevelLighting`; пятна — `BlobShadows.Attach(view)` (дочерний квад, `Purge/BlobShadow`).
- Доп. свет — в шейдерах через `Art/Shaders/PurgeLighting.cginc` (`PurgeExtraLight` → albedo × свет в emission): фонарь (глобалы `_PurgeLantern*`) + свет источников (`_PurgeLightMap`, `LevelLightMap`). Вне уровня глобалы нулевые — доп. света нет. На полу и стенах свет источников гаснет с высотой (`PurgeExtraLightGeometry`, `ThemeLighting.LightFade*/LightTopShare`) — верх стен почти не освещён; персонажи (`Purge/Lit`) — без этого.
- **Биомы:** `SnowTheme`, `ForestTheme` — **Purge → Dev → Build Biome Themes** (`BiomeThemeBuilder`): процедурные бесшовные текстуры (цвет + нормали) в коде билдера, свои меши блоков с тайлинговыми UV (стена: сабмеш 0 — бока, 1 — верх), наборы Floor/Wall; новая тема — копия `CastleBlockTheme` (остальные наборы общие), свет/туман настраиваются один раз и потом сохраняются. Верх стен должен контрастировать с полом (камера почти сверху).
- **Светильники** (факелы на стенах): вид визуала `Light` (набор темы), выбранный вариант — `LightSourceData.Visual` (назначает `VisualAssigner.AssignLights` из `LightPlacer`/`AddLight`, правка — `LevelEditing.SetLightVisual`). Поза — `LightFixtures` (грань стены по сдвигу источника, иначе первая стена вокруг; нет стены — нет светильника; высота 0.95). В игре — `LightFixturesView` (вьюхи в `EntityViewRegistry`, после прогрева перезапускает пламя `TorchFlame`, окрашенное в цвет источника). Префабы — **Purge → Dev → Build Light Fixtures** (`LevelPropsBuilder`).
- Источники — `LevelData.Lights` (`LightSourceData`, не в `AllEntities`), считаются при загрузке `LightField` (Core/Lighting, 4×4 текселя на клетку, стены и закрытые двери перекрывают, при смене двери — частичный пересчёт). Авторасстановка — `LightPlacer` (у стен, по `VisualSeed` и `LightDensity`), вызывается из Regenerate Visuals; правки — `LevelEditing.*Light`.
- Шейдеры: пол/стены — `Purge/Geometry`, «живые» объекты (персонажи, оружие, двери, ключи, предметы) — **`Purge/Lit`** (свойства как у Standard). После добавления моделей — **Purge → Dev → Convert Object Materials to Purge Lit**.

## Видимость
- Расчёт — `FieldOfView` (Core/Visibility): окно (2·радиус+1)² вокруг клетки игрока (`VisibilitySystem.Radius`, по умолчанию 10 — `VisibilitySystem.DefaultRadius`; тесты окна — 5); лучи из центра и 4 углов (с отступом) клетки игрока в те же точки клеток окна не дальше `NearRadius` (4), к дальним — из центра в центр, плюс веер из 5 точек к центрам клеток края окна (этап 2: в 4–5 раз дешевле); **видима каждая клетка, через которую прошёл луч**, и непрозрачная, в которую он упёрся. Непрозрачная клетка видна ещё если примыкает **стороной** к видимой прозрачной или закрывает угол видимого пола (диагональ + обе клетки между ними — видимые стены); диагональное касание через скрытый пол не считается. `IsRevealed` (для пола/стен) = видимые + одиночная скрытая клетка между двумя видимыми **прозрачными** по W+E или S+N; объекты — только `IsVisible`. Луч — `GridLineOfSight.Trace` (визитор клеток; угловой стык двух непрозрачных клеток блокирует), прозрачность — `IGridOpacity` (struct, generic, без аллокаций); в игре `LevelOpacity` (Wall, закрытая Door, вне сетки).
- Туман войны (только визуал): `FogOfWarView` (Presentation) — плоскость на уровне пола с материалом `VisualTheme.FogMaterial` (шейдер `Purge/Fog`, все параметры в материале), маска `_PurgeFog` (R8 (W+2)×(H+2), билинейно) по `RevealedCells`; `FogMask` плавно меняет только меняющиеся клетки (первое открытие мгновенно). Туман рисуется без проверки глубины (край затягивает и стены на границе). С туманом геометрию уходящих из видимости клеток скрывает `FogOfWarView`, когда туман их полностью затянул (`JustCovered`), а не `VisibilityController`. Нет материала — нет тумана.
- `VisibilitySystem` (Gameplay) пересчитывает только по `PlayerSystem.Spawned`, `CellChanged` и `DoorChanged` (дверь в окне) → `Changed`. `VisibilityController` (Presentation) пишет `RevealedCells` в маску геометрии и `IsVisible` в `EntityView.SetVisible`. Новые вьюхи — через `EntityViewRegistry.Add`, движущиеся меняют клетку только `EntityViewRegistry.Move` — тогда видимость применяется сразу. AI видимость не использует (§57).

## Зима (уровни 21–30, `SnowTheme`)
- Зомби зимы — `Data/Zombies/SnowZombie{Walker,Listener,Hunter}` (сильнее лесных, в сугробе вязнут меньше игрока: ×0.7–0.75), набор `SnowZombieSet` (модели Zombie_01–03, как у заглушки). Лесной и снежный наборы ведутся вручную: Build Zombie Animations обновляет только `PlaceholderZombieSet`.
- Погода — `VisualTheme.Weather` (`ThemeWeather`, только вид; пустой материал = нет эффекта; **Purge → Dev → Build Weather**). Изморозь — `_Frost` в `Purge/Lit` **на рендерер** (общие материалы Synty у игрока/дверей): пишется в тот же `MaterialPropertyBlock`, что и вспышка (`HitFlash.SetFrost`, иначе вспышка затирает); цвет/форма — глобалы из `LevelLighting`. Снег — `SnowfallView`, пар — `BreathView` (голова — `CharacterHead`, у зомби `ZombieViewPresenter.Heads`): по одной системе частиц, только `Emit` из `Tick` (на паузе нет), в `LateTick` без тика — `Pause`; после прогрева `Play` (`LevelWarmup` останавливает все системы).
- **Сугробы** — `CellSurface` в `LevelGeometry._surfaces` (пустой массив у старых уровней = нет; только Floor; `LevelEditing.SetSurface`, кисть **Snowdrift**; смена типа/Erase снимают). Скорость × `SnowdriftSpeed` (Player/ZombieDefinition), `SpeedFactor` от полной скорости. A* с весами: `IGridCost` (`GridPathfinder.TryFindPath<TPass, TCost>`), у зомби сугроб = `NavigationSystem.SnowdriftCost` (3); подсказка маршрута и валидатор — по шагам. Вид — пол категории `VisualCategory.Snowdrift` (нет в теме — обычный пол; у снега — холм с материалом обычного снега), авто-декора нет. Белизну и мягкий край рисует `Purge/Geometry` (keyword `PURGE_SNOWDRIFT`): `SnowdriftMask` — R8 W×H, билинейно, 1 = клетка с полом-сугробом, стена/дверь рядом 0.6 (сугроб доходит до стены, не растекаясь вдоль); низкие поверхности, смотрящие вверх, тянутся к `ThemeWeather.Drift*` + шум края + тень у подножия. Строится при загрузке (`GeometryBuilder` → `LevelGeometryView.Bind`), в превью Level Designer — тоже; `GeometryShaderEditorGuard` снимает keyword после Play.
- **Мёрзлые двери** — `DoorData.IceHits` (0 = нет; с Initially Open несовместимо). `DoorSystem.HitIce/IceLeft/IsFrozen`, события `IceHit`/`IceBroken`, `SetOpen` по мёрзлой — исключение; разбитая — обычная закрытая. Бьёт только ближний бой: `PlayerCombat` — соседняя мёрзлая дверь по направлению удара (в дуге, грань ≤ `MeleeRange`), `LastIceHit`, звук `SoundType.Door`. Interact → `InteractionResult.DoorFrozen` (`hud.door_frozen`). Вид — `FrozenDoorsView` (`Weather.IceOverlay` дочерним к вьюхе двери, `FrozenDoorIce` — глыбы, в момент удара клипа; осколки — частицы), звук `AudioCatalog.IceHit/IceBreak` (пусто → пуля о стену / отпирание), на карте голубая.
