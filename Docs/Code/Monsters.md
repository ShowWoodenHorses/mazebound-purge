# Зомби Maze, монстры, орда, стресс-тест

Справочник по текущему коду (перенесён из CLAUDE.md 2026-10-17). Читать, когда задача касается этих систем; **обновлять при их изменении.** Общие правила — [CLAUDE.md](../../CLAUDE.md).

## Зомби
- `ZombieSystem` (шаг `SpawnZombies`, тик после пуль): `ZombieRuntime` (`IDamageable`, в `SpatialQueryService` и `OccupancyMap`) + `ZombieController` на каждого. Убитый: убирается из occupancy и spatial, `KilledCount++`, событие `Died` (вьюха удаляется).
- `ZombieController`: обнаружение раз в 0.1 с (`ZombieDetection`: VisionOnly — `VisionRange`/`VisionAngle` от `Facing` + `IsClear`; HearingOnly — `Hear(SoundEvent)`, дистанция ≤ min(радиус звука, `HearingRadius`); VisionAndHearing — видит во все стороны в `DetectionRadius`, стены и закрытые двери загораживают (`IsClear`), и слышит звуки по `HearingRadius`, как HearingOnly). Цель — последняя замеченная клетка; Chase к ней, дошёл без нового обнаружения → Return (на спавн → Idle). Патрулей нет (убраны 2026-10-14). Игрок в соседней по стороне клетке → Attack (первый удар через пол-интервала). Урон не вызывает реакции (§76).
- Движение по `NavigationSystem.TryFindPath` (A* только при смене цели или `Version` дверей); в клетку игрока не входят (`CanZombieEnter`), друг через друга — да; закрытая перед носом дверь → новый поиск.
- Скорость: Return — `MoveSpeed` (walk), Chase — `ChaseSpeed` (run).
- **Alert** (сверх §74): заметив игрока из Idle/Return — стоит и рычит `ZombieController.AlertDuration` (0.5 с), потом Chase; игрок рядом — сразу Attack; после атаки погоня возобновляется без рыка.
- Вид: `ZombieViewPresenter` (шаг `SpawnZombies` после системы) — `EntityViewRegistry.Add/Move/Remove`, параметры `ZombieAnimatorParameters` (наличие кэшируется — `animator.parameters` аллоцирует); убитый остаётся `CorpseTime` (анимация смерти), потом удаляется. Префабы `Art/Zombie/*` + общий контроллер собирает **Purge → Dev → Build Zombie Animations** (он же заполняет Zombie Set темы — вариант на префаб, тип в `Definition` варианта сохраняется, новому ставится автоматически — и переназначает визуал зомби в уровнях; модель игрока для билдеров — единственный префаб в `Art/Player`). Темп шага клипов — `LocomotionAnimation.Playback` (≤1.4×). Билдеры персонажей пересобирают контроллер на месте — не удалять ассет (ломает ссылки префабов).
- Смерть игрока: `PlayerDeathRule` (резолвится в `LevelSessionFactory`) → `LevelRuntime.Finish(Failed)`; `LevelRuntime.Tick` прерывает кадр, когда уровень завершён.
- **Победа (временно, до волн этапа 6):** `AllKilledRule` (резолвится там же) — последний убитый зомби → `LevelRuntime.Finish(Completed)`; уровень без зомби так не завершается (решение пользователя 2026-10-14).

## Монстры этапа 5 (рядовые — 5а)
- **Определение** — `MonsterDefinition` (`Core/Monsters`, `ContentDefinition`, меню Purge/Definitions/Monster): ранг `MonsterRank` (Mass/Officer/Elite/Boss), биом `MonsterBiome`, восприятие `MonsterPerception` (Wanderer/Caller/Hunter — `HordePerception`, 5б; Ходок и биомные — бродяги, Бегун — охотник), статы `MonsterStats` (HP, скорость, радиус, досягаемость, урон, интервал атаки, поворот, расталкивание, время трупа, **`EmergeTime`** — сколько вылезает из-под земли; восприятие 5б: `WanderSpeed` — шаг бродяги, клип ходьбы 1× при `MonsterStats.WalkClipSpeed` 0,4 кл/с; `SightRange` 7; `CallRadius` 12 — у зовущих), дроп `DropTable` (ранга; пусто — уровня), сопротивления `StatusResistance` (состояние × длительность, 0 = иммунитет), эффекты смерти — `[SerializeReference, ModuleList] List<EffectModule>` (те же, что у метательного). **Вид не здесь**: каталог контента грузит все определения при старте — тяжёлое (меш, текстуры костей, экипировка) лежит в `HordeVisualDefinition` с `MonsterId` (`[ContentRef]`).
- **Создание** — **Purge → Dev → Build Monsters** (`MonstersBuilder`): по папкам `Art/Monster/<Биом>/<Ранг>`; рядовые (Mass) — запечённые, офицеры (5в, кроме `Ram_*`) — Animator, раздел «Способности и офицеры». Определения — `Data/Monsters/<Биом>/<префаб>.asset` (id = имя префаба: `zombie_common` — Ходок, `zombie_2_common` — Бегун, `skeleton_castle`, `zombie_forest`, `ghoul_snow`), виды — `Data/Monsters/Visuals/<префаб>.asset`, запечённое — `Art/Horde/<префаб>/`. Клипы `Monster_*` в `Art/Animations` (копии из Zombie_Animations и UAC: ожидание, 2 ходьбы, бег, 2 спринта, 3 атаки, 3 реакции, оглушение UAC Bare Fists, 4 смерти по сторонам UAC, появление = `Crawl_OutOfGround` + `CrawlIdle_To_Stand`; с 5д1 — только окна 2,4–5,0 с и 0,6–3,2 с с переходом 0,4 с на стыке: весь клип 13,3 с в 2 с дёргался ×7, теперь ~4,8 с ×2,4, 72 кадра — `ClipEntry.Windows`/`Blend`). Ходьба паков — шарканье 0,2–0,6 кл/с, поэтому погоня всегда бег (`Run_02`, ~2,2 кл/с) или спринт (≥ 2,8 кл/с, ~3,4); ходьба запечена для бродяг 5б. **Клипы запекаются на месте**: атаки Zombie_Animations — версии с перемещением (выпад бёдер ~1,4 м), реакции отходят назад, появление ползёт ~1,9 м — горизонтальный уход бёдер от первого кадра клипа вычитается (иначе монстр «прыгает» сквозь игрока и отскакивает на каждом повторе); у смертей уход оставлен (`ClipEntry.KeepDrift` — тело падает). Запекание экономит размер: у `HordeClip.FrameRate` своя частота (атаки, смерти, оглушение, ожидание — 15 к/с, реакции — первые 0,8 с, появление — 60 кадров на весь клип) → ~590–610 кадров, ~0,7 МБ на вид (RGBAHalf 150 × кадры).
- **Экипировка рядовых** — список `HordeEquipment` (кость Humanoid → модель) в виде; модель вклеивается в меш с весом 1 на кость в бинд-позе, сдвиг/поворот/масштаб — компонент `EquipmentModel` (`Core/Visual`) на префабе модели, общий для всех монстров (билдер добавляет его с нулями). Подсетка на материал+кость — у вида `ExtraMaterials`, рисуется вторым вызовом на пачку. Сейчас — меч `SM_Wep_Sword_09` у Скелета.
- **Орда с видами** — `StressTestDefinition.Monsters` (`HordeSpawn`: монстр + вес) → `HordeSystem.KindList` (`HordeKind`: определение + статы); пусто — встроенный монстр (`StressTestDefinition.Monster` + `Visual`, стресс-тест). На слот — `Kinds` (индекс вида), `StatsOf/DefinitionOf/RadiusOf(agent)`, `MaxRadius` для запросов; расталкивание — по сумме радиусов. Новое состояние **`Emerging`**: замена (не первая волна) `EmergeTime` секунд вылезает из-под земли — по ней бьют (`IsAlive`), но она не ходит и не атакует. Вид слота выбирается по весам (`DeterministicRandom`).
- **Сопротивления** — `StatusSystem.Apply` умножает длительность на `DurationFactor` монстра. **Дроп** — `DropSystem` берёт таблицу монстра (`HordeDrop` у рядовых), иначе пула. **Эффекты смерти** — `MonsterDeathEffects` (Gameplay/Effects, после `DropSystem`): на `Killed` ставит в очередь, применяет на следующем тике (`EffectSystem.Apply`, `hostile`), чтобы цепочки взрывов не рекурсировали в уроне орды.
- **Вид** — `HordeRenderer`: вид на каждый вид монстра (`StressTestDefinition.VisualOf`, `MonsterVisuals` — Build Monsters кладёт виды монстров из списка), пачки по (вид × материал). Клип по состоянию: смерть (сторона — по толчку убийства относительно взгляда: толчок назад = удар спереди → `Death_Front`; слабый толчок — любая), появление (клип сжат в `EmergeTime`), оглушение, реакция на удар (пока монстр в `Stagger`; новый удар перезапускает после 0,3 с), атака (сжата в интервал), бег (фаза копится со скоростью монстра / `LocomotionSpeed` вида, 0,5–2×). Цвет брызг — `SplashColorOf(agent)`. Тень-пятно — по радиусу.
- **Восприятие (5б)** — `HordePerception` (Gameplay/Horde, создаёт и ведёт `HordeSystem`; получает `SoundEventBus` и `VisibilitySystem`): на слот `HordeAwareness` — Wander / Investigate / Alert / Chase. Охотник — сразу Chase. **Бродяги** идут шагом (`HordePace.Walk`, `WanderSpeed`) с одной из `StressTestDefinition.WanderGroups` групп (слот % групп) к её случайной достижимой точке: на группу свой `FlowField`, новая точка раз в `WanderRetarget` с (сдвиг между группами), не больше одной пересборки за тик, двери — пересборка; у точки стоят (idle). Поля групп создаются, только если какой-то вид не охотник. На этапе 6 точку заменит маршрут волны.
  - **Слух**: все звуки шины (кроме чужого этажа) копятся и раз в `ProcessInterval` 0,2 с превращаются в `NoiseField` (Core/Navigation): громкость = радиус − путь (орт. 1, диаг. √2, без срезания углов), окно ±радиус (≤ 24), стену (`BlocksSight`) звук не проходит, кусты/ящики — проходит, закрытая дверь × `ClosedDoorTransmission` 0,5. Звуки одного типа ближе 2 клеток склеиваются (очередь автомата — одно поле; последнее место, наибольший радиус), поле того же звука с того же места пересобирается, иначе вытесняется самое старое из `NoiseSlots` 8. Радиус × `DifficultyDefinition.Hearing`. Услышавший бродяга → Investigate: бежит (`Speed`) по шагам поля к источнику (через закрытую дверь не проходит — упирается); у источника или поле вытеснено → снова Wander. Новый звук перебивает старый.
  - **Зрение**: круг, раз в 0,2 с — клетка монстра в обзоре игрока и игрок ближе `SightRange` × `Sight`. Заметил (зрение, попадание `Damage`, зов) → Alert: стоит лицом к игроку `AlertTime` 0,5 с (idle), потом Chase **навсегда** (игрок не теряется). Незнающие не атакуют.
  - **Зов**: зовущий, заметивший игрока сам, в конце рыка шлёт `SoundType.Call` (`CallRadius` × `Call`, по проходам как звук; × слух не множится): все, кто его слышит, → Alert → Chase; позванные не зовут дальше (без цепочки). Счётчики `Calls`, `FieldBuilds`.
  - Песочница: `AllHunters` (все охотники), `HordeSystem.SpawnGroup` (10 монстров вокруг точки, восприятие поверх данных вида, первый — зовущий) и `SpawnAt` (тесты). `HordeSystem.Paces` — как монстр шёл в этом тике: `HordeRenderer` играет бег по скорости, ходьбу (клипы Walk, темп `WanderSpeed / 0,4`) или ожидание (стоит, рычит).
- **Сложность** — `DifficultyDefinition` (`Core/Monsters`, `Data/Difficulty/Easy|Normal|Hard|Unreal`, меню Purge/Definitions/Difficulty): уровень `DifficultyLevel` + множители слуха, зрения, зова (черновые 0,8 / 1 / 1,2 / 1,4); статы по сложности — этап 6. Пока берётся из `StressTestDefinition.Difficulty` (песочница — Normal, пусто = все 1).
- Песочница: Ходок 3, Бегун 2, Скелет/Лесной зомби/Гуль по 1, `EmergeTime` 2 с.

## Способности и офицеры (5в)
- **Модули способностей** — `AbilityModule` (`Core/Monsters/AbilityModules.cs`), список `MonsterDefinition.Abilities` (`[ModuleList]`, порядок = приоритет). Общее у модуля: перезарядка, `FirstDelay` (не раньше N с погони), дистанция min/max, `NeedsSight`, `HealthBelow` (условие по HP), `Warning` (0,2–2 с, по ТЗ 0,5–1), `Recovery`. Модули: **`ProjectileAbility`** (форма `Straight` / `Arc` / `Fan`, число и угол веера, скорость, урон, дальность, радиус и высота дуги, состояние на игрока, **эффекты попадания** — вложенный список `EffectModule`, инспектор рисует вложенные `[ModuleList]`) и **`StrikeAbility`** (сектор перед монстром: досягаемость, угол, урон, состояние). Рывок и отталкивание — 5г (ниже); «крик» Крикуна — это зов восприятия (`MonsterPerception.Caller`), отдельного модуля нет.
- **`MonsterAbilities`** (Gameplay/Horde, после `HordeSystem`): на слот — индекс каста, фаза `AbilityPhase` (Warning → Recovery), начало фазы, точка/направление прицела, готовность по способностям (`MaxAbilities` 4). Кастует только в погоне (`HordeAwareness.Chase`), в состоянии `Moving`, не оглушённый. Прицел фиксируется на старте (куда стоял игрок) — можно увернуться; дуга — `LandingPoint` (стены укорачивают). Оглушение срывает каст (перезарядка `BrokenCooldown` 1 с), попадание — нет. На время каста `HordeSystem.SetCasting`: монстр стоит и поворачивается к прицелу. Раз в `SightInterval` 0,2 с — `HordeSystem.SetSeesPlayer` (линия без `BlocksBullets`) для каста и тактики. В `GodMode` игроку ничего.
- **Снаряды монстров** — свои плоские массивы в `MonsterAbilities` (≤ `MaxProjectiles` 96, не `BulletSystem`): прямые летят над монстрами, гаснут о стену (`Spatial.QuerySegment`, Blocker) или игрока (круг `PlayerRadius` 0,35); дуга летит `travel / speed` и падает в точку (урон игроку в `ArcRadius`). Конец — `EffectSystem.Apply(hostile: true)` (лужа кислоты — зона монстров), событие `ProjectileEnded`. Урон игроку — `PlayerHealth.Damage(amount, source)` (направление для дуги HUD), состояние — `PlayerStatusSystem.Apply`. `ShotReach` — докуда долетит прямой (линия предупреждения).
- **Тактика дальнего** — `MonsterStats.HoldRange` / `RetreatRange` (`HordeSystem.TickRanged`): в погоне ближе `RetreatRange` — отходит от игрока; почти не сдвинулся `StuckTime` 0,4 с — «прижат», `CornerTime` 2 с обычная погоня и ближний бой; в `HoldRange` и видит игрока — стоит и целится; иначе подходит по полю пути.
- **Виды «по запросу»** — `StressTestDefinition.OnDemandMonsters`: виды с весом 0, в волны не попадают (`PickKind` их пропускает), появляются `HordeSystem.SpawnKind` / `SpawnAt(…, kind)`; `KindIndexOf`. Песочница: строка **Officer** оверлея — кнопка на каждого (`StressController.SpawnOfficer`, 7–9 клеток от игрока).
- **Вид офицеров** — `MonsterViewDefinition` (Core/Horde, по `MonsterId`): префаб с Animator, экипировка (кость → модель), измеренные скорости бега/ходьбы, `CastMoment`/`CastLength` клипа каста, цвет брызг, модель/цвет/размер снаряда. `StressTestDefinition.MonsterViews` + `ViewOf`. `HordeRenderer` такие виды не рисует (цвет брызг берёт из вида). **`MonsterViewPresenter`** (Presentation/Visual/Horde): пул `PoolPerKind` 12 экземпляров на вид при загрузке (не хватило — предупреждение, лишние не рисуются), слот берёт экземпляр и отдаёт после трупа; скрытие вне обзора (`SetActive`), тень `BlobShadows` (масштаб компенсирован). Параметры Animator — `MonsterAnimatorParameters`: `Pace` (0/1/2), `Playback` (скорость / скорость клипа), `Attack`+`AttackIndex`+`AttackSpeed`, `Hit`+`HitIndex` (не во время каста), `Stunned`, `Alert` (рык), `Cast`+`CastSpeed` (в предупреждении `CastMoment·CastLength / Warning` — клип «отпускает» ровно в конце предупреждения, потом 1×), `Dead`+`DeathIndex` (сторона по толчку). **Без выпадов**: атаки, реакции, рык и бросок у офицеров — свои копии клипов `Officer_*` с горизонтальным уходом, вынесенным в root motion (не применяется); остаток (вынос считается по центру масс, ~0,6 м в атаке) снимает `KeepInPlace` — после анимации бёдра подтягиваются к точке монстра, если ушли дальше `MaxHipsDrift` 0,25 м (покачивание ожидания меньше; смерти не трогаются — тело падает).
- **Вид способностей**: `AbilityWarningView` (Presentation/Visual, шейдер `Purge/Warning`, материал `CombatVisualDefinition.AbilityWarning`) — линии (по одной на снаряд веера, обрезаны по препятствию), круг под дугой, сектор удара; заливка растёт к срабатыванию; рисуется и вне обзора. `MonsterProjectileView` — модель снаряда вида (первый меш, по направлению полёта) или светящаяся капля цвета вида со следом; дуга поднимается и опускается. Оба — шаг загрузки `SpawnZombies` (после `MonsterAbilities`; на BuildVisuals он ещё не готов).
- **Офицеры 5в** (Build Monsters → `OfficersBuilder`, данные — черновые, правятся в ассетах): **Крикун** `shouter_common` — зовущий, HP 120, 2 кл/с, удар 10, зов 14; **Дальний** (бродяги, HP 70, 2,2 кл/с, `HoldRange` 7, `RetreatRange` 3, зрение 9): `distant_castle` — стрела (18 урона, 14 кл/с, перезарядка 2,5 с), `distant_forest` — плевок дугой (8 + лужа `Zone_Acid` r 1,2 на 5 с; `Status_Acid` 12/с, держится 1,5 с после лужи), `distant_snow` — веер 3 сосулек по 30° (10 урона, `Status_Slow` ×0,5 на 2 с). Дроп — `Data/Drops/OfficerDrop` (пусто 25, патроны 35, аптечки 18, метательное 12, оружие 10). Громилы (`Ram_*`) — раздел 5г.

## Громила и двери (5г)
- **Двери по рангам** — `MonsterStats.Doors` (`MonsterDoorUse`: `ByRank` по умолчанию — рядовые `Never`, офицеры и элита `Open`, боссы `Break`; явно — `Never/Open/Break`), `DoorDamage` (урон двери за удар); `MonsterDefinition.DoorUse`, `HordeKind.Doors` (ранг разрешён). Запертые и мёрзлые двери стоят для всех (`DoorSystem.IsPassableForMonsters`).
- **`HordeSystem`**: если есть виды, проходящие двери, и закрытые проходимые двери — второе поле пути `DoorFlow` (маска `_doorWalkable` = проходимо + такие двери; строится вместе с основным, в `RefreshWalkable` считается `_passableDoors`). Такие монстры в погоне идут по нему; следующая клетка поля — закрытая дверь и тело ближе `радиус + 0,75` к её центру → `TickDoor`: **Open** — `SetOpen(true)` сразу (дверь остаётся открытой) и идёт дальше; **Break** — стоит лицом к двери, удар раз в `AttackInterval` (первый — через половину), `AttackStart` (вид играет атаку), `DoorSystem.HitDoor`. Шум: открывание 5, удар 9 (`SoundType.Door`). Счётчики `DoorsOpened`, `DoorBlows`. Бродяги и идущие на звук двери не трогают (поля групп и шума — по обычной проходимости).
- **Рывок** — `HordeSystem.BeginDash(agent, направление, скорость, дистанция, расталкивание)` / `EndDash` / `IsDashing`, `DashReach` (докуда пройдёт тело до стены или закрытой двери — линия предупреждения). В рывке монстр только бежит по прямой (оглушение, стена, закрытая дверь — стоп), лицом по ходу.
- **`CrowdImpulse.Shove(horde, from, to, halfWidth, speed, ignore)`** (Gameplay/Horde) — общий «импульс сквозь орду»: живых монстров, задетых телом на отрезке пути за тик, толкает вбок (на ту сторону, где стоят; ровно по центру — по чётности слота) + немного вперёд, без урона (`HordeSystem.Push`). Под машину-таран (Progress, открытые пункты).
- **Модули**: `ChargeAbility` (линия: дистанция, скорость, урон, отбрасывание в клетках, расталкивание кл/с) и `PushAbility` (круг вокруг монстра: радиус, урон, отбрасывание, состояние). `MonsterAbilities`: у рывка в `Begin` считается длина `ChargeLength` (`DashReach`), в `Release` — фаза **`AbilityPhase.Active`** и `BeginDash`; каждый тик отрезок пути тела против круга игрока (`радиус + 0,35`) — урон, `PlayerSystem.Knock` по направлению рывка (без оглушения), рывок кончается; остановился — `Recovery`. Отталкивание — игрок в радиусе и без стены: урон, состояние, `Knock` от монстра. В `GodMode` — ни урона, ни состояний, **отбрасывание остаётся** (стенд должен его чувствовать). Счётчик `ChargeHits`.
- **Вид**: `AbilityWarningView` — рывок линией шириной в тело на `ChargeLength`, отталкивание кругом вокруг монстра. `MonsterViewPresenter` — параметр `CastIndex` (индекс способности; клип каста на способность), тайминг каста — `MonsterViewDefinition.CastTiming(index)` (первая — `CastMoment/CastLength`, остальные — `_moreCasts`); в рывке — бег (`Pace` 2, темп по скорости рывка, ≤ 2×), не каст; атака играется по смене `AttackStart` вне каста и рывка (удары по двери тоже).
- **Масса тела** — `MonsterStats.Mass` (0 = по рангу: рядовые 0,15, офицеры 0,5, элита 4, боссы неподвижны) и `Immovable`; `MonsterDefinition.MassOf/BodyMass` (∞ = неподвижен), `HordeKind.Mass/InverseMass/KnockScale` (= min(1, 1/масса)); масса игрока — `PlayerDefinition.Mass` (1). Где работает: (1) **игрок и монстр** — `HordeSystem.ResolvePlayerContacts` в конце тика: перекрытие тел делится по массам, монстр отходит на свою долю (стены могут остановить — тогда остаток игроку), игрок — `PlayerSystem.Displace` на остаток; толпа не складывается (игрок сдвигается не больше самого глубокого одиночного перекрытия); рядовых игрок по-прежнему почти не замечает, Громилу (6) едва сдвигает, неподвижного — обходит; монстр, прижатый к стене, не пропускает. (2) **толпа** — `Separation`: перекрытие пары делится по обратным массам (равные — пополам, как раньше; неподвижного не двигают). (3) **толчки** — `HordeSystem.Push` × `KnockScale`: отбрасывание оружием (Feel), отлёт трупа, взрывы, `CrowdImpulse` (рывок, будущая машина) — рядовые и офицеры как раньше, Громила 1/6, неподвижный — никак. Оглушение от попаданий массой не меняется.
- **Громилы** (`OfficersBuilder`, Build Monsters): `ram_castle` (орк, молот), `ram_forest` (демон-козёл, топор), `ram_snow` (йети, дубина) — клипы `Brute_*` UAC Creature, `Brute.controller`, рост головы 1,6 м; черновые данные — [PurgeMenu.md](../PurgeMenu.md), Build Monsters. Песочница: кнопки в строке Officer.

## Элита (5д1)
- **Броня спереди** — `MonsterStats.FrontArmor` (доля урона, снимаемая с ударов спереди; 0,5 у Броненосца) и `FrontArc` (ширина фронта, 120°), `MonsterStats.ArmorFactor(facing, направление удара)`. Считается в `CombatTargets.Damage` по направлению полёта удара (`HordeSystem.ArmorFactor`), в событие `Damaged` уходит уже уменьшенный урон, счётчик `ArmoredHits`. Удар **без направления** (`Vector2.zero`: зоны `ZoneSystem`, состояния `StatusSystem`) — всегда полный.
- **Память павших** — `HordeSystem`: кольцо `FallenMemory` 128 смертей рядовых и офицеров (элита и боссы не запоминаются): где, вид, когда. Тела не хранятся — труп исчезает через `CorpseTime`, как раньше. `FindFallen(центр, радиус, возраст, results, max)` — ближайшие сначала; `Raise(index, время подъёма)` — тот же вид встаёт на том же месте в `Emerging` на своё время (`EmergeTimeOf(slot)`; у обычной замены — `MonsterStats.EmergeTime`), сразу охотник; поверх целевого числа; один раз. Счётчик `Raised`. `Reset` забывает всех.
- **Ярость** — `HordeSystem.Enrage(slot, урон ×, скорость ×)` / `IsEnraged` / `DamageFactorOf` (× урон обычной атаки и всех способностей, у снарядов — множитель стрелявшего на момент выстрела); сбрасывается новым монстром в слоте.
- **Модули** (`AbilityModules.cs`): **`AreaStrikeAbility`** (удар по площади с задержкой: круг под игроком на начало каста, в конце — урон и состояние игроку в радиусе и не за стеной, `Impact` — эффекты в центре, враждебные; `WarningRadius`), **`RaiseAbility`** (радиус 7, до `MaxCount` 5, возраст 20 с, подъём 2 с; без павших рядом каста нет; места выбираются в начале каста — `MonsterAbilities.RaiseCount/RaisePoint`), **`RageAbility`** (по умолчанию `HealthBelow` 0,3, без видимости, предупреждение 1 с — рык, форма `None`; один раз за жизнь; **может начаться в ближнем бою** — остальные способности только когда монстр идёт). Эффект смерти — `MonsterDefinition.DeathEffects` (с 5а).
- **Враждебные эффекты** — `EffectSystem.Apply(…, hostile: true)` (снаряды, удар по площади, смерть монстра): взрыв ранит и монстров вокруг, и игрока (меньше к краю, стены закрывают), зона — монстров (вредит игроку), «состояние в радиусе» — только на игрока. `GodMode` орды бережёт игрока.
- **Вид**: `AbilityWarningView` — круг удара по площади, кружки 0,45 на местах подъёма; ярость без предупреждения (рык — клип каста). Подъём: рядовые — клип `Emerge` в своё время слота (`HordeRenderer`), офицеры и элита — состояние `Rise` контроллера, время клипа = `EmergeProgress` (`MonsterViewPresenter`, параметр `Emerging`; бёдра во время подъёма не подтягиваются — лежащее тело далеко от точки).
- **Контент** (Build Monsters → `OfficersBuilder.Elite.cs`, папка `Special`; `Capture_*` (Крюк) пропускается): **Броненосец** `armadillo_common` — контроллер `Armadillo.controller`, клипы `Elite_Shield_*` (UAC Sword&Shield: боевая стойка, ходьба, бег, удары мечом и щитом, реакции, насмешка вместо рыка, смерти, подъём), щит в левой руке, меч в правой, способностей нет; **Шаман** `shaman_castle/forest/snow` — `Shaman.controller`, клипы `Elite_Wizard_*` (UAC Wizard; заклинания выбраны замером рук: подъём — `CastSpell4` руки над головой, удар — `CastSpell6` выпад, обычная атака — заклинания вперёд), посох, держит дистанцию 7 / отходит от 3, способности [подъём, удар по площади]: Замок — взрыв 30 r 1,6, Лес — `Zone_Poison` (`Status_Poison` 8/с) r 1,6 на 6 с, Снег — 6 урона + `Status_Freeze` (оглушение) 1,2 с. Рост элиты 1,45 м, дроп `Data/Drops/EliteDrop` (пусто 5, патроны 35, аптечки 22, метательное 18, оружие 20). Громилам добавлена `RageAbility` первой (клип `Brute_Rage` — `Roar3Creature`; `OfficersBuilder.EnsureRage` добавляет и в существующие). Песочница: строка **Elite** оверлея.

## Чемпионы (5д2)
- **Аффикс — контент** `ChampionAffixDefinition` (`Core/Monsters`, меню Purge/Definitions/Champion Affix, `Data/Monsters/Champions`): цвет свечения (альфа — сила) + модули `AffixModule`: `SpeedAffix` (скорость ×, частота атак ×), `ArmorAffix` (урон с направлением ×; зоны и состояния — полностью), `HitStatusAffix` (состояние игроку при каждом попадании монстра), `TrailAffix` (зона на клетках, с которых сходит; зона монстров; сам её не получает — `HordeSystem.IgnoresZone`), `DeathBlastAffix` (эффекты после смерти через задержку, вложенный список `EffectModule`, круг-предупреждение радиусом самого широкого), `LifestealAffix` (доля урона по игроку в HP), `ResistAffix` (сопротивления состояниям). Значения модулей кэшируются (`OnValidate` сбрасывает).
- **Правила** — `ChampionRules` в `StressTestDefinition.Champions` (до волн этапа 6): шанс для монстров волн (`SpawnOne` → `RollChampion`, 4 % в песочнице), список аффиксов (выбор равновероятно), HP ×2, вид ×1,15 (тело в геймплее — как у вида), дроп на ранг выше (`DropOf(rank)`: рядовые → `OfficerDrop`, офицеры → `EliteDrop`). Чемпионами бывают только рядовые и офицеры (`CanBe`); поднятые Шаманом встают обычными.
- **Состояние слота** — `HordeSystem`: `_affix` (индекс аффикса + 1), `_maxHealth`, `_attackRate`; `MakeChampion(slot, affix)` (HP, скорость, темп атак; один раз), `AffixOf/IsChampion/Affixes`, `MaxHealthOf`, `AttackIntervalOf` (вид и способности берут его), `Heal`, `ArmorFactor` × броня аффикса для ударов с направлением, `ChampionsMade`. Новый монстр в слоте — обычный. Событие **`PlayerHurt(slot, урон)`** — `ReportPlayerHit(slot, generation, урон)`: обычная атака и все попадания способностей (`MonsterAbilities.HurtPlayer`; снаряд помнит стрелявшего и его поколение — снаряд мёртвого никого не лечит). Сопротивления аффикса — в `StatusSystem.Apply`, дроп — `DropSystem`.
- **`ChampionSystem`** (Gameplay/Horde, после `MonsterDeathEffects`): на `PlayerHurt` — состояние игроку и лечение вампира (`Healed`); след — каждый тик клетка, с которой сошёл чемпион, получает зону (`ZoneSystem.Place`, hostile; `TrailCells`); на `Killed` взрывного — отложенный взрыв (≤ 32 сразу; `BlastCount/BlastPosition/BlastRadius/BlastProgress`, `Blasts`), потом `EffectSystem.Apply(hostile)`.
- **Вид**: `Purge/Horde` — инстансное `_HordeGlow` (rgb в цветовом пространстве проекта + сила): подкраска + яркий край по углу к камере; `HordeRenderer` — пульсация 0,8–1,0, масштаб и тень ×`Scale`, гаснет при смерти, клип атаки по `AttackIntervalOf`. `Purge/Lit` — `_Glow` (то же, в эмиссию); у офицеров `MonsterViewPresenter` держит `HitFlash` на экземпляр (`SetGlow`), масштаб от исходного префаба. `AbilityWarningView` рисует круги взрывов чемпионов.
- **Бенчмарк песочницы** (замер этапа 5): `BenchmarkPlan.CreateSandbox` + `StressController` (`SpawnExtras` — двери закрыть, офицеры/элита/чемпионы шага; `TickKills` — бенч убивает ближайшего монстра волн; на время бенча AllHunters и God); автопилот `StressAutopilotInput` регистрируется и в песочнице, но включён только в бенче. Методика — [StressTest.md](../StressTest.md).
- **Песочница**: строка **Champ** — `Offc` (рядовой охотник из видов волн / случайный офицер) и кнопка на аффикс (`StressController.SpawnChampion`, 7–9 клеток от игрока). Создание — Build Monsters ([PurgeMenu.md](../PurgeMenu.md)).

## Орда и стресс-тест (этап 2)
- **Боевая песочница (этап 4а):** `StressTestDefinition.IsSandbox` (`Data/Horde/Sandbox.asset`, уровень `Level_Sandbox` 40×40 — **Build Stress Test Levels**: оружие из `SandboxWeapons` рядом к югу от старта) — орда воюет с оружием игрока: стресс-оружия, автопилота и бенчмарка нет, `CombatSandbox` выдаёт `SandboxAmmo` каждого типа и полную стопку первого метательного (кнопки оверлея SANDBOX: AMMO — пополнить, THROW — стопка следующего вида метательного), орда роняет дроп по `HordeDrop`, кусты к северу и востоку от старта (проверка распространения огня), черновой вид атак без префабов — `WeaponEffectsView` (пламя, молнии, взрывы, искры по орде, горение, оглушение; с 4в на всех уровнях — материалы `CombatVisualDefinition.BoltMaterial/EffectParticles`, иначе песочницы).
