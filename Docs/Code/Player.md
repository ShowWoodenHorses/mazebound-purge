# Игрок, ввод, тики, двери, предметы, оружие в руках

Справочник по текущему коду (перенесён из CLAUDE.md 2026-10-17). Читать, когда задача касается этих систем; **обновлять при их изменении.** Общие правила — [CLAUDE.md](../../CLAUDE.md).

## Игрок, ввод, тики
- Тики уровня: `ILevelTickable` (симуляция, только в Running) → `ILevelLateTickable` (синхронизация вьюх, также в Paused). Порядок шагов внутри одной стадии и тиков = порядок регистрации в `LevelLifetimeScope` (геймплей раньше своих вьюх).
- Ввод: `IPlayerInput` (Gameplay) реализует `InputService` (Application) — карта действий в коде: Move, Look, Attack, Interact, Slot1, Slot2, Reload, Throw (G, LT), OpenMap, Pause; касание по самой игре (не по UI и тач-контролам) — `IPlayerInput.TryGetGroundTap` (`IUiPointer.IsOverUiAt`). Клавиши — по физическому месту (US), не по символу: `<Keyboard>/#(m)` на русской раскладке не находит клавишу; в текстах для AZERTY — ZQSD и Tab вместо M. Кнопки геймплея **опрашиваются из тиков** `WasPressed(PlayerAction)` (нажатия на паузе не применяются позже); Pause — событие `IInputService.PauseRequested`. Мышь — отдельное действие: нажатие, начатое над UI (`IUiPointer` → `UiPointer`, `UIRoot.EventSystem`), не атакует до отпускания. Тач-контролы (`OnScreenButton`, свой стик `TouchStick` с мёртвой зоной и кривой `StickResponse`, плавающий/фиксированный) эмулируют геймпад — новые экранные кнопки биндить на `<Gamepad>/...`. Они на отдельном канвасе `TouchControls` (под основным UI, показывает HUD): единица = 0.1 мм по `Screen.dpi` × размер из настроек, safe area (`SafeAreaFitter`), зеркальная раскладка для левшей. Настройки управления — `ControlsSettings` в `SaveData.Settings` (там же `ShowFps` — счётчик `FpsCounter` слева под статусом HUD, над зоной стика (не в углу — углы на части устройств обрезаны), на основном канвасе поверх всех экранов); экран Settings (меню и пауза; вкладки Controls / Shooting / Other, Reset — только открытая) → `SettingsPresenter`: `SettingsService.PreviewControls` применяет сразу, `SaveControls` пишет при закрытии. Раскладка: `ControlsSettings.Layout` (`TouchLayout`: на элемент `Moved`/`Position` в долях safe area правой раскладки/`Scale`), правится «Edit button layout» → `TouchLayoutEditor` (канвас контролов поверх UI, `TouchLayoutHandle` на элементах, ввод и `TouchPress` выключены, выбранный — в акцентной рамке); `TouchControls._mirrored` = [зона стика, кластер атаки, Use] (порядок `TouchElement`; Melee/Ranged — часть кластера `TouchAttackCluster`, двигаются с ним; их placement в сейве не используется; сейв v3 сбросил старые места, v4 — место Use). Кластер (этап 4в): Attack — четверть круга (прямой угол справа снизу), по её дуге три сектора — слот 2 (`_ranged`, RB), слот 1 (`_melee`, LB) и метательное (`_throw`, LT); у слота — штрихи магазина, дуга перезарядки, запас под иконкой, без патронов и запаса — красная обводка (`WeaponSlotState.Reserve/OutOfAmmo`); Use — круг левее; левша — зеркало содержимого (иконки и числа читаемы). Стик — кольцо с метками режима прицела (`TouchStickMarks`). Прицел (там же, для всех устройств): `AimMode` (Free/Eight/Four — `Aim.Snap` направления атаки и `Facing` при остановке) и автонаведение (`PlayerCombat.AimDirection`: цель в конусе ±30°, без стен); Gameplay читает через `IAimSettings`.
- Позиции игрока — `Vector2` в единицах сетки (x = East, y = North), клетка = `PlayerMovement.CellOf`. Движение `PlayerMovement` (без физики): квадратный футпринт `BodyHalfSize` против непроходимых клеток, по осям (скольжение), подшаги ≤ 0.2, corner assist. Центр не входит в клетку с зомби (`OccupancyMap`).
- Проходимость: `LevelPassability` (флаг `BlocksMovement`; Door — если открыта в `DoorSystem`).
- Состояния (5в): `PlayerSystem.StatusSpeed` (× скорости, замедление) и `Stunned` (не ходит; `PlayerCombat` не атакует, `PlayerThrowing` не бросает) ставит каждый тик `PlayerStatusSystem` (Combat.md); `PlayerHealth.Damage(amount, source)` — удар с направлением, событие `Hurt` (дуга HUD).
- `PlayerSystem.CellChanged(from, to)` = PlayerCellChanged из ТЗ; `Spawned` — после появления. Старт: `LevelLaunchOptions` (StartIndex для Test from Start #N, Seed), иначе случайный через `DeterministicRandom`.
- Общие определения (`PlayerDefinition` "Player/Definition", `PlayerVisualDefinition` "Player/Visual", `ContentCatalog` "Content/Catalog") грузит `SharedDefinitionsService` при старте приложения; в LevelScope прокинуты из проектного. Build/Sync держит их Addressable (группа Purge Shared).

## Двери, ключи, предметы
- `DoorSystem`: open/closed + locked (дверь с `KeyId`, не открытая изначально). `Unlock` только отпирает; открыть запертую нельзя (исключение). События `DoorChanged`, `DoorUnlocked`. **Выбивание (5г)**: `HitDoor(id, damage, from)` — удар монстра по закрытой незапертой немёрзлой двери (`IsPassableForMonsters`); набралось `DoorData.Strength` (поле двери, 0 = `DefaultStrength` 60) — дверь **выбита** (`IsBroken`): открыта навсегда, `SetOpen(false)` — исключение; события `DoorHit(door, from)`, `DoorBroken(door, from)` (перед `DoorChanged(open)`), `StrengthLeft`.
- `PlayerInteraction` (тик после `PlayerSystem`) — Interact: оружие в клетке игрока → иначе соседняя дверь (по `Facing`, своя клетка последней; выбитые не предлагаются): запертая + ключ в `PlayerInventory` → `Unlock` (ключ тратится, дверь закрыта); иначе открыть/закрыть; закрыть нельзя при зомби Maze или теле монстра орды в клетке двери (`HordeSystem.AnyBodyInCell`) или пересечении тела игрока с ней. Событие `Interacted(InteractionResult, door)` для UI.
- `PlayerSystem.Knock(direction, distance)` — отбрасывание от способностей монстров (рывок, отталкивание): заменяет текущий толчок, гаснет как толчок, стены останавливают; `Push` — отдача оружия (с потолком 8 кл/с); `Displace(delta)` — сдвиг сразу (тело тяжёлого монстра, в которое упёрся игрок, — `HordeSystem.ResolvePlayerContacts`). Масса игрока — `PlayerDefinition.Mass` (1), см. [Monsters.md](Monsters.md), «Масса тела».
- `PickupSystem` (шаг `InitializeSystems`, тик — время жизни дропа; подписан на `Spawned`/`CellChanged`): ключи, патроны (в `AmmoStock`), метательное, на которое есть место в слоте (свой тип или пустой слот; остаток лежит), — при входе; аптечка — при входе, если HP не полный (уровневая — до полного, из дропа — `MedkitDefinition.Heal`, 0 = до полного); метательное другого типа — Use (`TryTakeThrowable`, старая стопка падает); дроп монстров — `DropAmmo/DropThrowable/DropMedkit/DropWeaponItem` (`Pickup.IsDropped`, свой id `drop_N`, точка в клетке, `ExpiresAt`; не больше `MaxDropped`, старый уступает; `Pickup.WasTaken` — взят или истёк; на карте не показываются); оружие — `TryTakeWeapon` (через Interact), выброс — `DropWeapon(slot)` (по `WeaponSystem.DropRequested`) в клетку игрока. `WeaponSystem` (этап 4а): **2 слота** `WeaponSlot.First/Second` (огнестрел/ближнее в любом сочетании); пустой слот = **базовый пистолет** `PlayerDefinition.BaseWeapon` (`Glock_base`, бесконечный запас; `WeaponRuntime.IsBase`, не выпадает); подобранное занимает слот с базовым (сначала активный), иначе заменяет оружие в руках — оно выпадает (`PickupSystem.Added`); новое сразу активно; магазин при выбросе не сбрасывается. Клавиши слотов `PlayerAction.Slot1/Slot2` (1/2, LB/RB): нажатие — выбрать, по активному — перезарядка (`ReloadRequested`), удержание `DropHoldTime` (0.6 с, `IPlayerInput.IsHeld`) — выбросить. `WeaponRuntime` хранит исходный `WeaponPickupData` (id и визуал). `PlayerHealth` — HP.
- Presentation: `DoorViewPresenter` (компонент `DoorVisual` на префабе двери: Closed/Open/Lock и/или Animator bool `Open`/`Locked`; без него — прячет рендереры открытой двери; активность корня не трогает — её ведёт видимость; **выбитая** — `DoorVisual.SetBroken` (закрытое полотно, Animator выключен) и падение плашмя от выбившего: четверть оборота вокруг низа за `FallTime` 0,35 с с ускорением, подъём на полтолщины — late tick), `PickupViewPresenter` (`EntityViewRegistry.Remove` взятых, вьюха выпавшего оружия по его сохранённому визуалу), `HudPresenter` (шаг `InitializeUI`, пишет в `UIRoot.Hud` из проектного скоупа).
- Дев-контент: `Level_Items` (копия Level_Dev с дверями, ключом, аптечкой, оружием; PlayMode-тест предметов), двери-заглушки (Purge → Dev → Rebuild Placeholder Doors).
- **Оружие (этап 4а):** определение `WeaponDefinition` = редкость (`Rarity`), «без прокачки», `WeaponHold` (как держать: набор анимаций), звуковая группа + **модули** (`WeaponModules.cs`): ровно одна атака `WeaponAttack` (`Interval`, `Automatic`) — `BulletAttack` (пули/веер дроби `Pellets`, `Spread`, `Range`, `Pierce`), `StreamAttack` (конус-струя, урон в секунду), `ChainAttack` (цепная молния: первая цель в конусе, прыжки с ослаблением), `ExplosiveAttack` (снаряд со взрывом: цель/стена/конец дальности, урон к краю меньше, стены укрывают), `MeleeAttack` (сектор); `AmmoModule` (тип патронов, магазин, перезарядка, патронов на атаку, бесконечный запас, свой радиус шума), `SilencerModule` (шум ×), `MobilityModule` (скорость в руках и при стрельбе — только активное оружие). `WeaponDefinition.Validate` (одна атака, у дальнего — патроны). **Патроны** — контент `AmmoDefinition` (`Data/Ammo`, 7 типов: радиус шума калибра + `ModelFolders` — папки моделей этого калибра). Запас — `AmmoStock` (по id типа, без лимита). Всё собирает **Purge → Dev → Build Weapons** (`WeaponsBuilder`): модели в `Art/Weapons/Purge`, папка 1-го уровня = класс (`Pistol`, `Auto`, `Shotgun`, `Sniper_rifle`, `Ballons`, `Energy`, `Another`, `Melee` — черновые модули класса в `WeaponsBuilder.Classes`), глубже — калибр (тип патронов — тот, чьи `ModelFolders` содержат самую глубокую папку пути); не оружие — `For_monsters`, `Throw` (метательное, 4б), `*_Ammo` (снаряды); связь модель ↔ определение — `WeaponVisualCatalog`, новой модели — определение с черновиком класса (`Data/Weapons/<модель>.asset`, id из имени файла; файл с таким именем уже есть — берётся он); списков контента в коде билдеров не держать. Остальное: `WeaponVisualCatalog` ("Weapons/Visual", грузит `SharedDefinitionsService`), метки `WeaponModel` (Muzzle/Tip; у огнестрела `Grip_L` — левая ладонь из позы выстрела; ближнее, длинное не по +Z, — `GripRotation`), пикапы «лежит боком» в Weapon Set темы, `CharacterWeaponRig` на игроке; после новых моделей — Convert Object Materials to Purge Lit. В руках — `PlayerWeaponPresenter` (шаг `SpawnPlayer` после `PlayerViewPresenter`): модели оружия уровня грузятся при загрузке; ближнее — жёстко в `WeaponSocket_Melee`; огнестрел каждый `LateTick` позирует `CharacterWeaponRig.PoseGun` (после Animator, без Humanoid IK): рукоять в правой ладони, ствол — куда его направляет клип (правая → левая ладонь); корпус «стрелковой» стойки доворачивается к взгляду до `_bodyYaw` (20°, ноги как в клипе); затем правое запястье доворачивает ствол к линии выстрела на `Aim Barrel` (префаб: 1; клипы rifle держат ствол ~23° левее; доворот корпуса `Max Twist` в префабе 0 — он уводит левое плечо и ствол ещё левее, замер 2026-10-08); левая рука — `TwoBoneIK` на `Grip_L` (вне досягаемости — оружие чуть поворачивается к плечу). Состояния аниматора с тегом `NoHandIK` (перезарядка, урон, Use) — без IK левой руки, `NoWeaponPose` (смерть) — без позы; всё плавно за 0.15 с.
