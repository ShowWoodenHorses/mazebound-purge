# Идеи будущих проектов на базе Purge

Обсуждение 2026-10-16. Не план и не ТЗ — заметки, чтобы не забыть. Оценки на глаз.

## 1. Кооп / онлайн до 4 игроков (Purge)

**Помогает:** нет физики (состояние — плоские массивы), Gameplay отделён от View, детерминированная случайность и стабильные id, ввод через `IPlayerInput`.

**Мешает — всё рассчитано на одного игрока:** один `PlayerSystem`, `FlowField` к одному игроку, видимость/туман/камера на одного, правила смерти и победы; пауза останавливает тики (в онлайне паузы нет — карта, подсказки, выбор карточек); сейв и прогрессия персональные.

| Вариант | Объём |
|---|---|
| Локальный кооп (один экран) | ~2–4 недели; на вебе/телефоне малополезен |
| Онлайн с друзьями, хост-авторитетный, через relay | ~2–4 месяца: снапшоты орды с дельта-сжатием по обзору, предсказание своего игрока, лобби, переподключение |
| Публичный матчмейкинг, выделенные серверы | ещё +2–3 месяца и расходы на серверы |

- WebGL: только WebSocket/WebRTC, нужен relay.
- Lockstep для шутера рискован: float на WASM/ARM не побитово одинаков, 100+ монстров расходятся → fixed-point.
- **Если кооп вероятен — заложить заранее:** игроки массивом с `PlayerId`, фиксированный шаг симуляции отдельно от кадра, ввод как команды.

## 2. Вид от первого лица

Другая игра на общем ядре — **форк**, не правка.

- **Переносится (~половина кода):** контент-как-данные, модули, оружие, дроп, карточки, сейв, магазин, платформы, реклама, локализация, звук, UI, логика монстров и навигация.
- **Заново:** уровни и арт (сейчас под камеру сверху: блоки, нет потолков, плоский туман, поклеточное скрытие), вертикаль (прицел, хитбоксы, прыжки, лестницы — своя математика без физики), руки и детальное оружие, мобильное управление.
- **Главный риск:** 100+ монстров вблизи на слабом телефоне в браузере (нужен LOD, overdraw, ≤ 20 МБ загрузки).
- **Дешёвая середина:** третье лицо / наклон 45–60° — почти всё переиспользуется.

## 3. Стратегия в духе «Первобытных войн»

Развитие идеи (механики, изменения, режимы, MVP) — [StrategyIdeas.md](StrategyIdeas.md).

**Суть:** юниты не строятся в казармах — рождаются детьми от пары мужчина + женщина; любой может стать кем угодно — нужно сделать оружие и обучить. Ресурсы (дерево, камень, еда, …) собирают юниты. Охота на зверей в лесу, у зверей требования к оружию (кому хватит любого дальнего, но мало ближнего; кому подойдёт любое медленное). Стройка, ускоряется числом строителей (с лимитом). 3D, камера ~60°. Режим против бота, позже PvP. Платформы: ПК, мобилки, веб.

**Ложится на Purge:**
- сетка 1×1 с флагами — постройки по клеткам, ресурсы = препятствия с запасом;
- плоские массивы и инстансинг с запечённой анимацией — 100–300 юнитов на телефоне;
- A*, flow field, occupancy, пространственные запросы;
- туман войны (маски W×H) — родная механика;
- модули контента: оружие, уязвимости зверей, постройки, навыки;
- вся инфраструктура: площадки, реклама, сейв, облако, локализация, звук, UI, сборки, лёгкая веб-загрузка.

**Новая работа (основная):**
1. Управление: выделение, приказы, очереди. Для мобилок — **косвенное управление** (назначить N человек на ресурс, приоритеты работ, как Settlers/Banished).
2. Экономический AI юнитов (job system): добыть → отнести на склад → вернуться, стройка, охота группой, потребности.
3. Демография: пол, возраст, семьи, взросление, навыки, обучение; долгий баланс роста населения.
4. Звери: стада, бегство, агрессия, уязвимости (модули монстров Purge).
5. **Бот-соперник** — самая недооценённая часть: сценарные планы развития + эвристики, уровни сложности.
6. Предметы в руках инстансированных юнитов: кость руки из текстуры анимации + инстансируемый меш предмета.

**PvP:** детерминированный lockstep — по сети только приказы, трафик мал, задержка 100–200 мс незаметна, WebSocket-relay в браузере подходит. **Условие: детерминированная симуляция (fixed-point, свой порядок обновления, без зависимости от кадра) с первого дня** — переделка потом ≈ написать заново. Код боя Purge на float → для PvP геймплей пишется заново, переносится инфраструктура, сетка, данные. Сложности: рассинхроны (нужны инструменты), переподключение, maphack.

**Оценка:** против бота — проект больше Purge. PvP — плюс несколько месяцев. Делать **форком Purge** (как Purge от Maze), убрав шутер.

## 4. Вселение в любого юнита (к стратегии)

Реально; прецеденты — Dungeon Keeper, Battle Realms, SpellForce.

- **Техника:** у юнита выключается AI задач, он получает ввод игрока (та же подмена `IPlayerInput`, что у стресс-автопилота). Движение и бой — **код Purge** (стик, прицел, ближний/дальний бой, автонаведение) — главная синергия проектов. Вид: инстансированный юнит при вселении заменяется полной моделью с Animator, при выходе возвращается в массив.
- **Колония живёт дальше:** оповещения, быстрый выход, возможно лимит вселения; в PvP паузы нет — риск как механика.
- **Почему игрок лучше бота — задать явно**, иначе фича пустая: тайминг при рубке ×2 добычи, прицельный выстрел добивает зверя, манёвры в бою.
- **Камера решает цену:** близкий вид сверху / третье лицо — дёшево, тот же арт, **работает и на мобилках/вебе** (это управление Purge); первое лицо — дорого, только ПК.
