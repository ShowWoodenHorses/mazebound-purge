# Опыт Maze — правила и уроки для Mazebound: Purge

Статус: черновик (2026-10-13). Собрано из `CLAUDE.md`, `Docs/Progress.md` и памяти агента в проекте Maze.
При клонировании: разделы 1–2 → правила в новом `CLAUDE.md` и память агента; разделы 3–6 → `CLAUDE.md` (ловушки, принятые решения) и `Docs/Progress.md` (раздел решений).

## 1. Договорённости с пользователем (обязательные)
- Общение на русском.
- **Git-коммиты не делает агент** — всегда пользователь. После завершения этапа плана — в конце ответа предложить название коммита.
- **Сборки (APK, WebGL и т.п.) — только после подтверждения пользователя**, кроме случаев, когда он сам попросил сборку. В конце этапа предлагать сборку, а не запускать.
- **Согласованный многоэтапный план** выполняется подряд: короткий отчёт после каждого этапа, без ожидания подтверждения (но сборки и коммиты — по правилам выше). Каждый этап заканчивается в рабочем состоянии (компиляция, сцены, тесты).
- **Progress.md** читать перед работой; после каждого этапа обновлять статус, решения и историю. Генерацию уровней (контент) в историю **не** писать — только код и тулзы.
- Справочники обновлять вместе с изменениями: команды меню (аналог `MazeMenu.md`), руководство по редактору уровней (аналог `LevelDesigner.md`), список префабов.
- **Закреплённые правила не игнорировать** — если что-то нарушено (например, настройки Play Mode), исправить, а не просто сообщить.
- **Контент без кода и без ручного ввода id**: билдеры находят контент по папкам/именам файлов; строковое поле, ссылающееся на контент, — выпадающий список (`PropertyDrawer`), не текст (опечатки молча ломают). Любой оставшийся ручной шаг — отметить и предложить убрать.
- Решения пользователя фиксировать с датой («решение пользователя 2026-10-10»), отклонённые идеи — тоже (зачёркнутым), чтобы не предлагать их заново.

## 2. Работа с Unity через MCP
- После правок скриптов — проверять консоль (`read_console`, только ошибки/предупреждения по теме, малый `count`).
- Экономить контекст: не запрашивать всю иерархию, большие списки и логи; то, что есть в файлах, — читать файлы.
- **Enter Play Mode Options**: перезагрузка домена при входе в Play включена (`m_EnterPlayModeOptions: 0`, решение пользователя). MCP-прогоны PlayMode иногда оставляют `1` — после каждого прогона проверять `git diff ProjectSettings/EditorSettings.asset` и возвращать **через API** (`EditorSettings.enterPlayModeOptions = None; AssetDatabase.SaveAssets()`), не правкой файла.
- **Колбэки `EditorApplication.update`** из `execute_code` (виртуальный геймпад, автопауза…) обязаны отписываться при любом исходе: цель достигнута, лимит кадров/времени, выход из Play, нет объектов, исключение (try/catch). Застрявший колбэк однажды залил консоль 999+ исключениями. Спасение — `EditorUtility.RequestScriptReload()`.
- **Пункты меню с `DisplayDialog`** через MCP не запускать (модальное окно блокирует редактор, все вызовы MCP висят) — вызывать их API через `execute_code` (например, `RuntimeScenesBuilder.Rebuild()`; для него сцены Bootstrap/Game не должны быть открыты).
- **VContainer перезаписывает шаблоном** любой новый `*LifetimeScope.cs` при создании его `.meta`. Создав такой файл снаружи Unity: refresh → записать содержимое ещё раз.
- **PlayMode-тесты**: `[UnitySetUp]`/`[UnityTest]` не возвращают `UniTask.ToCoroutine(...)` напрямую — только через итератор-обёртку (`yield return UniTask.ToCoroutine(...)`), иначе NRE во всех SetUp/TearDown после EditMode-прогона (MCP гоняет без перезагрузки домена).
- PlayMode-тесты, которые пишут сейв, сохраняют и восстанавливают настоящий ключ сейва в `PlayerPrefs`.
- Проверка компиляции под Android без смены платформы — `PlayerBuildInterface.CompilePlayerScripts` (target Android + нужные define).

## 3. Код и Unity: ловушки
- Пространство имён `X.Application` перекрывает `UnityEngine.Application` — писать `UnityEngine.Application.xxx` полностью. (В Purge: не называть сборки/namespace словами, совпадающими с типами Unity.)
- UniTask в Unity 6: `AsyncOperation` ожидать через `.ToUniTask()`.
- `animator.parameters` аллоцирует — наличие параметров кэшировать.
- Пауза — не через `Time.timeScale`: уровень перестаёт тикать `ILevelTickable`. Замедление времени (если будет) — своей «скоростью игры» в тиках.
- Кнопки геймплея **опрашиваются из тиков** (`WasPressed`), а не событиями — нажатия на паузе не применяются после неё.
- Нажатие мыши, начатое над UI, не атакует до отпускания (`IUiPointer`).
- Клавиши — по физическому месту (US), не по символу: `<Keyboard>/#(m)` не работает на русской раскладке. В подсказках для AZERTY — ZQSD.
- Во время игры **ничего не создавать впервые**: всё (эффекты, свет, декор, частицы) создаётся/пулится при загрузке и прогревается (`LevelWarmup`, `IViewWarmup`), затем `GC.Collect`. Частицы при прогреве проматываются (0.02 с), после прогрева системы, которые должны идти, перезапускаются.
- Runtime-меши и текстуры уничтожать явно; после выгрузки уровня — `Resources.UnloadUnusedAssets`.
- Цвета палитры — sRGB, в вершины пишутся в Linear.
- Шейдеры эффектов — `ColorMask RGB` (не портить альфу кадра в WebGL).
- Билдеры персонажей пересобирают контроллер аниматора **на месте** — не удалять ассет (ломает ссылки префабов).
- Общий `Characters.fbx` Synty целиком попадает в сборку — меши/аватар персонажей копировать отдельно (`CharacterMeshExtractor`).

## 4. Сборка, Addressables, веб и площадки — ловушки
- **Не-Addressable ассет, на который ссылаются несколько групп, копируется в каждый бандл** — в сборке это разные объекты (в редакторе — один). Дубли выносить в общую группу автоматически перед сборкой; остались дубли — сборка не идёт. Не сравнивать определения из разных Addressable-корней по ссылке без запасного сравнения по id. PlayMode-тесты (режим AssetDatabase) такое не ловят.
- **Размер веб-загрузки**: до первого `gameplayStart` ≤ 20 МБ (CrazyGames, мобильная главная). Визуальные бандлы — по отдельности (уровень качает только своё), общие зависимости — одним бандлом (много мелких файлов — кэш браузера перепроверяет каждый, +3 с на старте). Замер — CDP-скриптом (байты до `gameplay start`).
- Текстуры паков на WebGL/Android ограничивать: цвет ≤ 1024, нормали ≤ 512, свечение ≤ 256, персонажи ≤ 512.
- LZMA на WebGL нельзя (Addressables молча оставляет LZ4). WebGL: Brotli + fallback, хеши имён, IL2CPP size, stripping Medium + `link.xml`.
- **Мобильные браузеры не поддерживают DXT** — подцель текстур WebGL **ASTC**.
- **Звук WebGL на мобильных**: короткие клипы (< 128 КБ) Unity декодирует через `decodeAudioData`, мобильный Chrome не декодирует AAC → тишина. WebGL-override — **MP3** с **явной** частотой (`OverrideSampleRate` 44100; Preserve молча отклоняется — проверять возвращаемое значение).
- Unity 6 блокирует http (кроме localhost) — для проверки сборки по LAN разрешить http в настройках сборки, иначе Addressables не грузятся.
- Проверка на телефоне — сборка по `http://<ip>:8080`, консоль браузера — CDP через `adb forward tcp:9222 localabstract:chrome_devtools_remote` (PowerShell `ClientWebSocket`, без установки); `Page.addScriptToEvaluateOnNewDocument` — подменить функции для логирования.
- **Атласы шрифтов** содержат только ASCII + символы из таблицы переводов: новый символ появляется после попадания в таблицу и пересборки локализации; звёзды и т.п. — иконками.
- Заглавные — в таблице переводов, **никакого `ToUpper`** (турецкое i/İ). Проценты — через строку формата (tr «%50», de «50 %»).
- Safe area — только через обёртку площадки (`WebPage.SafeArea`), не голый `Screen.safeArea`: ВК сообщает свои отступы, приложение ВК на Android не сообщает панель навигации (запас по бокам + сдвиг кнопок справа сверху на телефоне).
- Углы экрана на части устройств обрезаны — важное (счётчик FPS и т.п.) не в углу.
- **ВК**: значение Storage ≤ 4096 символов, ≤ 1000 вызовов/ч → сейв частями в слоты A/B, указатель пишется последним; хостинг ВК меняет адрес при каждой выкладке (поэтому облако), запрещены аудио/видео-**файлы** (звук — внутри бандлов); событие старта рекламы не приходит — тишина при запросе.
- **CrazyGames**: interstitial только между уровнями; `adsDisabledBasicLaunch` → награда бесплатно; новый игрок сразу в игре (`StartsInGameplay`); happytime — только на настоящем достижении.
- **GameDistribution**: запрещены внешние ссылки, контакты, чужая реклама/аналитика, покупки; частоту interstitial ведёт SDK.
- **Яндекс**: инициализация с таймаутом; вход только по кнопке игрока, затем слияние сейвов.
- **Android / RuStore**: плагин myTarget закреплён на версии SDK, под которую написан (`AndroidJavaProxy`-слушатели должны совпадать с интерфейсами); плагин отдаёт по одному колбэку за кадр (результат рекламы — через несколько кадров после закрытия); EDM — пакет Unity, настройки без диалогов; подпись — вне git.
- Любой упавший SDK площадки — не ломает игру (идёт как «без площадки»); упавший синк аналитики — тоже.
- Сторонние паки качаются в игнорируемую папку `Import`; используемое переносится в `Art/ThirdParty` (GUID сохраняются, коллайдеры/Rigidbody снимаются) **до коммита**; ссылок на `Import` быть не должно.

## 5. Проверенные решения архитектуры (переносить)
- Слои `Core ← Gameplay ← Application ← Presentation`, отдельная сборка Composition (VContainer знает только она).
- Сцены: Bootstrap (всегда) + Game (аддитивно на уровень, `LevelLifetimeScope` дочерний, `autoRun = false`). Выгрузка Game убирает всё уровня.
- `GameFlow` не знает VContainer; переходы по одному, новый отменяет текущий; любое исключение → полная выгрузка → экран ошибки.
- Загрузка уровня — шаги `ILevelLoadStep` по стадиям; регистрация в скоупе = порядок; последний — прогрев.
- Тики: `ILevelTickable` (симуляция, только в Running) → `ILevelLateTickable` (вьюхи, и на паузе).
- Addressables только через владельцев handle; `ActiveHandleCount` в тестах на утечки.
- `GameLog` с каналами вместо `Debug.Log`.
- `LevelData` — источник правды, мутация только `internal` (редактор и тесты), правки — через класс команд редактирования, покрытый тестами.
- Валидатор с кодами проверок; невалидный уровень не запускается.
- Визуал выбирается хешем от seed и сохраняется (`VariantId` + поворот) — никакого рандома визуала в runtime.
- Геометрия без GameObject на клетку: склейка мешей в чанки, клетка в UV3, поклеточное скрытие маской в шейдере; маски-текстуры W×H для всего, что «по клеткам» (видимость, туман, сугробы, свет).
- Свет без ламп Unity: глобалы фонаря + световая карта уровня в шейдере.
- Пятна-тени вместо realtime-теней.
- UI: свои SDF-фигуры (`UiShape`, один материал — батчинг), сцены и вёрстка собираются кодом (билдер сцен, а не ручная правка сцены).
- Полоски HP и цифры урона — один динамический меш, без Canvas и аллокаций.
- Звук: свой пул 2D-голосов, громкость/пан считают вьюхи; каталог звуков по именам файлов; музыка грузится только пока играет.
- Локализация: таблица TSV → таблицы на язык (грузится только выбранная), ключи-константы, проверка таблицы при сборке.
- Платформенный слой: `IGamePlatform`, `IAdProvider`, `IAnalyticsSink`, облако в `SaveService` (облако важнее при старте, запись с задержкой и склейкой, при уходе в фон — сразу), `PlatformTraits` для различий площадок, define площадки только в сборке плеера.
- Тесты: много EditMode на чистой логике (фазз-тесты движения, массовые прогоны генератора на 1000 seed'ов), PlayMode — сквозные проверки потока и утечек.

## 6. Уроки геймдизайна и UX из Maze
- Маленькие кнопки на телефоне: клик — внутри фигуры + запас (`HitPadding`, `raycastPadding`), иначе мимо; порог перетаскивания — ~2 мм по dpi.
- Тонкие элементы (ползунки) ловят касание только своим rect-ом — нужна невидимая зона касания.
- Раскладку тач-кнопок игрок должен мочь двигать и масштабировать; левша — зеркально.
- Стрельба на бегу рывками «шаг-стоп» — плохо: при зажатой атаке игрок стоит, стик только поворачивает.
- Предупреждение перед атакой врага (рык 0.5 с перед погоней) — честно и читаемо.
- Визуал удара ждёт момента контакта в клипе, урон по геймплею — сразу.
- Зона зрения на полу должна совпадать с геймплеем (иначе игрок не верит игре).
- Стиль эффектов — мультяшный, без крови и следов пуль.
- Камера не вращается — вверх экрана всегда север, ввод на это опирается.
- Рекламу никогда не показывать внутри действия; звук глушится по реальному старту рекламы.
