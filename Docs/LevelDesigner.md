# Level Designer — руководство

Как пользоваться конструктором уровней: что откуда берётся, где что настраивать и как добавлять новый визуал.

---

## 1. Быстрый старт (5 минут)

1. **Purge → Dev → Create Placeholder Theme**. Создаётся тестовая тема с простыми префабами. Нужно один раз; если у вас уже есть своя тема, этот шаг пропустите.
   Для запуска уровня в игре нужен ещё игрок: **Purge → Dev → Create Placeholder Player** (тоже один раз, см. раздел 9).
2. **Purge → Level Designer**. Открывается окно конструктора.
3. Кнопка **New Level** на верхней панели: сохраните ассет уровня, например в `Assets/_Project/Data/Levels/`.
4. Вкладка **Visuals** → в поле **Theme** укажите тему (например, `PlaceholderTheme`).
5. Вкладка **Generation** → выберите **Biome Recipe** (Лес — `Data/Recipes/ForestRecipe`), задайте размер (Лес — 64×64) и нажмите **Generate New** (без рецепта — открытая площадка, см. раздел 5).
6. Вкладка **Edit**: дорисуйте стены и двери, расставьте ключи, зомби, оружие и прочее.
7. Вкладка **Validate**: ошибок быть не должно.
8. **Build Preview** — посмотреть уровень в 3D в сцене. **Build / Sync** — зафиксировать уровень для игры.
9. **Play** или **Test from Start ▾** — сразу сыграть уровень (Build / Sync делается сам).

## 2. Главные идеи (прочитать обязательно)

**Логика и визуал — разные слои.**
- Тип клетки (`Wall` / `Floor` / `Door`) определяет геймплей: можно ли пройти, видно ли сквозь неё, летит ли пуля.
- Префаб (`wall_02.prefab`) отвечает только за внешний вид. Никакой игровой логики в префабе нет.

**Случайность есть только при создании уровня.**
- Генератор и подбор визуала используют seed'ы.
- Результат (какая клетка какой вариант получила) **сохраняется в уровень**.
- Игра никогда не выбирает префаб случайно: один и тот же уровень всегда выглядит одинаково на любом устройстве.

**Два независимых seed'а:**

| Seed | Что определяет |
|---|---|
| **Layout Seed** | расстановку столбов на площадке (раздел 5) |
| **Visual Seed** | первоначальный выбор визуальных вариантов (какой пол, какая стена) |

Если поменять только Visual Seed, геометрия останется той же, изменится только внешний вид. И то лишь после нажатия **Regenerate Visuals**: просто изменение числа уровень не трогает.

**Генератор даёт черновик, дизайнер доводит до финала.** После **Generate New** можно менять что угодно. Генератор сам ничего не перегенерирует.

**Пол есть под каждой клеткой.** Визуально у клетки два слоя:
- **Floor** — у **всех** клеток: пол, стена, дверь. Поэтому пол сплошной и вокруг тонких стен нет пустот;
- **Wall** — только у клеток-стен, ставится поверх пола.

Это чисто визуальное правило. Для геймплея стена остаётся стеной.

**Приоритет визуала клетки или объекта:**
```
Ручной Override дизайнера  >  Сохранённое назначение  >  Default-вариант набора  >  нет визуала (ошибка)
```

## 3. Где что лежит

| Что | Где |
|---|---|
| Уровни (`LevelData`) | `Assets/_Project/Data/Levels/` |
| Визуальные темы и наборы | `Assets/_Project/Data/Themes/` |
| Тестовые префабы-заглушки | `Assets/_Project/Art/Placeholders/` |
| Игрок: параметры (`PlayerDefinition`) и внешний вид (`PlayerVisual`) | `Assets/_Project/Data/Player/` |
| Код логики уровня (данные, генератор, визуал, валидатор) | `Assets/_Project/Scripts/Core/` |
| Код конструктора (окно, инструменты) | `Assets/_Project/Scripts/Editor/LevelDesigner/` |
| Тесты | `Assets/_Project/Tests/EditMode/` |

**Как связаны ассеты:**
```
LevelData (уровень)
├── Generation settings     — рецепт биома, размер, seed'ы, плотность столбов (без рецепта)
├── Geometry                — тип каждой клетки
├── Объекты                 — двери, ключи, старты, зомби, оружие, аптечки
├── VisualTheme ──────────► VisualTheme (тема, общая для многих уровней)
│                             ├── Floor Set ─► VisualSet ─► варианты: id, prefab, weight, category, color tag
│                             ├── Wall Set
│                             ├── Door Set, Key Set, Medkit Set, Weapon Set, Zombie Set, Decor Set, Light Set
└── VisualData              — сохранённый результат: (клетка, слой Floor/Wall) или объект → VariantId + поворот,
                              плюс ручные overrides
```

## 4. Окно конструктора

**Слева** — вкладки и инспектор выделенного. **Справа** — схема уровня (вид сверху, север вверху).

### Управление на сетке
| Действие | Как |
|---|---|
| Масштаб | колесо мыши |
| Сдвиг схемы | кнопка **Hand (H)** на верхней панели (или клавиша **H**), затем тянуть ЛКМ. **Зажатый пробел** включает руку временно. Также работают средняя кнопка мыши и **Alt + ЛКМ**. Текущий инструмент при этом не сбрасывается |
| Применить инструмент или выбрать | **ЛКМ** (можно протягивать) |
| Удалить выделенный объект | **Delete** |
| Вернуться к инструменту Select (и выключить руку) | **Esc** |
| Отменить или повторить | **Ctrl+Z / Ctrl+Y**. Один мазок кистью = один шаг отмены |
| Вписать уровень в окно | кнопка **Fit** |

### Обозначения на схеме
| Значок | Что это |
|---|---|
| тёмная клетка / светлая / коричневая | стена / пол / дверь |
| **S** | стартовая точка игрока |
| **D** | дверь. Цвет буквы — цвет пары ключ↔дверь, белая — дверь без ключа |
| **K** | ключ (в цвете своей двери) |
| **Z** | зомби |
| **W** | оружие |
| **+** | аптечка |
| **M** | точка появления монстров волн |
| **B** | бочка: зелёная — газ, оранжевая — огонь, жёлтая — кислота |
| **C** | сундук: коричневый — обычный, золотой — запертый, фиолетовый — с испытанием |
| розовая рамка | арена (толстая — её свободные клетки, тонкая — с кольцом); зелёные полосы — проёмы кольца шириной ≥ 3, оранжевые — узкие |
| голубая заливка | область блокировки (Generate её не трогает) |
| маленький квадрат в левом нижнем углу клетки | декор: тёмный — поставлен авторасстановкой, зелёный — вручную |
| красная / оранжевая рамка | ошибка / предупреждение валидатора в этой клетке |
| жёлтая рамка | выбранная клетка |
| голубая рамка | выбранный объект |

**Строка внизу** показывает клетку под курсором, её визуал (пол + стена + декор: вариант, поворот, источник) и итог валидации.

**Инспектор выделенного (слева внизу):**
- информация о клетке и её визуал по слоям с возможностью ручной замены:
  - **Floor override** — пол, у любой клетки, в том числе под стеной;
  - **Wall override** — стена, только у клеток-стен;
  - **Decor override** — декор, только у клеток пола: **(automatic)** — решает авторасстановка, **(none)** — здесь декора нет никогда, вариант — поставлен вручную (+ **Decor rotation** четвертями);
  - **Decor shift (X, Z)** (до ±0.5 клетки), **Decor height** (−0.5…2 м), **Decor turn** (градусы) — точное положение декора; любая правка делает авто-декор ручным. **X -0.25 / X +0.25 / Z -0.25 / Z +0.25** — сдвиг на четверть клетки одной кнопкой. **Reset decor placement** — обратно в центр клетки. Предметы, поставленные на этот декор (**Put on decor**), двигаются, поднимаются и поворачиваются вместе с ним;
- кнопки объектов в клетке;
- настройки выбранного объекта.

## 5. Вкладка Generation

| Поле | Смысл |
|---|---|
| Biome Recipe | рецепт генератора биома (`Data/Recipes`, этап 7): список шагов-модулей; пусто — открытая площадка (dev-уровни) |
| Width / Height | размер в клетках (1 клетка = 1×1 м); минимум 16×16 с рецептом, 5×5 без него |
| Layout Seed / Visual Seed | см. раздел 2. Кнопка **Random** подставляет случайное число |
| Obstacle Density | только без рецепта: одиночные столбы на клетках с обеими чётными координатами (0 — открытая площадка) |

**Две кнопки.**
- **Generate** (только с рецептом) — генерирует заново всё, **кроме клеток, правленных руками, и областей блокировки**: они сохраняют клетку (стена/пол, поверхность, препятствие), объекты, источники света, точки появления и ручной визуал. Старт, точки появления и арена на таких клетках остаются — остальное строится вокруг них.
- **Generate New** — разрушительная: заменяет геометрию, все объекты, весь визуал, ручные метки и области блокировки.
Обе спрашивают подтверждение и отменяются Ctrl+Z. Проблемы генерации (арена не влезла, мало точек появления…) показываются под кнопками.

**Ручные метки.** Любая правка клетки в Level Designer (кисти, Erase, перенос объекта, ручной декор, свет) помечает клетку как ручную. Счётчик и кнопка **Clear Marks** — под кнопками генерации: после снятия меток **Generate** снова может менять эти клетки. Области блокировки — прямоугольники в `LevelData`, рисуются кистью **Lock Area** (вкладка Edit).

**Рецепт Леса** (`ForestRecipe`, шаги по порядку; числа — в инспекторе рецепта):
1. **Perimeter** — лес-стена 2 клетки по краю (клетки `Wall`, вид — деревья).
2. **Start** — старт в центре, открытая земля r 3.
3. **Arena** — 16×16, кольцо деревьев 2 клетки, 3–4 входа шириной 3, центр ≥ 20 клеток от старта (`LevelData.Arena`).
4. **Spawn Points** — 6–8 у краёв (до 6 клеток от периметра), ≥ 12 от старта и вне его обзора 21×21, между собой ≥ 10, у каждой открыто 3×3.
5. **Clearings** — 3–5 полян диаметром 6–10.
6. **Trails** — тропы шириной 3 (дерево связей между стартом, полянами, входами арены и точками появления); петляют по шуму.
7. **Obstacles** — деревья/кусты/камни по весам (60/25/15) рощами, не больше 35 % клеток чанка 8×8; не на тропах, полянах, арене.
8. **Ground** — земля на тропах, полянах и у старта (только вид и шаги; край мягкий и неровный).
9. **Grass** — трава (горит) пятнами на ~35 % свободного пола, не на тропах и не на земле.
10. **Decor** — плотность авто-декора, его предельная высота и доля высокой травы на траве.
После шагов всё проходимое связывается со стартом (лишние препятствия убираются, замкнутые карманы становятся стеной). Новый шаг — класс-модуль `GenerationStep`; новый биом — новый рецепт.

### Обучение (Tutorial Script)
Внизу вкладки — поле **Tutorial Script**. Уровень, у которого оно заполнено, — **обучение игры**: Build / Sync записывает его в каталог отдельно от номерных уровней. В игре он запускается кнопкой **ОБУЧЕНИЕ** в главном меню (между «Играть» и «Настройки»), в прогрессии не участвует и рекламы перед ним нет. Обучение в игре одно, сейчас это `Data/Levels/Level_Tutorial` (тема Castle) со сценарием `Data/Levels/TutorialSteps.asset`.
- **Create Tutorial Script** создаёт сценарий рядом с уровнем, **Edit Steps** открывает его в инспекторе.
- **Шаг** — это текст и цель:
  - **Text** — ключ текста `tutorial.*` из `Data/Localization/Strings.tsv`, выбирается из списка. Необязательные варианты ключа: `<ключ>.touch` — для телефона, `<ключ>.hint` (и `<ключ>.hint.touch`) — короткая строка-напоминание вверху экрана, пока шаг не выполнен. Новый текст: добавить строки в таблицу → **Purge → Dev → Build Localization**.
  - **Dialog** — в начале шага показать окно с текстом, игра на паузе до «ПОНЯТНО» (Enter / пробел / Esc). Без галочки — только напоминание.
  - **Goal** — когда шаг выполнен: *Reach* — дойти до клетки цели (или до **Cell**, если цели нет); *Collect* — предмет цели подобран; *Unlock Door* — дверь отперта; *Open Door* — открыта; *Kill* — зомби убит; *Open Map* — открыта карта; *None* — шаг не завершается сам (последний).
  - **Target** — объект уровня из списка. На него указывает стрелка.
  - **Highlight** — какую кнопку обвести пульсирующим кольцом: стик, атака, «Действие», слоты оружия, карта. На ПК есть только слоты оружия и карта.
- Если шаг уже выполнен, когда до него дошла очередь (игрок забежал вперёд), он пропускается без окна.
- Валидатор проверяет сценарий: у шага есть текст, цель существует и подходит к Goal, клетка Reach — пол.

## 6. Вкладка Edit — инструменты

| Инструмент | Что делает |
|---|---|
| **Select** | Клик выбирает клетку и объект (повторный клик перебирает объекты в клетке). Перетаскивание двигает объект |
| **Wall / Floor** | Кисть: клик или протягивание. Пол поверх двери удаляет дверь |
| **Door** | Делает клетку дверью и создаёт объект двери |
| **Start / Medkit** | Ставит объект на клетку пола |
| **Key** | Ставит ключ. Чтобы ключ сразу привязался к двери, используйте кнопку в инспекторе двери (см. ниже) |
| **Zombie** | Ставит зомби. В опциях инструмента выберите **Zombie Definition** и **Facing** (куда смотрит) |
| **Weapon** | Ставит оружие. В опциях выберите **Weapon Definition** |
| **Decor** | Кисть декора (только на пол). В опциях: **Paint** — **Variant** (выбранный вариант и поворот; у высоких рядом пометка «by hand only»), **None** (здесь декора нет), **Automatic** (вернуть авторасстановку). ПКМ / протягивание ПКМ — убрать декор. Декор только визуальный: на проходимость, видимость, игрока и зомби не влияет |
| **Snowdrift** | Сугробы (только на пол, клик или протягивание; ПКМ — убрать). Геймплей: игрок и зомби в сугробе идут медленнее (`SnowdriftSpeed` в определениях игрока и зомби, по умолчанию 0.6), зомби обходят сугроб, если обход не длиннее ~2 лишних клеток (сугроб стоит 3 шага в A*). На схеме — бело-голубая клетка. Визуал: пол категории **Snowdrift** темы (у `SnowTheme` — снежный холм; белизна и мягкий неровный край без швов между соседними сугробами — шейдер, настройки в теме: Weather → Snowdrifts; в превью видны после **Build Preview**), в других темах — обычный пол; авто-декора на сугробе нет. Стена/дверь/Erase на клетке сугроб убирают |
| **Grass** | Трава (только на пол; ПКМ — убрать): поверхность `Grass` — огонь распространяется по ней. На схеме — светло-зелёная клетка. Визуал: декор категории **Grass** темы (высокая трава) с долей *Grass Decor Density*; обычного авто-декора на траве нет. Шаг **Grass** рецепта кладёт её сам |
| **Ground** | Земля (только на пол; ПКМ — убрать): поверхность `Ground` — без геймплея, шаги по земле. На схеме — коричневая клетка. Визуал: текстура земли темы (`VisualTheme.Ground`) с мягким неровным краем поверх пола; авто-декора нет. Шаг **Ground** рецепта кладёт её на тропы, поляны и старт |
| **Obstacle** | Препятствие на клетке пола (клик или протягивание; ПКМ — убрать). В опциях — **Obstacle** (ассет из `Data/Obstacles`) и что он блокирует. Что блокирует (движение / пули / обзор), замедление и горючесть задаются **в ассете**, не в префабе: дерево — движение и пули, куст — движение (горит), камень — всё. На клетку с объектом блокирующее препятствие не ставится. На схеме — квадрат в клетке (тёмно-зелёный — непроходимое, светлый — проходимое). Вид — вариант набора **Decor** темы, у которого **Definition** = это препятствие (выбирается как декор, по `VisualSeed`); нет такого варианта — препятствие невидимо, валидатор предупреждает (`ObstacleWithoutVisual`). Ручной декор на клетке препятствие снимает |
| **Spawn** | Точка появления монстров волн (значок **M**) на свободном полу; ПКМ — убрать. Клетку не занимает. Валидатор требует: дальше 10 клеток от старта, путь от старта и путь тела 3×3 до арены |
| **Arena** | Протянуть прямоугольник — свободные клетки арены босса. В опциях — **Ring** (ширина кольца, по умолчанию 2) и **Remove Arena**. Клетки кисть не меняет: кольцо рисуется стенами, проёмы в нём — входы (нужно ≥ 3 шириной ≥ 3). Арена с кольцом помечается ручной — **Generate** её сохранит |
| **Barrel** | Бочка (значок **B**), в опциях **Kind** — газ / огонь / кислота. Бочка занимает клетку, взрывается от урона игрока (Data/Objects, Build Level Objects) |
| **Chest** | Сундук (значок **C**), в опциях **Kind** — обычный / запертый / с испытанием. Сундук занимает клетку, открывается Use рядом; генератор ставит их шагом **Objects** |
| **Vehicle** | Машина (значок **V**, корпус подсвечен), в опциях **Definition** и **Heading** (8 направлений). Ставится, если корпус влезает на свободный пол; оставлять 8+ клеток прямого разгона. Генератор ставит лёгкую и тяжёлую шагом **Vehicles** |
| **Lock Area** | Протянуть прямоугольник — область блокировки (голубая): **Generate** её не трогает. ПКМ внутри — снять |
| **Erase** | Очищает клетку (клик или протягивание): удаляет объекты, источники света, сугроб, препятствие и декор (ставит «здесь нет декора»), стена, дверь и пустота (Void) становятся полом |

**Правила расстановки** (тулза не даст их нарушить):
- объекты ставятся только на пол;
- в одной клетке — один объект;
- исключение — зомби: их может быть несколько в клетке, и они могут стоять на предметах;
- зомби не может стоять на стартовой точке.

### Двери и ключи — строгое правило
- **Один ключ открывает ровно одну дверь** и после использования исчезает из инвентаря.
- Ключ только отпирает дверь. Открывает и закрывает её игрок отдельным действием, сколько угодно раз.
- **Ключ всегда того же цвета, что и его дверь.** Цвет подбирается автоматически:
  - запертая дверь получает цветной вариант;
  - разные пары по возможности получают разные цвета;
  - ключ берёт цвет своей двери;
  - дверь без ключа — нецветная.

Как связать ключ с дверью:
1. Выберите дверь (Select).
2. В инспекторе:
   - **Key** — выбрать существующий ключ. Если он был привязан к другой двери, он оттуда отвяжется;
   - или **Place a new key for this door** — следующий поставленный ключ сразу привяжется.
3. **Initially Open** — дверь в начале уровня открыта. **Strength** — сколько урона выдерживает от монстров, выбивающих двери (Громила, боссы); 0 — по умолчанию (60).
4. **Frozen** — мёрзлая дверь: пока лёд не разбит, её не открыть (сообщение «Frozen: break the ice…»). **Ice Hits** (1–10, по умолчанию 3) — сколько ударов **ближнего боя** нужно; пули лёд не берут. Каждый удар — звук двери, его слышат зомби. После последнего удара дверь обычная (закрыта; с ключом — ещё и заперта). Мёрзлая дверь всегда изначально закрыта: Frozen и Initially Open взаимоисключают друг друга. Лёд виден, если в теме есть **Weather → Ice Overlay** (у `SnowTheme` — есть; иначе валидатор предупреждает). На карте — голубая.

Если вручную поменять визуал двери (Override) на другой цвет, ключ перекрасится автоматически.

### Инспектор объекта
- **Id** — можно переименовать. Ссылки (дверь→ключ) и визуал обновляются автоматически.
- **Override** — ручной выбор визуального варианта и поворота.
- **Shift (X, Z) / Height / Turn** — только у подбираемых предметов (ключ, аптечка, оружие): сдвиг внутри клетки (до ±0.5), высота, поворот на любой угол — например, положить ключ на стол. Кнопки **X -0.25 / X +0.25 / Z -0.25 / Z +0.25** — сдвиг на четверть клетки. **Put on decor** — поднять на верх декора этой клетки (стол, бочка; над его центром, если предмет ещё не сдвигали) и **связать с ним**: сдвиг и поворот предмета двигают и декор (поворот — вокруг предмета), и наоборот (вместе с другими предметами на этом декоре); высота предмета декор не поднимает. У края клетки группа останавливается целиком, не разъезжаясь. **Detach** — развязать, оставив позу. **Reset placement** — обратно в центр на пол (связь снимается). То же — маркерами в Scene view (см. вкладку Visuals → Decor). Только визуал: предмет по-прежнему лежит в своей клетке и подбирается как обычно. Перенос предмета в другую клетку сбрасывает положение; выпавшее в игре оружие ложится на пол.
- **Delete** — удалить объект.

## 7. Вкладка Visuals

- **Theme** — визуальная тема уровня.
- **Visual Sets** — какие наборы входят в тему, только просмотр. Редактировать наборы — в Inspector самих ассетов.
- **Visual Seed** + **Regenerate Visuals** — заново раздать варианты по весам.
  - Геометрия, объекты, двери, ключи и зомби **не меняются**.
  - Ручные overrides **сохраняются**, если не включить **Also clear manual overrides**.
- **Lights** — источники света (факелы, лампы). Они только освещают: на проходимость, видимость и зомби не влияют. Стены и закрытые двери свет не пропускают.
  - **Density** — сколько источников ставит авторасстановка: 0 — ни одного, 0.5 — примерно через 6 клеток, 1 — через 3.
  - **Place Lights** — расставить заново. Источники ставятся у стен, как факелы, по **Visual Seed**; вид (цвет, радиус, мерцание) выбирается по весам из пресетов темы (theme asset → **Lighting → Light Presets**). Ручные источники сохраняются. То же происходит при **Regenerate Visuals**; с **Also clear manual overrides** удаляются и ручные.
    - **Подсказка у ключа:** у каждого ключа сначала ставятся 2 источника цвета ключа — у стен, не дальше 3 шагов от ключа по полу (свет в том же коридоре, не за стеной). Ставятся и при Density 0; остальные источники держатся от них на обычном расстоянии. Ключ без цветного визуала подсказки не получает.
  - **Add at Selected Cell** — добавить источник в выбранную клетку пола (сдвигается к соседней стене, если она есть).
  - **Light List** — цвет, радиус (**R**, клетки), яркость (**I**), мерцание (**F**), **светильник** (вариант из набора Light темы, «-» — вариант по умолчанию набора), удаление (**X**). Любая правка делает источник ручным: авторасстановка его больше не трогает. Источники выбранной клетки подсвечены в списке.
  - **Светильник** (факел на стене) — у каждого источника, рядом с которым есть стена: висит на грани стены, к которой сдвинут источник (иначе — на первой стене вокруг клетки), на высоте 0.95 м, пламя окрашено в цвет источника. Вариант выбирается по весам из набора **Light** темы при расстановке/добавлении и сохраняется в уровне. Источник посреди комнаты без стен рядом светильника не получает. В превью светильники видны и двигаются вместе с источником.
  - На сетке источник — цветная точка. В Scene view (удобно после **Build Preview**) источник — шарик, его можно перетаскивать по полу; бледный круг показывает радиус. Источник принадлежит клетке, в которой оказалась точка; если это не пол — валидатор покажет ошибку `LightNotOnFloor`.
- **Decor** — предметы на полу (мусор, лужи, ковры, бочки, столы…), по одному на клетку пола; в стенах и дверях декора нет. Чисто визуальный.
  - **Density** — доля клеток пола с декором при авторасстановке: 0 — нет, 1 — в каждой.
  - **Max Auto Height (m)** — предметы выше этого (по умолчанию 0.3 м) авторасстановка не ставит: игрок и зомби проходят сквозь декор, высокие предметы ставятся только вручную кистью **Decor** туда, где не мешают (тупики, углы). Высота модели измеряется по префабу автоматически.
  - **Place Decor** — расставить заново по **Visual Seed** (вариант по весам, поворот на четверть оборота). Ручной декор и «здесь нет декора» сохраняются. То же происходит при **Regenerate Visuals**; с **Also clear manual overrides** удаляется и ручной.
  - **В клетке с ключом автоматического декора не бывает** — иначе маленький ключ теряется в куче предметов. Когда ключ ставят или переносят в клетку, её авто-декор убирается, а в покинутую клетку возвращается. Декор, поставленный вручную, остаётся — если нужно, положите ключ на него (**Put on decor**).
  - Предмет стоит в центре клетки; крупный может выступать за её пределы.
  - **Положение — в Scene view** (после **Build Preview**): у каждого декора маленький кубик (бежевый — авто, зелёный — ручной), клик выделяет клетку. У декора выделенной клетки: **квадрат** — сдвинуть внутри клетки (рамка показывает её границы), **стрелка** — поднять/опустить, **круг** — повернуть на любой угол (с Ctrl — шагом 15°). Правка сразу пишется в уровень (Ctrl+Z работает), превью двигается само, Build Preview заново не нужен. Отредактированный авто-декор становится ручным — перегенерация его не трогает. Логически предмет остаётся в своей клетке (с ней и прячется туманом).
  - Так же в Scene view двигаются **подбираемые предметы** (ключи, аптечки, оружие, части карты): голубой кубик (зелёный — уже поставлен вручную), клик выделяет предмет, у выделенного — те же квадрат, стрелка и круг. Если в клетке выделен предмет, маркеры показываются у него, а у декора — только кубик.
- **Manual Overrides** — список ручных замен: клик по координате выделяет клетку, кнопка **Clear** удаляет замену.
- **Visual Distribution** — фактическое распределение вариантов против весов. Проценты считаются внутри категории. Небольшое расхождение нормально: клеток конечное число. Статистика пола включает пол под стенами.

**Ручная замена визуала клетки:** выберите клетку → в инспекторе **Floor override** или **Wall override** → выберите вариант. Пункт **(automatic)** убирает замену.

- Замена **пола** сохраняется при любой перерисовке клетки: пол есть всегда.
- Замена **стены** удаляется, когда клетка перестаёт быть стеной.
- **Декор** клетки удаляется, когда она становится стеной или дверью.

## 8. Вкладка Validate

Валидатор запускается **автоматически после каждого изменения**. Кнопка **Show** у проблемы выделяет её клетку на схеме.

| Уровень | Значение |
|---|---|
| **Error** | Уровень не готов. Надо исправить |
| **Warning** | Возможная проблема (недостижимое оружие, ненужный ключ, повтор цвета) |

**Частые ошибки:**

| Код | Что значит | Что делать |
|---|---|---|
| `InsideWall` | объект стоит в стене | передвинуть объект или нарисовать пол |
| `DoorCellWithoutDoor` | клетка-дверь без объекта двери | перерисовать кистью Door или Floor |
| `MissingKeyReference` | дверь ссылается на несуществующий ключ | выбрать ключ в инспекторе двери |
| `KeySharedByDoors` | один ключ у нескольких дверей | у каждой двери свой ключ |
| `KeyDoorColorMismatch` | цвет ключа ≠ цвет двери, или запертая дверь без цвета | убрать ручной Override или Regenerate Visuals |
| `KeyUnreachable` / `ObjectUnreachable` | из старта не дойти до ключа или предмета (с учётом ключей) | проверить стены, двери и расположение ключей |
| `Intersection` | несколько объектов в одной клетке | развести объекты |
| `MissingVisual` / `UnknownVariant` | у клетки или объекта нет визуала, или вариант удалён из набора | Regenerate Visuals или поправить Override |
| `WallCategoryWithoutVariants` | в наборе стен нет вариантов нужной формы (угол, Т и т.д.) | добавить вариант этой категории (раздел 10) |
| `StaleWallVisual` | форма стены изменилась, визуал устарел | Regenerate Visuals |
| `OverrideLayerMismatch` | ручная замена стены стоит на клетке, которая уже не стена (замена игнорируется) | убрать замену в Visuals → Manual Overrides |
| `BrokenPrefabReference` | у варианта нет префаба или он удалён из проекта | назначить префаб в наборе |
| `GeometryMeshNotReadable` | меш пола или стены без Read/Write — в игре его не будет | включить Read/Write в импорте модели |
| `GeometryShaderUnsupported` | материал пола или стены не на шейдере Purge/Geometry — туман войны не скроет эти клетки | переключить материал на Purge/Geometry |
| `NoVisualTheme` / `MissingVisualSet` | нет темы или нужного набора | назначить тему, заполнить набор |
| `LevelDisconnected` | проходимая область отрезана от старта (двери считаются проходом) | прорубить проход или закрыть область стеной |
| `ArenaTooSmall` | в арене нет свободного квадрата 14×14 | убрать препятствия/стены из арены |
| `ArenaFewEntries` | меньше 3 входов шириной ≥ 3 через кольцо арены | расширить или добавить проёмы (на схеме узкие — оранжевые) |
| `SpawnInStartView` | точка появления в 10 клетках от старта — монстры появятся на глазах | отнести точку дальше |
| `SpawnUnreachable` / `SpawnNoBodyPath` | до точки нет пути от старта / крупному телу 3×3 не пройти от точки до арены | расширить проходы до 3 клеток |
| `ObstacleBudget` (предупреждение) | в чанке 8×8 препятствий больше доли рецепта (35 %) | проредить препятствия |

## 9. Build Preview и Build / Sync

- **Build Preview** — строит уровень из настоящих префабов в открытой сцене, в объекте `[Purge Level Preview]`. Это только просмотр: объект не сохраняется со сценой. **Clear Preview** убирает его.
  - Превью — снимок на момент нажатия. Сам уровень после правок кистью обновляется сразу, в том числе его визуал. Чтобы увидеть изменения в сцене, нажмите **Build Preview** ещё раз: старое превью заменится новым. Ничего перегенерировать не нужно.
- **Build / Sync** — фиксирует уровень для игры:
  1. запускает валидацию (при ошибках спросит, продолжать ли);
  2. делает уровень Addressable с адресом `Levels/<имя уровня>` в группе **Purge Levels**;
  3. делает Addressable все префабы темы, которых ещё нет в Addressables, в группе **Purge Visuals**;
  4. добавляет уровень в **каталог уровней** `Data/Levels/LevelCatalog.asset` (если каталога нет, создаёт его) или обновляет в нём адрес и название уровня;
  5. делает Addressable общие для всех уровней ассеты игрока (`PlayerDefinition`, `PlayerVisual` и его префаб) в группе **Purge Shared**. Если их нет, в консоли будет предупреждение: без игрока уровень в игре не запустится;
  6. сохраняет ассеты.

  **Никакой новой рандомизации Build / Sync не делает.**

- **Play / Test from Start** (справа на верхней панели):
  - **Play** — проверяет уровень, делает Build / Sync, входит в Play Mode со сцены Bootstrap (какие бы сцены ни были открыты) и сразу запускает этот уровень, минуя меню; старт случайный, как в игре;
  - **Test from Start ▾** — то же, но со стартовой точки, выбранной в списке (`Start #0`, `#1`, … — порядок, в котором старты лежат в уровне). Та же кнопка **Test from Start #N** есть в инспекторе выбранного старта;
  - уровень с ошибками валидации не запускается — сначала вкладка Validate;
  - «Play again» повторяет уровень с того же старта, «Main menu» ведёт в обычное меню. После остановки Play обычная кнопка Play Unity снова запускает открытые сцены.
- **Обучение** — уровень с заполненным *Tutorial Script* (вкладка Generation): Build / Sync ставит его в каталог на место обучения, а не в номерные уровни. Без сценария он возвращается в конец номерных.
- **Dev** (кнопка-переключатель в тулбаре, слева от Build / Sync) — уровень для разработки: попадает не в каталог игры, а в `DevLevelCatalog` и группу *Purge Dev Levels*. В игре такие уровни видны только в редакторе и dev-сборке — на отдельной странице «DEV» выбора уровней, без номера и прогрессии; в release-сборку не попадают. Повторное нажатие возвращает уровень в игру (в конец каталога).
- **Каталог уровней** — список уровней в главном меню игры. Уровень появляется в меню только после Build / Sync. В игре уровень называется по номеру в каталоге («LEVEL 3», «УРОВЕНЬ 3» — по языку); **Display Name** (поле *Settings → Display Name*) — только для разработки, игроку не показывается. Порядок уровней и удаление лишних — в инспекторе `LevelCatalog.asset`.
- Если игра не может загрузить уровень (например, в нём есть ошибки валидации), она показывает экран ошибки с причиной и возвращает в меню. Уровень с ошибками в игру не попадёт, даже если Sync сделан через «Sync Anyway».
- **Игрок** один на все уровни: `Data/Player/PlayerDefinition` (скорость, размер «тела» для столкновений со стенами, сила помощи на поворотах, HP) и `Data/Player/PlayerVisual` (префаб). Префаб игрока: pivot у ног, смотрит на +Z, без коллайдеров. Если в нём есть Animator с float-параметром **Speed**, игра передаёт туда скорость 0..1. При нескольких стартовых точках игра выбирает случайную при каждом запуске уровня.
- **Управление в игре:** WASD или стрелки — движение; Esc — пауза; E — действие (подобрать оружие, отпереть / открыть / закрыть дверь); 1 / 2 — ближнее / дальнее оружие; M или Tab — карта (закрыть — снова M, Esc или «Close»); ЛКМ или пробел — атака в сторону взгляда (удержание повторяет удар и автоматический огонь). На телефоне — экранный стик слева и кнопки справа: **Use** = действие (подобрать оружие, дверь), Melee / Ranged — переключить оружие, Attack — атака; карта и пауза — кнопки вверху. Встав на оружие, игрок видит подсказку «press Use (E) to pick up». Игра только в альбомной ориентации.
- **Как предметы ведут себя в игре** (учитывайте при расстановке):
  - **ключ** подбирается сам, когда игрок входит в клетку;
  - **запертая дверь**: E рядом с ней при нужном ключе только отпирает её (ключ тратится), открывает следующее нажатие E. Без ключа игрок видит сообщение, какой ключ нужен. Дверь без ключа открывается и закрывается по E. Закрыть дверь нельзя, если в проёме стоит игрок или зомби;
  - **аптечка** срабатывает при входе в клетку, только если HP не полный: лечит до полного и исчезает. При полном HP остаётся лежать;
  - **оружие** подбирается по E, когда игрок стоит в его клетке, и сразу становится активным. Если слот (ближнее / дальнее) уже занят, старое оружие выпадает в эту клетку. В начале уровня у игрока оружия нет;
  - закрытая дверь загораживает обзор — за ней ничего не видно.
- **Зомби в игре** (параметры — в ассете ZombieDefinition, поле **Detection Type**):
  - **Vision Only** — видит игрока в секторе **Vision Angle** перед собой на расстоянии **Vision Range**; стены и закрытые двери загораживают;
  - **Hearing Only** — реагирует на звуки (шаги, выстрелы, удары, двери, подбор) в пределах **Hearing Radius**, но не дальше, чем слышен сам звук (громкость задана у оружия и у игрока);
  - **Vision And Hearing** — замечает игрока в радиусе **Detection Radius**, стены не мешают;
  - заметив, идёт к месту, где видел/слышал игрока; потеряв — возвращается на свою клетку и смотрит в исходную сторону (патрулей нет);
  - если игрок в соседней клетке (по стороне), бьёт: **Damage** раз в **Attack Interval** секунд; **Move Speed** — клеток в секунду, **Max Hp** — здоровье;
  - двери не открывают: закрытая дверь — стена для них; в клетку игрока не заходят, друг через друга проходят;
  - урон от игрока, который зомби не заметил, не заставляет его реагировать;
  - заглушки трёх типов: **Purge → Dev → Create Placeholder Zombies** (`Data/Zombies`).
- **Смерть игрока** (HP 0) — уровень проигран, на экране «Play again» и «Main menu».
- **Победа** (временно, до волн) — убит последний зомби уровня. Уровень без зомби так не завершается.
- **Дев-уровень `Level_Items`** — копия Level_Dev с дверями, ключом, аптечкой, оружием и тремя зомби рядом со стартом, чтобы быстро проверить предметы. Это не игровой контент: его можно удалить (и из `LevelCatalog`).

## 10. Как добавить новый визуал (префаб)

### Требования к префабу
- **Размер:** одна клетка = **1×1 метр**. Центр клетки — это pivot префаба (0, 0, 0), пол на высоте Y = 0.
- **Без коллайдеров и Rigidbody.** Физика в проекте не используется.
- **Префаб стены — без пола.** Пол под стеной ставится отдельно, из набора пола. Если встроить пол в стену, два пола наложатся и будут мерцать (z-fighting). Низ стены — на Y = 0.
- **Префаб пола занимает всю клетку 1×1**, верхняя грань на Y = 0.
- **Никакой игровой логики в префабе.** Проходимость и прочее задаёт тип клетки.
- **Пол и стены — особые требования.** В игре их меши склеиваются в крупные куски (чанки 8×8 клеток), а туман войны прячет отдельные клетки прямо в шейдере. Поэтому для префабов **пола и стен**:
  - все материалы — на шейдере **Purge/Geometry** (как Standard: цвет, текстура, карта нормалей, metallic/smoothness, emission). Материал на другом шейдере покажется, но туман войны не сможет скрыть его клетки (`GeometryShaderUnsupported`);
  - у импортированных моделей включён **Read/Write** (Model → Read/Write в настройках импорта), иначе меш не попадёт в игру (`GeometryMeshNotReadable`). Встроенные примитивы Unity подходят как есть;
  - только MeshFilter + MeshRenderer. Свет, частицы, анимированные (skinned) меши в префабе пола или стены игра пропустит (`GeometryUnsupportedRenderer`). Если нужны — это отдельный объект, не геометрия клетки.
  - Двери, предметы и зомби — обычные префабы. Чтобы их освещали фонарь игрока и источники света, материалы должны быть на шейдере **Purge/Lit** (свойства как у Standard). Непрозрачные Standard-материалы переводит меню **Purge → Dev → Convert Object Materials to Purge Lit** — запускайте его после добавления новых моделей.
- **Ориентация.** Префаб делается в «канонической» ориентации. Тулза сама повернёт его на 0/90/180/270° по соседям:

| Категория стены | Префаб соединяется с соседями | Пример |
|---|---|---|
| `Isolated` | ни с кем (одиночная колонна) | `wall_isolated` |
| `End` | только **север** (+Z) | тупиковый конец стены |
| `Straight` | **север + юг** | прямая стена вдоль оси Z |
| `Corner` | **север + восток** (+Z и +X) | угол |
| `TJunction` | **север + восток + юг** | Т-образное соединение |
| `Cross` | все четыре стороны | крест |
| `Special` | — | **никогда не ставится автоматически**, только вручную через Override |

- **Дверь** при повороте 0 перекрывает проход **север–юг**: полотно двери вытянуто вдоль оси X.
  - Чтобы дверь показывала состояния, добавьте на корень префаба компонент **Door Visual** и укажите в нём дочерние объекты: **Closed** (видна, пока дверь закрыта), **Open** (пока открыта, например полотно, прижатое к стене), **Locked** (пока заперта, например замок). Любое поле можно оставить пустым. Вместо объектов (или вместе с ними) можно указать **Animator** с bool-параметрами `Open` и `Locked`.
  - Без компонента Door Visual открытая дверь просто исчезает (прячутся её рендереры).
  - Не выключайте и не включайте сам корень префаба из своих скриптов — им управляет туман войны.
- **Остальные предметы** (ключ, аптечка, оружие, зомби) не поворачиваются автоматически.

Для образца откройте префабы в `Assets/_Project/Art/Placeholders/`.

### Шаги
1. Положите префаб в проект, например в `Assets/_Project/Art/...`.
2. Откройте нужный **VisualSet** в `Assets/_Project/Data/Themes/` (например, `PlaceholderWallSet`).
3. В списке **Variants** добавьте элемент и заполните:

| Поле | Что указать |
|---|---|
| **Id** | уникальное имя варианта (`wall_straight_03`). Это имя сохраняется в уровнях, **не переименовывайте его после использования** |
| **Prefab** | ваш префаб |
| **Weight** | вес при автоматическом выборе (подробнее ниже). **0** = только вручную |
| **Category** | для стен — форма (раздел выше); для остального — `General` |
| **Definition** | необязательно: вариант только для конкретного `WeaponDefinition` / `ZombieDefinition`. Например, модель дробовика только для дробовика |
| **Color Tag** | только для дверей и ключей: `red`, `blue`, `green`, `yellow`, `orange`, `cyan`, `purple`, `pink` (или `#RRGGBB`; цвета имён — `VisualColors`; для нового имени нужна строка `hud.locked.<имя>` в `Strings.tsv`). Должен **совпадать** у двери и ключа одной пары. У нецветной двери поле пустое |

4. **Default Variant Id** набора — запасной вариант, если для формы стены нет ни одного варианта. Лучше указать; без него будет ошибка.
5. Чтобы новый вариант появился на **уже сделанных** уровнях, есть два способа:
   - **Regenerate Visuals** — перераздаёт все варианты по весам, ручные замены сохраняются;
   - или поставьте вариант точечно через **Override** в инспекторе клетки или объекта.

   На уже готовых уровнях **ничего не меняется само**: так задумано.
6. **Build / Sync** — новый префаб станет Addressable.

### Как работают веса
Вес — это относительная вероятность **внутри одной категории**. Пол под стенами выбирается по тем же весам, что и обычный пол. Пример для набора пола:
```
floor_01  Weight 80   →  ~80% клеток пола
floor_02  Weight 10   →  ~10%
floor_03  Weight 10   →  ~10%
floor_blood Weight 0  →  только вручную
```
- Для стен веса сравниваются только между вариантами одной формы: два `Straight` с весами 80/20 делят прямые стены 80/20.
- Сумма весов не обязана быть 100.
- Веса используются **только** при Generate New и Regenerate Visuals. В игре они не участвуют.

### Новая тема
Готовые темы-биомы **SnowTheme** (снег) и **ForestTheme** (лес) делает меню **Purge → Dev → Build Biome Themes** — свои пол и стены, остальное общее с замком. Своя тема проще всего — копией существующей (Ctrl+D на ассете темы) с заменой наборов Floor / Wall. С нуля:
1. **Create → Purge → Visual → Visual Theme**.
2. Для каждого вида создайте набор: **Create → Purge → Visual → Visual Set**. Поле **Kind** набора должно совпадать со слотом темы: Floor, Wall, Door, Key, Medkit, Weapon, Zombie, Decor, Light.
3. Назначьте наборы в слоты темы.
4. Необязательно: поле **Fog Material** — материал тумана войны (шейдер `Purge/Fog`). Пусто — тумана нет, скрытые клетки просто не рисуются.
5. В уровне: вкладка **Visuals** → **Theme** → **Regenerate Visuals**.

### Туман войны
Скрытые клетки затянуты анимированной дымкой. Её вид задаёт материал `Assets/_Project/Art/Fog/Fog.mat` (назначен в `PlaceholderTheme`, пересоздать — **Purge → Dev → Create Placeholder Fog**; уже настроенный материал при этом не перезаписывается). Параметры материала, их можно менять прямо во время Play:

| Параметр | Что делает |
|---|---|
| Noise | бесшовная текстура шума (серая, канал R) |
| Fog Color / Wisp Color | цвет дымки и светлых прядей |
| Density | плотность (1 — за туманом ничего не видно) |
| Wisp Strength | насколько заметны пряди |
| Noise Scale | размер «облаков» для двух слоёв (меньше — крупнее) |
| Flow Layer 1 / 2 | скорость и направление дрейфа слоёв, клеток в секунду |
| Edge Blur Radius | ширина размытия края, клетки (больше — расплывчатее граница) |
| Edge Softness / Edge Offset | мягкость края и его сдвиг: «+» — в сторону скрытых клеток, «−» — заходит на видимые |
| Fade Time | за сколько секунд туман рассеивается или сгущается при смене видимости |
| Plane Height | высота плоскости тумана над полом |

Туман рисуется поверх всего (без проверки глубины): мягкий край затягивает и стены на границе видимой зоны, поэтому граница не обрезана. Клетки, уходящие из видимости, исчезают только когда туман их полностью затянул.

Туман — только картинка: видимость объектов, AI и Level Designer от него не зависят.

### Свет и тени
Теней в реальном времени нет (дорого на телефонах и в браузере). Настроение задаётся в ассете темы, раздел **Lighting** (можно менять во время Play, применяется при следующей загрузке уровня):

| Параметр | Что делает |
|---|---|
| Ambient | общий фоновый свет — базовая яркость всего |
| Moon Color / Moon Intensity | слабый направленный свет без теней: даёт объём стенам и персонажам |
| Lantern Color / Intensity / Radius / Height | мягкий свет вокруг игрока |
| Light Fade Start / Fade Length / Top Share | свет источников на полу и стенах «прижат к полу»: полный до высоты Fade Start, дальше за Fade Length спадает до доли Top Share. Стены высотой 1.5, поэтому их верх почти не освещён. Персонажей и предметы это не касается |
| Blob Shadow Material / Size | мягкое круглое пятно под игроком и зомби (материал `Art/Lighting/BlobShadow.mat`) |
| Light Presets | виды источников для авторасстановки: id, вес, цвет, радиус, яркость, мерцание |

Материал пятна и пресеты по умолчанию (факел и холодная лампа) создаёт меню **Purge → Dev → Create Placeholder Lighting** (уже настроенное не перезаписывает).

### Новое оружие или тип зомби
- **Create → Purge → Definitions → Weapon** / **Zombie** — игровые параметры (урон, магазин, радиус обнаружения и т.д.). Поле **Slot** у оружия — Melee (ближнее) или Ranged (дальнее).
- Параметры оружия:
  - общие: **Damage** (урон), **Sound Radius** (на сколько клеток удар/выстрел слышат зомби);
  - ближнее: **Attack Speed** (ударов в секунду), **Melee Range** (дальность до края цели, клетки), **Melee Arc** (ширина сектора перед игроком, градусы) — удар задевает всех в секторе, но не через стену или закрытую дверь;
  - дальнее: **Fire Interval** (секунд между выстрелами), **Magazine Size**, **Reload Time** (перезарядка автоматическая, когда магазин пуст; патроны бесконечны), **Fire Mode** (Single — выстрел на нажатие, Automatic — пока кнопка зажата), **Projectile Speed** (клеток в секунду). Пуля пролетает открытые двери и останавливается о стену, закрытую дверь или цель.
- Эффекты боя общие для всех уровней: `Data/Combat/CombatVisual` — трассер, вспышка у дула, гильза, попадание в стену, попадание в зомби, взмах ближнего боя, цвета вспышки модели при уроне (префабы смотрят вдоль +Z, без коллайдеров). Свои эффекты собирает **Purge → Dev → Build Combat Effects** (`Art/Effects`), подробности — в [Prefabs.md](Prefabs.md).
- Зоны зрения зомби и волны шума настраиваются в теме (**Awareness**): цвета покоя и тревоги, прозрачность заливки и кромки, гладкость (шаг лучей), цвет и время волн. Материалы собирает **Purge → Dev → Build Awareness Visuals**; пустой материал выключает зоны (или волны). Зона показывает ровно то, что проверяет игра: у зомби «зрение» — конус Vision Angle / Vision Range, у «зрение + слух» — круг Detection Radius; стены и закрытые двери её обрезают.
- Следы игрока и зомби настраиваются в теме (**Footprints**): материал отпечатков и пыли, частота шагов, размер, цвет, на каком расстоянии и через сколько секунд отпечаток гаснет. Материалы и атлас собирает **Purge → Dev → Build Footprints**; пустой материал выключает отпечатки (или пыль).
- Для проверок есть заглушки: **Purge → Dev → Create Placeholder Weapons** создаёт в `Data/Weapons` нож и биту (ближнее) и пистолет (дальнее). Существующие ассеты не перезаписываются.
- Визуал задаётся отдельно, вариантами в Weapon Set / Zombie Set. Чтобы модель была только у этого оружия или зомби, укажите поле **Definition** у варианта.

## 11. Частые вопросы

**Поменял Visual Seed — ничего не изменилось.**
Так и задумано. Нажмите **Regenerate Visuals**.

**Нажал Regenerate Visuals — пропали мои ручные замены?**
Нет, если не была включена галочка **Also clear manual overrides**.

**Поменял стену на пол — соседние стены поменяли вид.**
Форма соседних стен изменилась (была прямая, стала угловая), поэтому им подобран вариант новой формы. Остальной уровень не трогается. Пол на месте убранной стены остаётся тем же, что был под ней.

**Между стеной и полом видна пустота.**
Значит, у клетки-стены нет пола: в наборе пола нет ни одного варианта с весом больше 0, или уровень сделан до появления слоя пола. Нажмите **Regenerate Visuals**.

**Двигаю стены рядом с дверью — дверь не меняет цвет?**
Правильно: при правке геометрии у объектов меняется только поворот, вариант остаётся.

**Ключ и дверь разного цвета.**
Скорее всего, на ключ или дверь поставлен ручной Override. Уберите его — пункт **(automatic)**.

**Что игрок видит в игре?**
Только квадрат 11×11 клеток вокруг себя (5 клеток в каждую сторону), и только то, что не загорожено стенами и **закрытыми** дверями; открытая дверь не мешает. Всё остальное — пол, стены, двери, предметы, зомби — скрыто. При планировке учитывайте: длинный прямой коридор просматривается на 5 клеток, вход в боковой проход виден заранее, а что за поворотом — нет. Сквозь щель между двумя стенами, касающимися углами, не видно.

**Нажал Play / Test from Start, ничего не произошло.**
Смотрите сообщение в окне и консоли: у уровня ошибки валидации, Unity уже в Play Mode или нет сцены Bootstrap (**Purge → Dev → Build Runtime Scenes**).

## Этажи и пустота (этап 3)
- У уровня может быть несколько **этажей** одного размера (`LevelGeometry.FloorCount`); клетка — `(x, y, этаж)`. Добавить/убрать верхний этаж — `LevelEditing.AddFloor/RemoveTopFloor` (кнопок в тулзе пока нет — придут с шагом «Здание» генератора, этап 13а). Схема и превью показывают этаж 0.
- Клетка **Void** — «нет земли» (часть верхнего этажа вне здания): не проходима, пули и обзор проходят, не рисуется. Новый этаж создаётся целиком из Void. Валидатор: клетка верхнего этажа над Void нижнего — `FloorOverhang`.
