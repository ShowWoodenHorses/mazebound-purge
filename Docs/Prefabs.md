# Список префабов

Какие префабы нужны игре, сколько видов каждого и какие у них требования. Сейчас все они — заглушки из примитивов (`Art/Placeholders`), созданные меню **Maze → Dev → Create Placeholder …**. Финальные префабы подключаются в тот же слот: вариант в Visual Set темы или поле в definition-ассете.

## Сводка

| Что | Где подключается | Минимум | Сейчас (заглушки) | Рекомендуется |
|---|---|---|---|---|
| Пол | Theme → Floor Set | 1 | 3 + 1 Special | 3–4 вариации + Special по желанию |
| Стены | Theme → Wall Set | **6** (по одной на категорию) | 7 | 6 категорий, у Straight 2–3 вариации |
| Двери | Theme → Door Set | 1 + 1 на каждый цвет ключа | 9 (обычная + 8 цветов) | 1–2 обычных + 8 цветных |
| Ключи | Theme → Key Set | 1 на каждый цвет | 8 (red, blue, green, yellow, orange, cyan, purple, pink) | 8 |
| Выход | Theme → Exit Set | 1 | CastleBlock: 2 лестницы (`Art/Exit`); заглушка — 1 | 1–2 |
| Аптечка | Theme → Medkit Set | 1 | 1 | 1 |
| Оружие на полу | Theme → Weapon Set | 1 на каждое оружие | 1 общий | 3 (нож, бита, пистолет) |
| Зомби | Theme → Zombie Set | 1 на тип | 2 общих | 3 типа × 1–3 вариации |
| Фрагмент карты | Theme → MapFragment Set | 1 | 1 | 1 |
| Декор | Theme → Decor Set | 0 | 18 (Synty, `Art/Decor`) | низкие для авторасстановки + высокие для ручной |
| Светильник (факел) | Theme → Light Set | 0 | 2 (`Art/Lighting`) | 1–3 |
| Игрок | `Data/Player/PlayerVisual` | 1 | 1 | 1 |
| Пуля (трассер) | `Data/Combat/CombatVisual` → Bullet | 0–1 | 1 | 1 |
| Вспышка у дула | `CombatVisual` → Muzzle Flash | 0–1 | 1 | 1 |
| Гильза | `CombatVisual` → Shell Casing | 0–1 | 1 | 1 |
| Попадание в стену | `CombatVisual` → Impact | 0–1 | 1 | 1 |
| Попадание в зомби | `CombatVisual` → Target Hit | 0–1 | 1 | 1 |
| Взмах ближнего боя | `CombatVisual` → Melee Swing | 0–1 | 1 | 1 |

**Итого минимум ≈ 29 префабов:** пол 1, стены 6, двери 5, ключи 4, выход 1, аптечка 1, оружие 3, зомби 3, фрагмент 1, игрок 1, эффекты 6 (свои уже есть — **Maze → Dev → Build Combat Effects**). С вариациями получается 40–50.

## Подробно

### Пол (Floor)
- Одна клетка 1×1 м, пивот в центре клетки на уровне пола (y = 0).
- Пол есть **под каждой клеткой**, в том числе под стенами.

Сугробы — варианты пола категории **Snowdrift** (только для клеток-сугробов): блок пола с холмом, край клетки ровный на высоте 0 (без швов с соседями), холм не выше ~0.2 м. У `SnowTheme` — 3 (**Build Biome Themes**).

### Стены (Wall)
Категория выбирается по соседям-стенам, поворот подставляется автоматически. Префаб делается в **канонической ориентации** (сверху, North = +Z):

| Категория | Соседи-стены в префабе |
|---|---|
| Isolated | нет |
| End | N |
| Straight | N + S |
| Corner | N + E |
| TJunction | N + E + S |
| Cross | N + E + S + W |
| Special | любые, ставится только вручную |

- **Без пола** внутри: пол рисуется отдельным слоем.
- Высота у заглушек 1.5 м. Камера смотрит почти сверху, поэтому важнее верхняя грань.

### Требования к полу, стенам и декору (проверяет валидатор)
- Материалы на шейдере **`Maze/Geometry`**: на нём работает туман войны по клеткам.
- Меши с включённым **Read/Write**.
- Только MeshFilter + MeshRenderer, без скриптов, коллайдеров и анимаций.

### Декор (Decor)
- Необязательный предмет на клетке пола, склеивается в меши вместе с полом и стенами — **требования как у пола и стен** (ниже) + без теней.
- Пивот в центре клетки на уровне пола; предмет по возможности в пределах клетки (1×1 м). Плоские (лужи, листы) — чуть выше пола, иначе мерцают.
- Положение (сдвиг до ±0.5 клетки, высота, поворот на любой угол) дизайнер задаёт в Level Designer — сам префаб в центре клетки.
- Вариант с высотой больше **Max Auto Height** уровня (по умолчанию 0.3 м) ставится только вручную. Высоту меряет редактор.
- Модели из `Art/Decor` готовит **Maze → Dev → Build Decor**: копии материалов на `Maze/Geometry` (`Art/Decor/Materials`), Read/Write у моделей, масштаб под клетку (кроме тел — они в натуральную величину), подъём плоских, набор `Data/Themes/PlaceholderDecorSet` в теме. Новую модель: положить префаб в `Art/Decor` и запустить меню.

### Выход (Exit)
- Лестницы вверх `Art/Exit`, готовит **Maze → Dev → Build Exits** (`LevelPropsBuilder`): без коллайдеров и теней, материалы на `Maze/Lit`, модель — в дочернем `Model`, задней стороной к стене на −Z (−0.5 + 2 см); набор `CastleBlockExitSet` в теме CastleBlock.
- Выход повёрнут к открытой стороне, за которой стена (в тупике — к коридору), поэтому лестница стоит у стены. Без такой стороны — к первой открытой.

### Светильники (Light)
- Факелы `Art/Lighting`, готовит **Maze → Dev → Build Light Fixtures** (`LevelPropsBuilder`): без коллайдеров и теней, `Maze/Lit`, дочерний `Flame` — простое мультяшное пламя (мягкие аддитивные пятна поднимаются и уменьшаются + редкие искры, материал `Art/Effects/fx_additive`, looping + prewarm) над верхом головки, компонент `TorchFlame` (окраска в цвет источника). Набор `CastleBlockLightSet` в обеих темах.
- Ориентация модели: крепление в начале координат, стена сзади (−Z), факел смотрит на +Z. Ставится в точку источника на грань стены (`LightFixtures`).

### Двери (Door)
- Поворот 0 перекрывает проход Север–Юг.
- **Обычная дверь — без ColorTag. Запертая — с ColorTag**, совпадающим с цветом ключа (`red`, `blue`, …).
- Состояния показывает компонент **`DoorVisual`** на корне: дочерние объекты `Closed`, `Open`, `Lock` (замок у запертой) и/или Animator с bool `Open` и `Locked`. Без компонента открытая дверь просто прячется.

**Лёд мёрзлой двери** — не вариант набора, а `VisualTheme → Weather → Ice Overlay` (Addressable, Build/Sync добавляет в Maze Visuals): кладётся дочерним на вьюху двери в той же ориентации (поворот 0 — поперёк прохода С–Ю, pivot — центр клетки на полу). Необязательный компонент `FrozenDoorIce` с глыбами по порядку откалывания. Сейчас — `Art/Effects/IceOverlay.prefab` (**Maze → Dev → Build Weather**).

### Ключи (Key)
- По одному на цвет, `ColorTag` как у двери. Сколько цветов, столько возможно одновременно разных пар на уровне.

### Оружие (Weapon)
- **Модель** (Synty): пивот у рукояти, ствол или лезвие по **+Z**, верх **+Y**, без коллайдеров. Сейчас 10 моделей в `Art/Weapons` (4 ближнего боя, 3 автомата, 3 одиночных).
- **Maze → Dev → Build Weapons** (`WeaponsBuilder`) делает из моделей всё остальное:
  - `WeaponDefinition` на модель в `Data/Weapons` (у нового — черновые характеристики, у существующего значения не трогаются);
  - **в руках** — сама модель + `WeaponModel` с меткой `Muzzle` (огнестрел) или `Tip` (ближний бой) на дальнем конце и, у огнестрела, `Grip_L` — где левая ладонь держит цевьё (считается по позе выстрела; при ручной правке её перезапишет Build Weapons); связь «определение → модель» — `Data/Weapons/WeaponVisuals` (`WeaponVisualCatalog`, Addressable "Weapons/Visual");
  - **на полу** — `Art/Weapons/Pickups/<модель>_Pickup`: та же модель **лежит боком** (сверху виден силуэт), по диагонали клетки, на полу, масштаб как в руках; в Weapon Set темы — вариант на каждое определение (`weapon_<id>`), визуал оружия в уровнях переназначается;
  - на префабе игрока — `CharacterWeaponRig`: `WeaponSocket_Melee` в правой кисти и `Palm_R`/`Palm_L` (центры ладоней).
- **Новое оружие:** префаб модели в `Art/Weapons/Melee` (ближнее), `Art/Weapons/Rifle/Auto` (автомат) или `Art/Weapons/Rifle` (одиночный) → меню; определение `Data/Weapons/<имя без SM_Wep_>` создаётся с черновыми статами по виду (подробно — [MazeMenu.md](MazeMenu.md)). Ближний бой держится в руке как меч (анимации sword), огнестрел — двумя руками как винтовка (анимации rifle).

### Зомби (Zombie)
- В варианте заполнить **Definition** ссылкой на `ZombieDefinition` (Walker, Listener, Hunter), чтобы тип был виден.
- Лицом по **+Z**, пивот у ног.
- Сейчас — `Art/Zombie/Zombie_01..03` (Synty, Humanoid; одна модель, разные материалы): Walker, Listener, Hunter. Собираются меню **Maze → Dev → Build Zombie Animations**: клипы `Art/Animations/Zombie_*` → Humanoid, общий контроллер `Art/Zombie/Zombie.controller` на все префабы папки, масштаб 0.75, варианты Zombie Set темы (`zombie_walker/listener/hunter` с Definition) и переназначение зомби в сохранённых уровнях. Новый вид — префаб в `Art/Zombie` → меню; тип ставится автоматически (с предупреждением), проверить `Definition` варианта в наборе — дальше билдер его сохраняет.
- Animator (необязательно, любой параметр можно опустить; имена — `ZombieAnimatorParameters`): float `Speed`, bool `Chasing` (бег вместо ходьбы), bool `Alert` (рык перед погоней), `WalkPlayback`/`RunPlayback` (множители, ставит презентер) и `WalkGroundSpeed`/`RunGroundSpeed` (данные билдера: скорость ступни клипа), float `IdleVariant` (0/1), триггер `Attack` + int `AttackIndex` + float `AttackSpeed`, триггер `Hit` (клипа нет), bool `Dead`.

### Игрок
- Лицом по **+Z**, пивот у ног.
- Сейчас — модель `Art/Player/SM_Chr_Hunter_Male_01` (Synty, Humanoid) с клипами Mixamo `Art/Animations/Player_*`. Модель игрока для билдеров — единственный префаб прямо в `Art/Player` (сменить модель = заменить префаб в папке). Собирается меню **Maze → Dev → Build Player Animations**: клипы → Humanoid, контроллер `Art/Player/Player.controller`, маска `PlayerUpperBody`, масштаб модели 0.75, назначение в `PlayerVisual`. Шаг бега подгоняется под скорость, но не быстрее 1.4× (`LocomotionAnimation`).
- Animator (необязательно, любой параметр можно опустить; имена — `PlayerAnimatorParameters`): float `Speed`, int `Weapon` (0 нет, 1 ближнее, 2 дальнее), триггеры `Attack` + int `AttackIndex` + float `AttackSpeed`, `Shoot` + bool `Automatic`, bool `Reloading` + float `ReloadSpeed`, триггеры `Hit`, `Use`, bool `Dead`; слой `UpperBody` выключается при смерти.

### Эффекты боя
Свои эффекты в мультяшном стиле (без крови, без следов от пуль) собирает **Maze → Dev → Build Combat Effects** в `Art/Effects` и назначает в `CombatVisual`. Пак можно подставить в те же слоты; любой слот можно оставить пустым.
- Все смотрят вдоль **+Z**, берутся из пула, показываются только в видимых клетках. Системы частиц перезапускаются при каждом показе; модуль Collision выключен (без физики). Компонент `CombatEffect` на корне задаёт длительность (без него — `EffectDuration`).
- **Bullet (трассер):** пивот у «головы»; при `Tracer Length` > 0 модель длиной 1 позади пивота (−Z), растягивается до видимой длины. Вылетает из дула и за 1.5 клетки сходится с линией пули.
- **Muzzle Flash:** в точке `Muzzle` оружия вдоль ствола. **Shell Casing:** из оружия, +Z — вправо от ствола.
- **Impact:** +Z — наружу из стены. **Target Hit:** +Z — к атакующему. **Melee Swing:** компонент `SwingArc` подгоняет дугу под `MeleeArc`/`MeleeRange` оружия.
- Вспышка модели при уроне — свойство `_HitFlash` шейдера `Maze/Lit` (цвета и время — в `CombatVisual`), моделям ничего не нужно.

### Общее для всех префабов
- **Никакой физики:** ни Collider, ни Rigidbody.
- Никаких геймплейных скриптов: префаб только показывает состояние.
- Префабы подключаются через Addressables: Build / Sync в Level Designer делает их Addressable сам.
- Модели персонажей и анимации (Mixamo) — см. раздел «Анимации игрока и зомби» в [Progress.md](Progress.md).
