## 5. Открытые пункты

- Обучение — сценарий Maze без шагов фрагмента и выхода; при `AllKilledRule` завершается на последнем убитом зомби (раньше шагов аптечки и карты). Переделывается в обучающий забег.
- Окно результата: подписи у звёзд «выход» и «карта» пустые (звёзды Maze) — до этапа 6.
- Звуки `Player/win`, `Other/map`, `UI/window_exit_level` больше ни к чему не привязаны (Build Audio покажет их неиспользуемыми); `win` — кандидат на конец волны.
- Заголовок «MAZEBOUND» в главном меню (`RuntimeScenesBuilder`, сцена Bootstrap) — меню переделывается на этапе 10.
- Политика конфиденциальности: `PlatformTraits.PrivacyPolicyUrl` указывает на страницу Maze — нужна своя (к выходу на площадки).
- Псевдоним ключа подписи Android — `mazebound` (keystore пользователя можно использовать и здесь).
- Настройки игрока: дистанция камеры (±4…±10, по умолчанию ±7) и масштаб разрешения на Android (по умолчанию 0,75; `WebPage.SetResolutionScale` уже есть) — в экран настроек, вместе с переделкой UI (этап 10 или раньше по команде). Обзор игры по умолчанию — радиус 10 (`VisibilitySystem.SetRadius`; сейчас 10 ставит только стресс-тест).
- Поле пути 100×100 — 4,5 мс на пересборку на A16: кэшировать маску проходимости (сейчас опрашивается каждую пересборку), при необходимости ограничить радиус — до этапа 8.
- Прогон стресс-теста на телефоне слабее A16 (класс Redmi 9A / Galaxy A03) — при появлении устройства.
- Ключ подписи Android для Purge (`UserSettings/PurgeAndroidSigning.json`) не заведён — release APK не соберётся; stress-сборки подписываются отладочным ключом.
- Сервер для платежей ВК — сервер пользователя (1 ГБ), отдельное обсуждение.

## 6. История

### 2026-10-14 — Этап 3: фундамент данных
- **Флаги клеток**: `CellFlags` (движение / пули / обзор / замедление / горючесть) = структура + поверхность + препятствие (`CellRules`), запекает `LevelGrid`; `ObstacleDefinition` (контент, `Data/Obstacles`: Tree, Bush, Rock), препятствия в `LevelGeometry` (палитра + byte на клетку), `LevelEditing.SetObstacle`, кисть **Obstacle**, вид — вариант Decor с Definition = препятствие. Проходимость, обзор, пули (`LevelOpacity.ForBullets`), ближний бой и автонаведение, зрение зомби, `KeyDoorSolver` и валидатор перешли на флаги. `CellType.Void` для верхних этажей.
- **Этажи**: этаж в `GridPosition`; `LevelGeometry/LevelGrid` хранят N этажей (индексы этажа 0 не изменились); A*, BFS, поле пути, обзор, лучи, свет, корзины, маски вида, карта — в пределах этажа; этаж у игрока, зомби, пуль, звуков, пространственных запросов; `LevelEditing.AddFloor/RemoveTopFloor`; проверка `FloorOverhang`.
- **Стабильные id**: `ContentDefinition` (оружие, зомби, препятствия), `ContentIds`, `ContentIdAssigner` (id при создании/копии), `ContentCatalog` (**Build Content Catalog**, Build/Sync, Addressable, грузится при старте), `[ContentRef]` — выпадающий список (голоса зомби в `AudioCatalog`). Id зомби стали уникальными (`zombie_*`, `forest_zombie_*`, `snow_zombie_*`).
- **Модули**: `ContentModule`, `[ModuleInfo]`, `[ModuleList]`, `ModuleTypes`, `Modules` (запросы и проверка), инспектор контента с меню Add module.
- **Сейв v1**: `SaveData` заново (деньги, уровни со сложностями, выживание, арсенал с прокачкой/развилками/★⊘, дерево, статистика, сейв забега, настройки), нормализация и слияние при входе; `ProgressService` на новой схеме (сложность в `RecordCompletion`).
- Тесты: EditMode 441/441 (+ этажи/флаги/препятствия, id/каталог/модули, сейв v1), PlayMode 13/13.

### 2026-10-14 — Этап 2: стресс-тест
- **Орда** (`Gameplay/Horde/HordeSystem`): монстры в плоских массивах, общее поле пути `Core/Navigation/FlowField` (Дейкстра 8 направлений, пересборка по смене клетки игрока/двери), расталкивание `Core/Horde/CellBuckets`, скольжение по стенам, атака, трупы, запросы попаданий. Включается у уровня с `LevelData.StressTest` (`StressTestDefinition`).
- **Запечённая анимация + instancing**: **Build Horde Visuals** (меш Synty сварен 4779 → 1572 вершины, 8 клипов → текстуры костей 0,8 МБ и VAT 8,7 МБ, материалы), шейдер `Purge/Horde` (кости/VAT, смешивание кадров, плоские нормали из производных, свет `Purge/Lit`), `HordeRenderer` (`RenderMeshInstanced` пачками по 128, отсечение по экрану и обзору, тени-пятна).
- **Нагрузка**: `StressWeapons` (пули в массивах, дробовик, огнемёт, `FireField`), `StressEffectsView` (трассеры, частицы через `Emit`, огонь — маска + шейдер `Purge/FireCells`).
- **Стенд**: оверлей с метриками и кнопками, автопилот (`StressAutopilotInput`, обход столбов), автобенчмарк 26 конфигураций → канал `Performance`; уровни `Level_Stress64/100` (**Build Stress Test Levels**); сборки **WebGL / Android APK Stress Test** (release + dev-уровни, `PURGE_DEV_LEVELS`; APK — отладочный ключ); `WebPage.SetResolutionScale` (веб: DPR, Android: `Screen.SetResolution`); `VisibilitySystem.SetRadius/LastComputeMs`, `TopDownCamera.FollowHalfExtent`.
- **Видимость** (`FieldOfView`): лучи 5×5 только для клеток ≤ 4, дальше — центр-центр + веер к краю окна; радиус 10 на A16 — 13–35 → 2–7 мс.
- **Android**: `targetFrameRate` = 60 (умолчание Unity на мобильных — 30).
- **Замеры A16** (Helio G99 / Mali-G57): браузер 1497×596 — 90 FPS (потолок экрана) при 150–300 монстрах, 68–73 при 370 в кадре; APK 2340×1080 — 64 FPS при 150, 45 при 500 в кадре, 84–88 при масштабе 0,75 (упор в заливку экрана). Порог 30/24 не нарушен нигде. Подробно — [StressTest.md](StressTest.md).
- Тесты: EditMode 406/406 (+4: поле пути, корзины), PlayMode 13/13.
