# Меню Purge — что делает каждая команда

Справочник по меню **Purge** в редакторе Unity: что делает команда, когда её запускать и что она перезаписывает.
В начале — готовые рецепты для частых задач («добавить оружие», «добавить звук» …), ниже — описание каждой команды.

Общие правила почти для всех билдеров:
- Повторный запуск безопасен: ассеты пересоздаются **на месте** (GUID сохраняется, ссылки уровней и префабов не рвутся).
- Подстроенные руками значения (статы оружия, громкость звуков, цвета/тайминги темы, веса вариантов) **сохраняются** —
  перезаписывается только то, что билдер генерирует сам.
- Результат и ошибки пишутся в консоль с префиксом `[Purge]`.
- Билдеры сами находят контент **по папкам и именам файлов** — чтобы добавить модель или звук, в код лезть не нужно.
  Код правится только там, где он сам и есть контент: процедурные эффекты/иконки, вёрстка UI, новый *вид* звука.

## Рецепты

### Добавить новое оружие
1. Положить префаб модели в `Assets/_Project/Art/Weapons/Purge/<класс>/[<калибр>/]` (pivot — в рукояти; огнестрел —
   ствол вдоль **+Z**; ближнее может лежать вдоль любой оси — билдер довернёт его в руке).
   **Папка 1-го уровня — класс** (черновые модули и как держать), **глубже — калибр** (тип патронов):

   | Класс | Атака (черновик) | Держится |
   |---|---|---|
   | `Pistol` | пули, одиночный | пистолет |
   | `Auto` | пули, автомат | винтовка |
   | `Shotgun` | веер дроби | дробовик |
   | `Sniper_rifle` | пуля с пробитием | винтовка |
   | `Ballons` | струя-конус | тяжёлое у бедра |
   | `Energy` | цепная молния | тяжёлое у бедра |
   | `Another` | снаряд со взрывом | на плече |
   | `Melee` | удар-сектор | ближнее |

   Тип патронов — `AmmoDefinition` из `Data/Ammo`, у которого в `Model Folders` есть самая глубокая папка пути модели
   (`Auto/7x62_mm/AK-74` → `Ammo_7_62`; у `Pistol/Glock_base` — `Pistol` → `Ammo_9mm`). Новый калибр = новый ассет патронов
   (Create → Purge → Definitions → Ammo) с радиусом шума и папками. **Не оружие:** `For_monsters/` (экипировка монстров),
   `Throw/` (метательное — рецепт ниже), модели `*_Ammo` (снаряды). Новый класс — это код (`WeaponsBuilder.Classes` + атака/анимации).

   Если модель из пака в `Import` — префаб перенести/скопировать сюда, меши/текстуры подтянет шаг 3.
2. **Purge → Dev → Build Weapons** — найдёт новую модель и создаст определение `Data/Weapons/<имя префаба>.asset`
   (id из имени файла, например `Pomp_Shotgun` → `pomp_shotgun`) с черновыми модулями класса, метки Muzzle/Tip и `Grip_L`,
   пикап-префаб, вариант `weapon_<id>` в наборе оружия, запись в каталоге визуала и иконку для HUD. В консоли будет
   `1 new (…: draft values …)`. Если в `Data/Weapons` уже есть определение с таким именем файла — билдер возьмёт его.
3. Если брали из пака — **Purge → Dev → Collect Used Third-Party Assets** (до коммита).
4. **Purge → Dev → Convert Object Materials to Purge Lit** — материалы модели на шейдер игры.
5. Настроить в `Data/Weapons/<имя>.asset`: редкость, «No Upgrades», `Hold`, и **модули** (Add module): атака (урон, интервал,
   автомат, дальность, разброс, дробь, пробитие…), «Ammo and magazine» (тип патронов, магазин, перезарядка, бесконечный
   запас, свой радиус шума), «Silencer», «Mobility» (скорость в руках / при стрельбе). Build Weapons их больше не трогает;
   проблемы модулей (нет атаки, дальнее без патронов) пишет предупреждениями.
6. Свой звук выстрела/удара или перезарядки — см. «Звуки оружия» ниже (например, глушитель: в поле `Sound` выбрать `silenced`).
7. Поставить на уровень: **Purge → Level Designer** → инструмент Weapon → поле `Definition` → клик по клетке → Build / Sync.
   Базовый пистолет пустого слота — `PlayerDefinition.Base Weapon` (сейчас `Glock_base`, у него «Infinite Reserve»).

**Убрать оружие** — удалить префаб модели и снова Build Weapons; определение, оставшееся без модели, он назовёт в консоли
(его стоит удалить и убрать с уровней). **Заменить модель** существующего оружия — положить новый префаб, в каталоге
`Data/Weapons/WeaponVisuals` у нужного определения поставить его в `Held Prefab`, старый префаб удалить, Build Weapons.
(При удалении модели Unity может написать ошибку импорта её пикапа «Missing Nested Prefab» — Build Weapons этот пикап удалит.)

### Добавить метательное (граната, молотов…), аптечку, вид патронов на земле
1. Модель метательного — в `Art/Weapons/Purge/Throw/` (верхний уровень папки; `Turret/` не трогается), аптечки —
   в `Art/Items/Purge/Medical/`, патроны на земле — `Art/Items/Purge/Ammo/<X>_ammo`, где X — одна из `Model Folders`
   типа патронов или её начало («9» → «9_mm»; у баллонов в папках добавлено «Gas»).
2. **Purge → Dev → Build Items** — создаст `Data/Throwables/<модель>.asset` / `Data/Medkits/<модель>.asset` (id из имени
   файла), пикап-префабы в `Art/Items/Pickups` и запишет всё в `Data/Items/ItemVisuals`.
3. Настроить ассет: у метательного — редкость, стопка, дальность, скорость, высота дуги, интервал и **эффекты**
   (Add module → Effect: «Explosion», «Place zone», «Status in radius»); у аптечки — `Heal` (0 = до полного).
   Без эффектов билдер предупреждает: метательное ничего не делает.
4. В дроп — список `Pool Throwables` в `Data/Horde/SandboxHorde.asset` / `RunHorde.asset` (позже — магазин), аптечка — в `Medkits` таблицы
   `Data/Drops/HordeDrop` с весом.

**Новая зона или состояние** — Create → Purge → Definitions → Zone / Status в `Data/Effects`, модули в инспекторе
(зона: урон, состояние, распространение по горючему; состояние: урон во времени, оглушение, замедление), цвета — черновой
вид. Поджог/оглушение оружием — модуль «Status on hit» у оружия.

### Добавить карточку забега
1. В `Data/Cards`: Create → Purge → Definitions → Card (или копия существующей) — редкость, максимум уровней, иконка, модули
   (Stat / Damage vs state / Throwables). Id даётся сам по имени файла.
2. В `Strings.tsv` — `card.<id>` (название) и `card.<id>.text` (что даёт уровень; `{0}`, `{1}` — числа модулей по порядку) →
   **Build Localization**.
3. **Build Cards** (соберёт колоду) → Sync. Новая механика (не стат) — новый модуль `CardModule` в коде.

### Переименовать или переместить файлы
Переименовывать префабы и ассеты можно — **только внутри Unity** (окно Project): GUID сохраняется, а все связи
(каталог оружия, набор зомби, `PlayerVisual`, уровни) держатся на GUID, а не на имени. Затем запустить билдер этого вида
(Build Weapons пересоздаст пикап под новым именем и удалит старый).
- Снаружи Unity (проводник, IDE) — только вместе с `.meta`, иначе Unity выдаст новый GUID и билдер сочтёт файл новым.
- Перенос модели оружия в другую папку уже созданное оружие **не меняет** — модули и тип патронов правятся в определении.
- `Id` в определении оружия лучше не менять после расстановки по уровням: визуал расставленного оружия переназначится.

### Добавить препятствие (дерево, куст, камень…)
1. **Create → Purge → Definitions → Obstacle** в `Assets/_Project/Data/Obstacles/` — галочки: блокирует движение / пули /
   обзор, горит, доля скорости (для проходимых). Id появится сам.
2. Вид: в набор **Decor** темы добавить вариант с моделью и **Definition** = это препятствие (вес > 0).
3. Ставить кистью **Obstacle** в Level Designer. Код не нужен.

### Звуки оружия
Звуки оружия выбираются по **звуковой группе** — полю `Sound` в определении оружия (`Data/Weapons/<имя>.asset`). Это
**выпадающий список** папок групп (вписывать руками ничего не надо); `Default` = группа с именем id оружия, если такая
папка есть, иначе общий звук. Рядом — **Sound Pitch** (тон: та же группа ниже на 10–15 % звучит тяжелее) и
**Sound Volume** (громкость выстрела этого оружия).

Группа — это папка `Assets/_Project/Sounds/Weapon/<группа>/` (свои записи):
- `attack*` — выстрел или удар (`attack1`, `attack2` … — случайные варианты);
- `start*` / `loop*` / `end*` — **непрерывный огонь** (миниган, огнемёт, луч): если есть `loop`, вместо звука на каждый
  выстрел играет петля, пока атака идёт, `start` — в начале, `end` — когда отпустили;
- `reload*` — перезарядка одной записью (если у группы нет шагов перезарядки).

**Общие части** — папки `Sounds/Weapon/_Parts/<часть>/` (любые имена файлов, все — варианты): шаги перезарядки
(`rifle_mag_out`, `rifle_mag_in`, `rifle_charge`, `pistol_slide`, `revolver_open`, `belt`, `shell_insert`, `pump`, `gl_open`,
`canister`, `battery`…), «достать» (`draw_gun`, `draw_pistol`, `draw_blade`, `draw_energy`), хвост выстрела `tail`, гильзы
`shells_brass` / `shells_shotgun`, удары (`hit_blade`, `hit_blunt`, `hit_heavy`, `hit_energy`, `hit_lightning`), полёт ракеты
`rocket_flight`. Одна запись служит многим стволам. Группа ссылается на части **выпадающими списками** в
`Data/Audio/AudioCatalog.asset` → **Weapon Sounds** → группа:
- **Reload Steps** — части перезарядки и когда каждая звучит (доля времени перезарядки; 1 = заканчивается с ней);
- **Draw** — при смене оружия; **Tail** — эхо после одиночного выстрела или в конце очереди (один раз);
- **Cycle** + **Cycle Delay** — после каждого выстрела (помпа, продольный затвор); **Shells** — гильзы;
- **Hit** — свой звук попадания этим оружием (ближнее — в момент удара клипа); пусто — общий «тук» по монстру;
- **Flight** — петля, летящая за снарядом (ракета).

Новая группа получает части по виду своего первого оружия (как держат, атака, тип патронов) — черновик, дальше правится в
каталоге; Build Audio потом их не трогает и предупреждает о ссылке на часть без папки.

**Свой звук одному оружию** — папка с именем его id, например `Sounds/Weapon/awm/attack1.wav` → **Build Audio**.
Поле `Sound` трогать не нужно (`Default`).

**Общая группа на несколько видов оружия** (например `rifle_545` у M416 и SCAR-L):
1. Папка `Sounds/Weapon/<группа>/` с файлами `attack*` (и при нужде `start/loop/end/reload`).
2. У каждого нужного оружия в определении в списке `Sound` выбрать эту группу (папка появится в списке сразу).
3. **Purge → Dev → Build Audio**, затем в каталоге проверить части группы.

Громкость, разброс тона, число голосов, минимальный интервал — в `AudioCatalog.asset` (группа и каждая часть; Build Audio
их не трогает). Сведение: скорострельное — громкость ≤ 0.5 и 4–8 голосов, ручное (снайперки, дробовики) 0.7–0.9; у
струй (`Stream`) — `Min Interval` ~0.3 (атака 10 раз в секунду). Build Audio предупреждает о группе, которую не использует
ни одно оружие, и об оружии, чей `Sound` указывает на несуществующую папку (в инспекторе — красным «(missing folder)»).

Общие звуки боя (`Sounds/Weapon`, `Sounds/Combat`): `empty_click` (пустой магазин), `low_ammo` (каждый выстрел, когда в
магазине ≤ 25 %), `monster_hit` (попадание), `kill_pop` + `kill_splat` (убийство), `explosion_small/medium/large` (по
радиусу взрыва), `throw`, `pin`, `land` (метательное), `ignite` (молотов). Отобранные исходники — шортлист
(`Docs/SoundShortlist/README.md`, что куда перенесено — `transfer_log.tsv`).

Это только то, что слышит игрок. Как далеко выстрел слышат **монстры** — `Sound Radius` в том же определении оружия.

### Ощущение оружия (отдача, отбрасывание, тряска…)
У каждого оружия модуль **Feel** (`Data/Weapons/<имя>.asset` → Add module → Feel): отбрасывание и короткое оглушение
монстра от попадания, отлёт трупа, отдача игрока; толчок и тряска камеры, отдача оружия и корпуса, свет выстрела,
вспышка и «вмятина» монстра, брызги, кольцо под целью, вибрация. Без модуля — значения по умолчанию.
Подбирать удобно на стенде: уровень `Level_Sandbox` → панель **FEEL** справа (переключатель и ползунок ×0–3 на каждый
канал; **LOG** пишет множители в консоль). Найденные множители перенести в модули оружия (умножить поля канала).
Код не нужен.

### Добавить или заменить звук / музыку
1. Положить файл в `Assets/_Project/Sounds/<Player|Weapon|Other|Zombie|UI>/` (музыку — в `Assets/_Project/Music/`).
   Имя должно подходить под шаблон нужного звука (таблица шаблонов — массив `Cues` в
   [AudioBuilder.cs](../Assets/_Project/Scripts/Editor/Dev/AudioBuilder.cs)). Пример: ещё один вариант выстрела — `Weapon/rifle_attack3.wav`;
   все файлы, подходящие под шаблон, станут случайными вариантами одного звука.
2. **Purge → Dev → Build Audio**.
3. Совсем новый вид звука (не подходит ни под один шаблон) — нужны поле в `AudioCatalog`, строка в `Cues` и код,
   который его играет (`LevelAudioPresenter` / `AppAudioPresenter`).

### Добавить декор
1. Префаб модели — в `Assets/_Project/Art/Decor/` (подпапки допускаются).
2. **Purge → Dev → Build Decor** (материалы на `Purge/Geometry`, Read/Write, масштаб под клетку, вариант в наборе декора).
3. Если из пака — **Collect Used Third-Party Assets**.
4. В уровнях: Level Designer → Regenerate Visuals (авторасстановка) или ручная расстановка.

### Биом: снег / лес, поменять вид пола и стен
1. Цвета и узоры текстур — в коде `BiomeThemeBuilder` (метод на поверхность: `SnowGround`, `Ice`, `SnowStoneWall`, `Grass`,
   `Hedge`, `MossyStoneWall`, `LogWall`…; веса вариантов — в `Snow()` / `Forest()`).
2. **Purge → Dev → Build Biome Themes**.
3. В уровне: Level Designer → вкладка Visuals → тема `SnowTheme` / `ForestTheme` → Regenerate Visuals → Build / Sync.

### Добавить факел (светильник)
1. Префаб — в `Art/Lighting/` (факел: крепление в начале координат, стена в −Z, факел смотрит в +Z).
2. **Purge → Dev → Build Light Fixtures**.
3. Если из пака — **Collect Used Third-Party Assets**.

### Добавить внешний вид зомби
1. Префаб модели — в `Assets/_Project/Art/Zombie/`.
2. **Purge → Dev → Build Zombie Animations** — префаб получит контроллер и масштаб, в наборе зомби
   (`Data/Themes/PlaceholderZombieSet`) появится вариант с id по имени префаба (`Zombie_04` → `zombie_04`).
   Тип зомби новому виду ставится автоматически (тип, у которого ещё нет вида, иначе первый), в консоли — предупреждение.
   **Проверить** поле `Definition` у варианта в наборе и при необходимости поменять — билдер его больше не трогает.
3. **Extract Character Meshes** → **Convert Object Materials to Purge Lit** → (если из пака) **Collect Used Third-Party Assets**.

Несколько видов у одного типа — можно: в игре вид выбирается из них по весам (`Weight` варианта).

Новый **тип** зомби (поведение) — новый `ZombieDefinition` в `Data/Zombies` (можно скопировать существующий), затем
вид для него (шаги выше; Build Zombie Animations называет в консоли типы без вида — в игре такие зомби невидимы);
тон голоса — список `Zombie Voices` в `AudioCatalog`.

### Заменить модель игрока или анимации
- Клипы — файлы Mixamo в `Art/Animations` с фиксированными именами `Player_*` (`Player_rifle_weapon_shoot`, …). Заменить
  клип — положить файл с тем же именем → **Build Player Animations**.
- Новая модель: префаб (Humanoid) положить в `Art/Player/` **вместо** старого — модель игрока = единственный префаб прямо
  в этой папке (если их несколько, берётся текущий из `PlayerVisual`). Затем **Build Player Animations** → **Build Weapons**
  (риг рук и `Grip_L` считаются по модели) → **Extract Character Meshes** → **Convert Object Materials to Purge Lit**.

### Взяли что-то новое из стороннего пака
Сначала подготовить ассет его билдером (Decor / Weapons / Light Fixtures …), затем
**Purge → Dev → Collect Used Third-Party Assets**. Делать **до коммита**: папка `Import` не в git.

### Изменить или добавить текст игры (локализация)
Все тексты UI — в таблице `Data/Localization/Strings.tsv`: строка на ключ, колонка на язык (`en ru tr es de`), колонки
разделены **табуляцией** (удобно править в Google Sheets / Excel и сохранять как TSV, UTF-8). Первая колонка (`en`) —
базовый язык: пустая ячейка другого языка берёт её текст (в редакторе и dev-сборке вместо него виден ключ). Тексты,
которые на экране заглавными, и в таблице пишутся заглавными (турецкое i/İ код не переведёт). `{0}`, `{1}` — значения;
у всех языков набор `{n}` должен совпадать.
1. Поправить текст в таблице.
2. **Purge → Dev → Build Localization** — таблицы языков, проверка, атласы шрифтов под новые символы.

**Новый текст в коде** — ключ-константа в `TextKeys` + строка в таблице; статичная подпись в `RuntimeScenesBuilder` —
`Loc(TextKeys.…)` вместо литерала (затем Build Runtime Scenes). **Новое оружие** — строка `weapon.<id>`, **новый цвет
ключа** — `hud.locked.<цвет>` (Build Localization напомнит о пропусках).

**Добавить язык** — колонка с кодом языка, в ней строки `language.name` (название на самом языке) и `language.system`
(имена `SystemLanguage` через запятую — для автовыбора при первом запуске), затем Build Localization. Буквы, которых нет
в Rajdhani, берутся из Exo 2 (кириллица); для других алфавитов (греческий, CJK …) нужен свой fallback-шрифт в `UiStyleBuilder`.

### Поменяли вёрстку UI в коде
**Purge → Dev → Build Runtime Scenes** — сцены Bootstrap и Game пересоздаются из `RuntimeScenesBuilder`.

### Собрать игру

## Purge → Level Designer
Окно редактора уровней: генерация, правка клеток и объектов, визуал, свет, валидация, Build / Sync, Test / Play.

## Purge → Build
Сборка игры в `Builds/<Platform>` (папка не в git). Порядок: проверка всех уровней каталога (невалидный — сборка не идёт) →
перенос ассетов, попавших в несколько бандлов, в группу **Purge Shared Dependencies** → Addressables-контент → плеер.
В конце в консоли — размер сборки.

**Яндекс Игры:** в сборку попадает symbol `PURGE_YANDEX` (только в плеер, редактор без него) — игра работает через SDK ЯИ
(язык площадки, сейв в данных игрока, кнопка «Войти» в меню, реклама ЯИ, события загрузки/геймплея), в `<head>` — `/sdk.js`
и счётчик Метрики, если задан `WebPlatforms.YandexMetrikaCounter` (`Editor/Build/WebPlatform.cs`; пусто — Метрики нет).
Рядом с папкой сборки кладётся zip с `index.html` в корне — его загружают в черновик игры в консоли ЯИ.
В консоль — **только release** (~25 МБ): dev-сборка без сжатия и с отладочным кодом (`.wasm` ~150 МБ) не проходит лимит ЯИ
100 МБ в распакованном виде; она — для локальной проверки через прокси.

**CrazyGames:** symbol `PURGE_CRAZYGAMES`, в `<head>` — их JS SDK v3. Проверка у себя: открыть сборку с `localhost` (любой
статический сервер, например `python -m http.server 8000` в папке сборки) — SDK работает в локальном режиме (демо-реклама,
тестовый пользователь); на другом адресе SDK выключен и игра идёт как без площадки. В портале при отправке включить
**Progress Save** (иначе сейв не работает) и альбомную ориентацию.
**Игры ВКонтакте:** symbol `PURGE_VK`, в `<head>` — VK Bridge (`vk-bridge.min.js` рядом со страницей, копия npm
`@vkontakte/vk-bridge` 3.0.2 из `WebPlatforms/Vk/`; CDN в регионе игрока может быть недоступен) и `VKWebAppInit` до загрузки
игры. Игра: язык из `vk_language`, сейв в VK Storage частями (`SlottedCloudSave`), реклама VK, баннер снизу (на телефонах — `VkPlatform.MobileBanner`), пауза при
скрытии в приложении ВК, строка «Поддержка» в настройках (Other). Вне ВК мост не отвечает — игра идёт как без площадки.
Сборка кладёт `Builds/vk-hosting-config.json` (папка этой сборки, `app_id` — `WebPlatforms.VkAppId`; пусто — вписать в файл
или задать `MINI_APPS_APP_ID`) и предупреждает, если в сборке есть аудио/видеофайлы (хостинг VK их не принимает).
**Выкладка** (нужен Node.js): в папке `Builds` — `npx @vkontakte/vk-miniapps-deploy`. Первый раз утилита даст ссылку для
входа (ключ сохранится), каждую выкладку надо подтвердить на телефоне; на вопросы «update prod/dev urls?» — да. Только
в режим разработки (видят админы): `set MINI_APPS_ENVIRONMENT=dev` перед командой (cmd) или `$env:MINI_APPS_ENVIRONMENT="dev"`
(PowerShell). Лимит — 24 выкладки в сутки; адрес игры меняется при каждой выкладке.
**GameDistribution:** symbol `PURGE_GAMEDISTRIBUTION`, в `<head>` — `GD_OPTIONS` с Game ID (`WebPlatforms.GameDistributionGameId`
в `Editor/Build/WebPlatform.cs`) и загрузчик их SDK (`html5.api.gamedistribution.com/main.min.js`). Игра: interstitial перед
каждым уровнем (и первым PLAY) и при выходе в меню с окна результата — частоту ведёт SDK GD (наши «не раньше 4-го уровня /
раз в 90 с» здесь выключены); rewarded как везде, награда — только за досмотренную; пауза и тишина на время рекламы.
Облака, языка площадки, входа, ссылок и почты нет (правила GD) — сейв в браузере, язык системы. В панели GD: загрузить zip,
включить **rewarded ads**, открыть игру в iframe со страницы загрузки и **досмотреть тестовый pre-roll** (без этого GD не
активирует игру), отключив блокировщик рекламы. Тестовая реклама в своей проверке — `gdsdk.openConsole()` в консоли
браузера (выключить — очистить localStorage). Без SDK (заблокирован, нет сети) игра идёт как без площадки.
Проверка на своём компьютере (нужен Node.js): `npx @yandex-games/sdk-dev-proxy -p Builds/WebGL-Yandex-dev --app-id 628471`
— прокси печатает ссылку вида `https://yandex.ru/games/app/628471?game_url=https://localhost:…`, игра открывается внутри ЯИ
с настоящим SDK; `--dev-mode true` — имитация SDK без площадки. Вне ЯИ (просто открыть папку) SDK нет — игра работает как без площадки.

**RuStore (Android):** symbol `PURGE_RUSTORE` — реклама — Рекламная сеть VK, аналитика — MyTracker, в настройках (Other) — почта
поддержки и «Политика конфиденциальности» (кнопка открывает `Contacts.PrivacyPolicyUrl`). Ключи — в одном месте,
`RuStoreKeys` (`Scripts/Application/Platform/Android/RuStore.cs`): пустой ключ MyTracker — аналитика только в лог, нулевые
слоты рекламы — демо-слоты VK (тестовая реклама, без дохода). Команда сама выставляет: компанию **BGames**, пакет
**ru.bgames.mazebound** (после публикации не менять), versionCode из **Version** в Player Settings (`1.2.3` → 10203; перед
каждой загрузкой в RuStore поднять Version), IL2CPP ARM64 + ARMv7, target API — новейший установленный, APK (не AAB), иконку
(`Art/AppIcon`), без заставки Unity. Библиотеки SDK подтягивает External Dependency Manager в Gradle-шаблоны
`Assets/Plugins/Android` (создаются при первой Android-сборке; Gradle качает их при сборке — нужен интернет).
**Подпись release:** ключ не в git. Один раз создать (JDK есть в Unity):
`"<Unity>\Editor\Data\PlaybackEngines\AndroidPlayer\OpenJDKin\keytool" -genkeypair -v -keystore D:\Keys\mazebound.keystore -alias mazebound -keyalg RSA -keysize 2048 -validity 36500`,
затем заполнить `UserSettings/PurgeAndroidSigning.json` (создаётся при первой release-сборке): путь к keystore, пароли, alias.
**Ключ и пароли хранить в надёжном месте с копией:** без них новые версии в RuStore не загрузить. Путь и пароли в
ProjectSettings не остаются (команда сбрасывает их после сборки). Dev-сборки — отладочным ключом Unity.

Платформа должна быть **активной** (File → Build Profiles). Если нет — команда только переключит платформу (долгий реимпорт),
и её надо запустить ещё раз.

**WebGL:** настройки выставляет сама команда (не менять руками в Player Settings — перезапишутся): шаблон страницы
`Assets/WebGLTemplates/Mazebound` (игра на всё окно, без полос прокрутки и жестов браузера, своя полоса загрузки),
сжатие Brotli с распаковкой в браузере (сборка открывается с любого статического сервера, в том числе по http с телефона),
имена файлов с хешем, текстуры ASTC (в мобильных браузерах нет DXT; первая смена — долгий переимпорт), IL2CPP «меньше размер» (release), вырезание кода Medium — наши сборки, VContainer и UniTask
сохраняет `Assets/_Project/link.xml`. Подцель ASTC передаётся и в саму сборку плеера (`BuildPlayerOptions.subtarget`):
без этого Unity собирал плеер с DXT и сбрасывал настройку — каждая следующая сборка заново переимпортировала все текстуры.
Визуал (**Purge Visuals**) упакован **по бандлу на префаб** (имена — только хеш): браузер качает лишь то, что нужно уровню
(до первого уровня ~16–17 МБ вместо ~20–23). Общие зависимости (**Purge Shared Dependencies**) — одним бандлом: по бандлу на
ассет старт был на ~3 с дольше (кэш Unity в браузере проверяет у сервера каждый файл при каждом запуске). LZMA для бандлов на WebGL
Addressables не поддерживает — остаётся LZ4. Музыка — группа **Purge Music** (бандл на трек, качается только когда играет),
её создаёт Build / Sync.

## Purge → Dev

### Контент игры

#### Build Content Catalog
Стабильные id и каталог контента (этап 3). Каждый ассет-наследник `ContentDefinition` (оружие, зомби, препятствия, дальше —
метательное, монстры, карточки…) получает **стабильный id** один раз — при создании, из имени файла
(`ForestZombieWalker` → `forest_zombie_walker`, занят → `_2`); переименование/перенос файла id не меняет, копия ассета
получает свой. Это делает `ContentIdAssigner` автоматически при импорте; команда дополнительно чинит пустые/повторяющиеся id
и пересобирает `Data/Content/ContentCatalog.asset` (`"Content/Catalog"`, грузит `SharedDefinitionsService`) — все такие
ассеты проекта по пути. В сейве покупки и прокачка хранятся по этим id.

Запускать: не нужно вручную — это делает **Build / Sync** (Level Designer). Вручную — чтобы проверить каталог.
Id в инспекторе только для чтения; строковые ссылки на контент — выпадающие списки (`[ContentRef(typeof(...))]`).

#### Build Weapons
Всё оружие игрока из моделей `Art/Weapons/Purge`: класс — папка 1-го уровня, калибр — глубже (см. рецепт); не оружие —
`For_monsters/`, `Throw/`, модели `*_Ammo`.
- `WeaponDefinition` в `Data/Weapons`: модель, уже записанная в каталоге, сохраняет своё определение; для новой модели
  создаётся `<имя префаба>.asset` с черновыми модулями класса и типом патронов по папке. Значения существующих
  определений не трогаются;
- на префабе модели — `WeaponModel` с меткой `Muzzle` (огнестрел) или `Tip` (ближнее) на дальнем конце меша; ближнему,
  вытянутому не вдоль +Z, — поворот в руке (`Grip Rotation`);
- пикап-префаб `Art/Weapons/Pickups/<модель>_Pickup` (лежит боком, по диагонали клетки), вариант `weapon_<id>`
  в `PlaceholderWeaponSet` (его используют обе темы), Addressable;
- каталог визуала `Data/Weapons/WeaponVisuals` (`"Weapons/Visual"`) — связь определение ↔ модель;
- `CharacterWeaponRig` на префабе игрока (центры ладоней, сокет ближнего оружия);
- у огнестрела — метка `Grip_L` (куда левая рука берётся за оружие, по позе выстрела);
- переназначает визуал оружия в уровнях, если старый больше не подходит; иконки оружия для HUD (как Build UI Icons);
- удаляет пикап-префабы и иконки, которые больше не соответствуют ни одному оружию (после переименования или удаления
  модели, смены id) — папки `Art/Weapons/Pickups` и `Art/UI/Icons/Weapons` целиком принадлежат билдеру, руками туда не класть;
- предупреждает об определениях без модели, о модели вне известного класса, об оружии без типа патронов и о проблемах модулей.

Запускать: после добавления/замены/удаления модели оружия, после смены модели игрока; затем Convert Object Materials to Purge Lit.
Требует: `PlaceholderWeaponSet` (иначе — Create Placeholder Theme), типы патронов в `Data/Ammo`.

#### Build Items
Предметы, появляющиеся в игре: метательное (определение на модель `Art/Weapons/Purge/Throw/*`, новое — без эффектов),
аптечки (определение на модель `Art/Items/Purge/Medical/*`, новое — лечит до полного), патроны на земле (модель
`Art/Items/Purge/Ammo/<X>_ammo` ↔ тип патронов по `Model Folders`), оружие (пикапы Weapon Set). Пикап-префабы (модель
уменьшена до ~0,45 клетки и стоит на полу) и летящие (по центру) — `Art/Items/Pickups` (папка принадлежит билдеру), Addressable
в Purge Visuals; каталог `Data/Items/ItemVisuals` (`"Items/Visual"`, Purge Shared). Значения существующих определений
не трогаются; предупреждает о метательном без эффектов и о типе патронов без модели. В конце рисует силуэты метательного для HUD.
Запускать: после новых моделей метательного, аптечек, патронов и после Build Weapons (пикапы оружия); затем Convert Object Materials to Purge Lit.

#### Build Zombie Animations
Клипы Mixamo `Zombie_*` → Humanoid; общий `Art/Zombie/Zombie.controller` (Idle ×2, Walk, Scream (Alert), Run, 3 атаки,
смерть; замеряет скорость шага клипов); каждому префабу в `Art/Zombie` — контроллер и масштаб; набор зомби темы —
по варианту на префаб: существующие варианты сохраняют id, вес и тип (`Definition`), новому префабу тип ставится
автоматически с предупреждением (см. рецепт), варианты удалённых моделей убираются; префабы Addressable;
переназначает визуал зомби в уровнях; предупреждает о типах без вида.
Запускать: после смены/добавления моделей или клипов зомби. Контроллер пересобирается на месте — **не удалять его ассет**.

#### Build Horde Visuals
Встроенный монстр стресс-теста (этап 2; монстры этапа 5 — **Build Monsters**): модель первого префаба в `Art/Zombie` сваривается по позиции+UV (Synty плоские —
вершин ~в 3 раза меньше, нормали считает шейдер), клипы `Zombie_*` (idle/walk/run/attack/death по имени) запекаются в
две текстуры — матрицы костей и позиции вершин (VAT) → `Art/Horde` (меш, текстуры, материал на каждый вид зомби,
`FireCells.mat`), `Data/Horde/ZombieHorde.asset` (`HordeVisualDefinition`); создаёт `Data/Horde/StressTest.asset`
(настройки стресс-теста, значения сохраняются) с материалами эффектов и `StressHorde.asset` (орда стресс-теста) с визуалом.
Запускать: после смены моделей или клипов зомби. Ассеты обновляются на месте (GUID те же).

#### Build Monsters
Монстры из папок `Art/Monster/<Биом>/<Ранг>/*.prefab` (биом — Common/Castle/Forest/Snow…, ранг — Mass/Officer/Special
(элита)/Boss). Рядовые (Mass, этап 5а) — запечённые, офицеры (Officer, этап 5в; Громилы `Ram_*` — 5г) — Animator. Рядовые: копирует недостающие клипы `Monster_*` в `Art/Animations` из паков
Zombie_Animations и UAC в `Import` (один раз) и импортирует их Humanoid; определение `Data/Monsters/<Биом>/<префаб>.asset`
(`MonsterDefinition`: создаётся один раз с черновыми статами и дропом ранга `HordeDrop`, дальше правится руками — ранг и
биом берутся из папки); вид `Data/Monsters/Visuals/<префаб>.asset` (`HordeVisualDefinition` с id монстра): меш + экипировка
из списка вида (вклеивается на кость, сдвиг — компонент `EquipmentModel` на префабе модели, добавляется сам), текстура
костей (без VAT, клипы реже/короче там, где их видно мельком), материалы `Purge/Horde` → `Art/Horde/<префаб>`; бег или
спринт — по скорости определения (≥ 2,8 кл/с — спринт), замер скорости шага. Песочнице и стресс-тесту — виды монстров из
их списков `Monsters`; пересобирает каталог контента. Список экипировки и цвет брызг вида сохраняются.
**Офицеры** (`OfficersBuilder`): копирует клипы `Officer_Bow_*` (UAC Bow & Arrow) и свои копии общих клипов
(`Officer_Attack_*`, `Officer_Hit_*`, `Officer_Stunned`, `Officer_Scream`, `Officer_Throw` — из `Monster_*`, `Zombie_scream`,
`Player_Throw`; импорт с выпадом в root motion, у рыка — та же обрезка 0,45–1,3 с) и импортирует; один контроллер
`Art/Monster/Officer.controller` (Pace, атаки, реакции, оглушение, рык, каст — бросок, 4 смерти),
лучнику — подмена клипов `Art/Monster/Controllers/Distant_Castle.overrideController`; префаб настраивается на месте:
контроллер, без root motion, **масштаб под рост головы 1,3 м** (рядовые — 1,18), экипировка из вида на костях (дети
`Equipment_*`, сдвиг — `EquipmentModel` модели), непрозрачные Standard → `Purge/Lit`; вид `Data/Monsters/Views/<префаб>.asset`
(`MonsterViewDefinition`: скорости ходьбы/бега, момент выстрела — бросок: рука быстрее всего, лук: полное натяжение;
экипировка, брызги и снаряд — задаются один раз, дальше правятся в ассете). Новое определение офицера получает черновые
статы, восприятие, способности и дроп `Data/Drops/OfficerDrop`; заодно создаются `Status_Acid`, `Zone_Acid`,
`Status_Slow` (`Data/Effects`). Песочнице офицеры ставятся в `On Demand Monsters` (кнопки Officer), обоим стендам —
виды офицеров их списков (`Monster Views`).

#### Build Combat Effects
Свои мультяшные эффекты боя (без крови и следов пуль) в `Art/Effects`: текстуры (мягкая точка, звезда, трассер),

→ `Data/Combat/CombatVisual`. Ещё материалы броска и зон: `fx_throw_arc` (точки дуги), `fx_throw_target` (кольцо
приземления, `Purge/Ring`), `fx_zone_cells` (клетки зон, `Purge/FireCells`, цвет — из зоны). Ощущение стрельбы (этап 4в):
`fx_splash` (капли цвета монстра, текстура `fx_blob`), `fx_hit_ring` (кольцо под целью, `fx_ring`), а также материалы
чернового вида атак на всех уровнях — молнии (`fx_tracer`) и частицы пламени/взрывов/горения/оглушения (`fx_additive`).
Цвета и параметры частиц — в коде билдера; цвет брызг — `HordeVisualDefinition.Splash Color`.
Этап Э2: пых у ствола после очереди `fx_barrel_puff` (дым паков сверху не читается — свой, на материале дыма
PolygonParticleFX `Art/Effects/PolygonParticleFX/Materials/Smoke_Mat_01.mat`; нет материала — предупреждение, пыха нет) →
`CombatVisual.Barrel Smoke`.
Запускать: после правок эффектов в `CombatEffectsBuilder.cs`; после Build Pack Effects (для пыха).

#### Build Pack Effects
Эффекты из паков `Import/FX` (PolygonParticleFX, Polygon Arsenal; этап Э). Что брать — список `Art/Effects/FxImport.asset`
(перетащить исходные префабы из `Import/FX`; у записи: имя копии, масштаб, **Radius** — сколько клеток эффект покрывает
в своём размере, взрыв масштабируется под свой радиус, 0 — не масштабировать; **Particles** — доля частиц, по умолчанию 0,6;
**Loop** — струя: зацикливается, до 256 частиц, гаснет к 75 % жизни (до дымного хвоста), Radius — дальность, под дальность
оружия подгоняется временем жизни частиц; **Flat** — вид сверху: без гравитации и скорости вверх (у струй всегда) —
поднимающиеся частицы раздуваются к камере; **Tint** — перекраска (альфа 0 — цвета пака): цвет частиц = Tint × их
яркость, одна струя в нескольких цветах; одна и та же исходная запись может повторяться под разными именами).
Первый запуск без списка создаёт пустой список. Для каждой записи — очищенная копия `Art/Effects/<пак>/<имя>.prefab`
(GUID при пересборке сохраняется): без Collision, Lights (и ссылки на лампу), Noise, ламп, `AudioSource`, коллайдеров и
скриптов пака; материалы — копии в `Art/Effects/<пак>/Materials` на `Purge/Particle` (аддитив/альфа/умножение),
`Purge/ParticleRim` (сферы и кольца Arsenal) и `Purge/Lit` (непрозрачные осколки), аддитивный дым (материал с «Smoke»
в имени) — на альфа-смешение и серее (пересвечивал светлый пол); материалы `LineRenderer`/мешей — так же; не больше 64
частиц на систему, всплески и эмиссия × доля; без зацикливания (кроме Loop); `CombatEffect` с длительностью по последнему
всплеску + время жизни (у Loop — время затухания).
Копии — Addressable (Purge Visuals). Назначаются в модуле оружия **Effects**, в `Look` взрывов (`Explosion` у
метательного и способностей, «Explosive projectile»), `Look only` (облако дымовой гранаты), `Particles` у зон и состояний
(излучатели массовых эффектов; `Particles At Head` — звёзды вокруг головы), `Fall` у удара по площади (падает сверху в конце
предупреждения), `Projectile Trail` у вида офицера (след снаряда) и умолчаниями в `Data/Combat/CombatVisual` (разделы
**Pack effects**, этап Э3 — вылезание, пых трупа, вспышка ярости). Взрыв под радиус растёт **разлётом** (`CombatEffect.SetSpread`:
корень × масштаб, размер частиц × 1/√масштаба, число × масштаб до ×2,5).
Затем — **Collect Used Third-Party Assets** (перенесёт текстуры и меши; сам список в расчёт не берётся).
Запускать: после правки списка.

`Art/Biomes/<Биом>/Textures`): свои меши блоков пола и стены с тайлинговыми UV (`Art/Biomes/Meshes`; у стены два материала —
бока и верх), материалы на `Purge/Geometry`, префабы, наборы `<Биом>FloorSet` / `<Биом>WallSet` (стены — варианты для
всех форм, поэтому без предупреждений о категориях). Снег: утоптанный снег, сугробы-рябь, лёд; стены — камень со снежной
шапкой, верх — белый снег. Лес: земля с листьями, трава, плиты во мху; стены — камень во мху и бревенчатый частокол, верх —
живая изгородь. Верх стен по цвету резко отличается от пола — лабиринт читается сверху.
Новая тема создаётся **копией `CastleBlockTheme`** (двери, ключи, предметы, зомби, декор, светильники — общие) со своим
светом, пресетами источников и копией материала тумана (`Art/Biomes/<Биом>/Materials/Fog_<Биом>.mat`). Повторный запуск
пересобирает текстуры, материалы и префабы; подстроенные на теме значения (свет, туман) и **содержимое наборов**
(удалённые вручную варианты, веса, default) сохраняются — в существующий набор добавляются только варианты категории,
которой в нём ещё нет. У снега — три варианта пола категории **Snowdrift** (`floor_snowdrift_01..03`: блок пола с низким
снежным холмом до 0.2 м, меши `Art/Biomes/Meshes/BiomeDrift_*`, материал обычного снега `floor_snow`) — их получают
только клетки-сугробы (кисть **Snowdrift**). Белизну сугроба и мягкий неровный край рисует шейдер `Purge/Geometry`
(маска сугробов уровня), настройки — `SnowTheme` → Weather → Snowdrifts (цвет, мягкость и шум края, тень у подножия).
Декор пока общий с замком (`PlaceholderDecorSet`).

#### Create Placeholder Fog
Бесшовная текстура шума `Art/Fog/FogNoise.png` и материал тумана `Art/Fog/Fog.mat` (`Purge/Fog`) → тема-заглушка.
Существующий материал сохраняет настройки (дозаполняется только отсутствующая текстура).

#### Create Placeholder Lighting
Материал пятна-тени `Art/Lighting/BlobShadow.mat` → `Lighting` темы-заглушки; пресеты источников (факел, холодная лампа),
если в теме их нет. Существующее не перезаписывается. Остальное настроение света — на ассете темы.

### UI

#### Build Localization
Из `Data/Localization/Strings.tsv` делает таблицу на язык (`Texts_<код>.asset`) и каталог языков `Languages.asset`
(всё Addressable, группа Purge Shared; в памяти игры — только выбранный язык), проверяет таблицу: ключи из `TextKeys`,
которых нет в таблице, и разные `{n}` у языков — ошибки (ничего не пишется); неиспользуемые ключи, непереведённые
тексты, оружие без названия, цвет ключа без сообщения — предупреждения. Затем запускает Build UI Style (атласы шрифтов
под символы всех языков). Отчёт — в консоли.
Запускать: после правки таблицы переводов.

#### Build UI Style
Общий материал фигур `Art/UI/UIShape.mat`, шрифты и `Data/UI/UiStyle.asset` (палитра, толщины линий — существующие
значения сохраняются). Шрифты — статические SDF-атласы только с нужными символами (ASCII + все символы таблицы
переводов): Rajdhani SemiBold/Bold — латиница всех языков, их fallback Exo 2 SemiBold/Bold (`Art/Fonts/Exo2`) —
остальное (кириллица). Делает Rajdhani шрифтом TMP по умолчанию и убирает образцовый шрифт и эмодзи TMP из `Resources`.
Запускать: на чистом проекте или после смены шрифтов (после правки текстов его запускает Build Localization).

#### Build UI Icons
Рисует линейные иконки UI (`Art/UI/Icons`) → `Data/UI/UiIcons.asset`, фон меню (процедурный лабиринт) и силуэты оружия
из моделей → `WeaponVisualDefinition.Icon`, силуэты метательного (пикап-модель сверху, `Art/UI/Icons/Items`) →
`ItemVisualDefinition.Icon` — иконки слота метательного в HUD.
Запускать: после правки иконок в `UiIconsBuilder.cs`. Иконки оружия пересобирает и Build Weapons, метательного — Build Items.

#### Build Map Icons
Значки карты «от руки» (флаг старта, дверь, замок, стрелка игрока, череп, оружие, аптечка, ключ) → `Art/UI/MapIcons` и
`MapIcons.asset`. Цвета и размеры набора сохраняются; любой спрайт можно потом заменить вручную.

#### Build Runtime Scenes
**Пересоздаёт целиком** сцены `Bootstrap` и `Game` (все экраны UI, HUD, тач-контролы, камера, свет) и ставит их
в Build Settings. Ручные правки в этих сценах **теряются** — вёрстку менять только в `RuntimeScenesBuilder.cs`.
Запускать: после любых изменений UI/сцен в коде билдера.

### Сторонние ассеты

#### Collect Used Third-Party Assets
Для паков, скачанных в `Assets/_Project/Import` (не в git):
1. снимает коллайдеры, Rigidbody и LOD со всех префабов вне `Import` (у LOD остаётся `LOD0`, нижние уровни и `LODGroup` удаляются: склейка геометрии взяла бы все меши и нарисовала их друг поверх друга); префаб, который так не правится (вложенный/вариант), — ошибка в консоли, править его исходник;
2. переносит всё используемое из `Import/<Пак>/…` в `Art/ThirdParty/<Пак>/…` (GUID сохраняются); список эффектов `FxImport.asset` не считается (он ссылается на исходники в `Import`, игра берёт очищенные копии);
3. проверяет, что ссылок на `Import` не осталось;
4. ограничивает размер текстур для Android/WebGL (≤2048, ключи — 256).

Запускать: после того, как взяли из пака что-то новое, **до коммита**. Оставшееся в `Import` не используется.

#### Cap Third-Party Texture Sizes
Только шаг 4 предыдущей команды — ограничение размеров текстур паков для Android/WebGL.

### Заглушки (начальная настройка)
Делают простые ассеты-примитивы, чтобы игра работала без арта. На готовом проекте обычно не нужны.

#### Create Placeholder Theme
Тема-заглушка `Data/Themes/PlaceholderTheme` с префабами из примитивов (`Art/Placeholders`): пол, стены всех форм,
двери (простая и цветные запираемые), ключи, аптечка, оружие, зомби.
**Осторожно:** наборы `Placeholder<Вид>Set` очищаются и заполняются заново — в том числе `PlaceholderWeaponSet` и
`PlaceholderZombieSet`, которые использует и основная тема. После запуска нужно заново выполнить
Build Weapons и Build Zombie Animations (и Build Light Fixtures для набора света).

#### Rebuild Placeholder Doors
Пересобирает только префабы дверей-заглушек на месте (закрытая створка, открытая у западной стороны, замок у цветных).

#### Create Placeholder Player
Капсула-игрок с «носом» и ассеты `PlayerDefinition` / `PlayerVisual` (Addressable). Значения существующего определения
сохраняются. Настоящий игрок — Build Player Animations.

#### Create Placeholder Zombies
Типы зомби в `Data/Zombies`: Walker (зрение), Listener (слух), Hunter (зрение + слух). Существующие ассеты не трогает.

## Зависимости между командами
- **Build Combat Effects** → до Build Light Fixtures (материал пламени) и Build Footprints (пыль).
- **Build Pack Effects** → затем **Build Combat Effects** (пых у ствола на дыме пака) и **Collect Used Third-Party Assets**.
- **Create Placeholder Theme** → до Build Weapons и Build Zombie Animations (им нужны наборы темы-заглушки).
- **Build Player Animations** → затем Build Weapons (риг рук по модели игрока).
- Билдеры персонажей → затем **Extract Character Meshes**.
- Новые модели объектов → **Convert Object Materials to Purge Lit** (Light Fixtures делает это сам).
- Что-то из `Import` → в конце **Collect Used Third-Party Assets**.
- Правка `Strings.tsv` → **Build Localization** (сама запускает Build UI Style). Новая подпись в `RuntimeScenesBuilder` → ещё **Build Runtime Scenes**.
